The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). This project does not yet follow Semantic Versioning releases (see `README.md` status) — entries accumulate under `[Unreleased]` until the first tagged release.

**Older entries are archived in [`docs/changelog/`](docs/changelog/)**, one file per rotation (e.g. [`2026-09.md`](docs/changelog/2026-09.md)), so this file stays short enough to read in full. ## [Unreleased]

### Added

- **Tests for the command-line utilities and the XISF converter.** `tests/test_xisf.py` (43 tests) builds real `.xisf` files and covers every sample format, geometry, raw/zlib/byte-shuffled/gzip pixel data, multi-channel images, header-card extraction, the refusal paths (bad signature, malformed geometry, truncated data, entity-expansion headers) and the Library's ingest handler end to end. `tests/test_commands.py` (47 tests) goes module by module through `galileo.commands` — load/sync repository, create/link sessions, register-existing, calibration reset, stack, download, photometry, auto-calibration and cloud sync — checking arguments, exit codes, what lands in the catalog and on disk, and what each refuses to do, against a temporary library and log folder. Three more tests are `xfail(strict=True)` and document the gaps below that were not fixed. `galileo.commands` coverage 16 % → 58 %; the XISF converter 0 % → 90 %.

- **The Library can now download from an SFTP server (`LIB-170`, traces to `EXT-120`).** `EXT-120` had an adapter but nothing in the app used it. Library > Download offers an **SFTP** source (hostname only — it is addressed, not network-scanned) and `galileo-download -t SFTP -H <host>` does the same from the command line; both list every FITS file under the configured remote folder, download them through the normal ingest, and can delete them from the server afterwards. Options > Library > Smart Telescopes gains an *SFTP Server* group — username, password (kept in the OS keychain, not `library.ini`), optional key file, remote folder, port, and *only connect to servers already in known_hosts*. Built on a new `SftpSession` in `galileo.library.adapters.sftp`. New requirement `LIB-170` in the SRS/SDD/RTM (`TC-LIB-170`).

- **The VSTarget plugin's analysis run is documented as off-UI-thread work with a settable aperture** (`docs/plugins/vstarget/SDD.md` Section 3.2, `RTM.md` Section 4). The panel's photometry now runs on a worker thread rather than in the button's own slot, so a multi-night run no longer freezes the window (core `NFR-PERF-020`), and its "Aperture radius (px)" field reaches the photometry engine instead of being ignored in favour of the 8 px default. The plugin's RTM cross-reference list gains the two core requirements its analysis panel now consumes but does not define, `LIB-040` and `NFR-PERF-020`. Implemented in the `Galileo-Plugins` repository (`vstarget/vstarget/analysis/runner.py`, `analysis/__init__.py`, `ui.py`), where the behavioural changelog entry lives; nothing in core changed.

- **`VST-AN-100` added to the VSTarget plugin's requirement chain** (`docs/plugins/vstarget/SRS.md`, `SDD.md` Section 3.2, `RTM.md`): the plugin's analysis panel now takes its input images from Galileo's image library instead of a folder on disk. It lists every catalogued session of every target designated a variable star — the `VariableStars` row the Library > Images context menu's *Add Variable Star* action writes — so an observer picks the nights to measure rather than hunting for the folder the frames were filed into, and photometry runs against the session's calibrated frames where it has them. Implemented in the `Galileo-Plugins` repository (`vstarget/vstarget/analysis/library_sessions.py` and the panel in `vstarget/vstarget/ui.py`), which is also where that behaviour's own changelog entry lives; nothing in core changed. The plugin's RTM note claiming it has no test suite is corrected at the same time — it has had one since the plugin moved out of core, and `TC-VST-AN-100` is part of it. The `VST`/`VST-AN` requirement counts in the SRS and RTM summary tables are brought back in line (21 requirements), having been left behind when `VST-100` was added.

### Fixed

- **Colour XISF files can now be imported, and XISF import works through the Library at all.** The ingest handler called the converter with the wrong arguments and so failed for every `.xisf` file; separately, `XISFGeometry.channel_size()` returned the whole image's pixel count, which broke the per-channel reshape of any multi-channel image; the converted header double-counted the channel axis in `NAXIS`; and the creation time and creator application were never read from namespaced headers or from PixInsight's standard `XISF:` properties. Found while writing the XISF tests.
- **`galileo-load-repo --repo` and `galileo-sync-repo --repo` now do what they say.** The override was set on the processor facade but files are filed by a fresh repository manager built from `library.ini`, so everything still went to the configured repository. Found while writing the command tests.
- **Tests brought in line with the product, and unimplemented features marked as such.** Three Star Atlas tests had gone stale (`contextMenuRequested` now carries a third argument; Options has a Plugins page after the per-section pages; a plugin can append items to a core menu, which also made the Science-menu test depend on the machine's installed plugins) and now match. The four tests for requirements with no implementation yet — `LOG-060` (recent-log pane) and `NOTIF-020`/`030`/`040` (email/SMS channels, contact details from the owning Observatory) — are `xfail(strict=True)` with the reason, so a failing run means a regression and implementing one of them will flag the leftover marker. No product code changed. Found by the 2026-10-04 code review (F3/F10).
- **Importing a hostile XISF file can no longer exhaust memory, and a non-HTTP notification webhook is refused.** The XISF converter parsed the header of an imported file with the standard XML parser, which expands entity declarations ("billion laughs", external entities); it now uses `defusedxml` (a declared dependency now, previously only present by accident), and a header that declares entities is rejected with a clear error. `WebhookChannel` also refuses any configured URL that is not `http`/`https` — `urlopen` would otherwise happily read a `file://` URL — and logs why. Found by the 2026-10-04 code review (F7). New tests: `TC-LIB-010` (XISF header, normal and hostile) and `TC-EXT-070` (webhook scheme).
- **SFTP retrieval is the Library's alone, and its failures are no longer silent.** The VSTarget plugin only re-exported the Library's SFTP adapter (and declared an unused `paramiko` dependency), so it was removed from the plugin and `VST-AN-010` retired across the plugin's SRS/SDD/PSD/RTM (counts now 20 requirements); core `SRS`/`SDD` state that `EXT-120` is Library-owned. In the adapter itself (`galileo.library.adapters.sftp`), a connection or listing failure now logs at WARNING with its traceback instead of debug (an unreachable server used to look like an empty folder), the SSH client is closed even on error, one failed file no longer abandons the others, accepted unknown host keys are logged with their fingerprint, and `strict_host_keys=True` refuses them. Found by the 2026-10-04 code review (F4). The plugin's own changelog records its side.
- **The two type errors on Galileo's startup path are fixed.** The main-window mixins' shared `AppWindowState` protocol declared `_camera_backends` and `_imaging_service` as plain attributes while `AppWindow` defines them as read-only properties, so mypy rejected `AppWindow` as a valid `self` (surfacing at `window.show()` in `app.py`); they're now declared as read-only properties. `app.py` also casts `QApplication.instance()` to `QApplication` before calling `setWindowIcon`. Type-annotation changes only — no runtime behaviour differs. Found by the 2026-10-04 code review (F9).
- **A device property write could silently vanish.** `DeviceController.set_property` fired the backend's async setter with a bare `ensure_future`, so the task could be garbage-collected mid-write and any failure (a device refusing a gain/offset value, say) was lost; with no event loop it swallowed the error and left the coroutine un-awaited. The write is now kept referenced until it finishes and a failure is logged with its traceback; the no-loop case runs it to completion. Callers still don't see an exception, as before. Found by the 2026-10-04 code review (F6).
- **`TC-EXT-110` now tests the Simbad lookup that exists.** It asserted a `SimbadClient` class in `galileo.planning.sky_atlas` that the code never had — the lookup is `_search_simbad_sync` behind `SkyAtlas.search_online` — so it failed although `EXT-110` is implemented. The test now runs that function against a stubbed `astroquery` (no network) and checks the returned coordinates and V magnitude. No product code changed.
- **Blocking network and file I/O no longer runs on the asyncio event loop.** The weather-forecast fetch in `galileo.safety` (run from the safety poll loop, which stalled for up to 10 s when Open-Meteo was slow), the geocoding lookup, the Alpaca discovery/GET/PUT fallbacks used when `httpx` isn't installed, and the SMB download now run in worker threads via `asyncio.to_thread`; the SFTP adapter's directory creation moved into its existing worker thread; the ASTAP solver's file checks and the Imaging page's FITS save (a full-frame disk write) likewise no longer block the loop. Behaviour and error handling are unchanged. Found by the 2026-10-04 code review (F5).
- **Star Atlas tests no longer read the developer's real `planning.json`.** The `window` fixture built the app before any test patched the Planning options path, so a machine with "Do not slew where obstructed" saved as on made `test_slew_guard_is_scoped_per_pier` fail (the checkbox started checked, so the test's `setChecked(True)` changed nothing). The fixture now points the options at the test's temp folder. No product code changed — this was a test-isolation bug, not a slew-guard state leak.

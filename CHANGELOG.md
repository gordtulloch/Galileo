# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). This project does not yet follow Semantic Versioning releases (see `README.md` status) — entries accumulate under `[Unreleased]` until the first tagged release.

**Older entries are archived in [`docs/changelog/`](docs/changelog/)**, one file per rotation (e.g. [`2026-09.md`](docs/changelog/2026-09.md)), so this file stays short enough to read in full. Search the archives (`grep -rn <term> docs/changelog/`) rather than reading them end to end. When this file grows past roughly 40 KB, move everything under `[Unreleased]` to the top of the current month's archive file (creating `docs/changelog/YYYY-MM.md` if needed) and leave `[Unreleased]` empty again.

## [Unreleased]

### Added

- **A Windows installer (`NFR-INSTALL-010`).** `Install-Galileo.bat` at the repo root is the one file a new user needs to download — double-clicking it fetches and runs the new `install/install.ps1`, which ensures Git and Python 3.11+ are available (offering a silent per-user install of either if missing — Git via `winget` when present, otherwise the latest Git for Windows release looked up from GitHub), clones the repo (or updates an existing checkout), creates `.venv`, installs `requirements.txt`, and creates a desktop shortcut set to open minimized (`WindowStyle = 7`), so the update-check console the shortcut launches doesn't steal focus on every start — the Galileo window itself opens normally regardless. Deliberately not a frozen/Nuitka-style monolithic executable (`docs/SDD.md`'s planned MSI packaging is a separate, later effort) — updates instead work the way the author's AstroFiler installer already does and has proven out: the desktop shortcut's target, `install/launch_galileo.bat` (and its PowerShell twin `launch_galileo.ps1`), checks for and applies updates via git on every launch, falling back to a no-op with a warning rather than discarding anything if the install directory has local changes. `install/upgrade.ps1` covers the manual "update now without starting the app" case with the same git-pull-plus-dependency-refresh approach, in its own console window with a completion dialog. `install/README.md` documents how the pieces fit together. macOS/Linux installers remain future work (`TODO.md`); `run.sh`/`run.ps1` (unchanged) still cover running from a manual checkout everywhere.

### Fixed

- **`assets/images/galileo.ico` was raw PNG data (1024×1024) wearing an `.ico` extension, not an actual ICO container** — Explorer can't parse PNG as an icon resource, so the installer's desktop shortcut (`install/install.ps1`, which points `IconLocation` at this file) silently fell back to a generic icon instead of Galileo's. Regenerated the file in place from the same artwork as a real multi-resolution ICO (16/24/32/48/64/128/256 px, via Pillow) — same source image, now actually readable as an icon; dropped from 1.8 MB to ~200 KB in the process. `galileo/app.py`'s `main()` also now calls `app.setWindowIcon(QIcon(...))` against this file, which it never did before, so the running app's own window/taskbar icon matches the shortcut instead of falling back to Qt's default. A desktop shortcut created before this fix keeps showing the generic icon until it's recreated (re-run `install/install.ps1`) or the Windows icon cache is refreshed, since Explorer caches per-shortcut icons.
- **mypy's `attr-defined` findings across `galileo/ui/*` were dominated by PySide6 enum stub noise**, drowning out real bugs (CODE_REVIEW.md Finding 11). PySide6 6.11's stubs only expose enum members under their nested enum class (e.g. `Qt.AlignmentFlag.AlignCenter`) even though the flat, un-nested spelling (`Qt.AlignCenter`) still works at runtime — this accounted for 220 of the 623 project-wide mypy errors, spread across 27 UI files, several of which also had real, unrelated `attr-defined` bugs (e.g. `DeviceBackend.list_available_devices`, `sessions.py`'s `Callable[[], QScreen]` calls) sitting in the same noisy output. Rewrote every flat Qt/PySide6 enum reference project-wide to its nested spelling (`Qt.AlignCenter` → `Qt.AlignmentFlag.AlignCenter`, `QDialogButtonBox.Ok` → `QDialogButtonBox.StandardButton.Ok`, etc. — `QHeaderView`, `QFrame`, `QAbstractItemView`, `QMessageBox`, `QDialog`, `QPainter`, `QSizePolicy`, `QImage`, `QGraphicsView`, `QFileDialog`, `QFontDatabase`, `QFormLayout`, `QLineEdit`, `QPlainTextEdit` also affected), derived from PySide6's own `.pyi` stubs rather than guessed. Purely a typing fix — nested and flat spellings are the same runtime value in PySide6 — verified via `python -c "import py_compile"` over every changed file, a before/after mypy diff showing zero new error messages of any kind (only the 220 Qt-enum lines disappeared), identical `ruff check` counts before/after, and a full `pytest` run showing the same pre-existing failures as before (see below) with no new ones. Brings project-wide `mypy . --ignore-missing-imports` from 623 to 404 errors, leaving `galileo/ui/*`'s remaining mypy output actually worth reading.
- **`Observatory` had no `contact_details` attribute**, so `test_tc_obs_090_observatory_carries_operator_contact_details` (`tests/test_obs.py`) failed at `obs.contact_details is None` — the class's `__init__` never set the attribute and had no `set_contact_details` method, even though `ContactDetails` (OBS-090) was already defined in `galileo/observatory.py`. Fixed by initializing `Observatory.contact_details = None` and adding `Observatory.set_contact_details(email=, phone_number=, channels=)`, which builds and stores a `ContactDetails` instance — one per Observatory, not per Pier, matching NOTIF-040's design of reading the operator's contact info from the owning Observatory rather than per-Pier or per-notification config.
- **Several Equipment/Options/Framing form fields (QComboBox/QLineEdit) were squeezed to a few characters wide on macOS only** — worst on Camera and Focuser's Device selector, where the device name was unreadable, but present anywhere a form field was placed via `QFormLayout.addRow(...)` without an explicit stretch. Cause: `QFormLayout`'s field growth policy default is platform-dependent (`AllNonFixedFieldsGrow` on Windows/Linux, `FieldsStayAtSizeHint` on macOS), so only Mac ever pinned these fields to their tiny size hint instead of filling the row — pages using a `QHBoxLayout` with a stretch factor for the same kind of row (Mount, Filter Wheel, Rotator) were never affected. Fixed by routing every affected form through a new `_new_form_layout()` helper (`galileo/ui/app_window/_common.py`) that pins the policy to `AllNonFixedFieldsGrow` explicitly: Camera and Focuser's Device panels, the Framing Assistant dialog, the Optics page's tube panel, the New Observatory dialog, the Imaging tab's Capture Settings/View groups, the Planning page's criteria panel, and the Imaging Settings options page's BITPIX combo. Forms whose fields are read-only status `QLabel`s (e.g. the Imaging tab's Statistics group) or fixed-size spin boxes were left as plain `QFormLayout()`, since the policy doesn't affect them either way.

### Changed

- **The changelog is split so it no longer dominates the context window of anyone (or any tool) reading it.** `CHANGELOG.md` had grown to ~250 KB in one `[Unreleased]` section, so every edit to it meant loading the whole history. All existing entries moved verbatim to [`docs/changelog/2026-09.md`](docs/changelog/2026-09.md); this file now holds only new entries, with a rotation rule (above) for when it grows again. `CLAUDE.md`, `CONTRIBUTING.md`, `TODO.md` and the VSTarget PSD now point at the archive where they cite past entries.
- **`galileo/ui/app_window.py` (a single ~7,900-line file, one `AppWindow` class) is now the package `galileo/ui/app_window/`, split into 22 files along the module's own pre-existing section comments (one file per page/concern — Camera page, Mount page, Imaging page, Framing Assistant, etc.), with `AppWindow` reassembled from mixins in `__init__.py`.** The file's size was itself a maintainability problem, independent of any single bug: window chrome, every device-category dialog, and Pier/Observatory CRUD were all in one module, and it accounted for over a third of the project's mypy findings by sheer bulk, burying the real bugs in there under noise. No behavior changed — this is a pure move, verified via `python -c "import galileo.ui.app_window"`, `ruff check galileo/ui/app_window/` (same pre-existing findings as before, none new), and the full set of `tests/test_*.py` files that exercise `AppWindow` (`test_driver_info`, `test_eqp`, `test_focus_page`, `test_guider_page`, `test_img`, `test_lib`, `test_optics_page`, `test_rotator_page`, `test_sched`, `test_sky`, `test_solve_page`, `test_star_atlas`) still passing. Splitting one class across files created a real mypy wrinkle — each mixin, checked alone, can't see that it'll share `self` with every other mixin once combined — fixed via a generated `Protocol` (`_state.py`) applied as an explicit `self: AppWindowState` type per mixin method (mypy's own documented pattern for mixin classes, no runtime effect). Net result: project-wide `mypy . --ignore-missing-imports` went from 623 errors to 620 — a net improvement, not the regression a naive per-file split would have been. Found by CODE_REVIEW.md (Finding 9); verified via mypy/ruff/pytest as above.

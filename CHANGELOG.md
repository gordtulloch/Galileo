# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions are pre-releases (`0.9.NNalpha`) tagged `v0.9.NNalpha`.

**Each release has its own archive file in [`docs/changelog/`](docs/changelog/)**, named after the version (e.g. [`0.9.03alpha.md`](docs/changelog/0.9.03alpha.md)); the older monthly files (`2026-09.md`, `2026-10.md`) hold entries from before versioned headings began. This file holds only `[Unreleased]` and the index below, so it stays short. Search the archives (`grep -rn <term> docs/changelog/`) rather than reading them end to end.

**At each release:** run `python scripts/archive_changelog.py <version>` (e.g. `0.9.04alpha`). It moves everything under `[Unreleased]` into `docs/changelog/<version>.md`, leaves `[Unreleased]` empty and adds a line to the index. Then bump the version in `galileo/__init__.py` and `pyproject.toml`, write `docs/release-notes/v<version>.md`, and tag.

## [Unreleased]

### Added

- **Control Surface, control lease, held motion and emergency operations (`galileo.control_surface`; `CSURF-010`–`080`, `250`, `300`, `400`–`420`, `LEASE-010`–`050`, `080`).** The contract the remote-client plugins are written against, usable with no plugin installed. Services declare operations (name, argument schema with ranges and units, permission class, lease requirement, availability) on a `Registry`; a request is validated first and always returns a typed outcome (`ok`, `refused`, `invalid` with the field, `unavailable`, `busy`, `unreachable`), never an exception, and a safety refusal passes through word for word. An entry of class *config* is refused at registration. Long-running operations publish started/progress/exactly-one-finished on the bus with a correlation id. `ObservableState` gives subscribers a snapshot then sequence-numbered changes per Pier. `LeaseBroker` keeps one holder per Pier in memory (granted when free, taken over only with confirmation, released on disconnect or after 10 idle minutes, published on the bus). `HoldManager` stops held motion when the keep-alive lapses, the holder disconnects, the lease changes hands, the pairing is revoked, the plugin is disabled or a safety stop occurs (defaults 250 ms / 600 ms, validated). `register_emergency` declares stop-everything, park and close-dome with no lease and no second step. No service registers its operations yet (the per-area inventory `CSURF-100`–`240` is still to do), so nothing in the app changes.
- **The Connect Link request pipeline (`LINK-230`).** `Gateway` is the one path from a route to a domain service: identify, authorise (read needs `view` or `control`, everything else `control`; guests only the allowlist), validate against the catalogue, lease, confirm (two-step single-use token for confirm-class operations), idempotency (a retried key returns the original result, even for a confirmed operation), dispatch under a load governor, and audit in a `finally` (a guest's identifier is never stored). The governor turns away transfers first, then previews, then interactive work, keeps slots for a running session, and always admits emergencies; clients are rate-limited individually; previews and transfers yield to a running session. It refuses to start if the catalogue holds a *config* entry.
- **The Master relay (`LINK-220`, `LEASE-070`).** `MasterRelay` presents the Master's Piers and those of paired spokes as one list, relays operations, state, events and previews, and forwards the originating client's identity so the spoke audits the client as actor and the Master's peer as carrier (the Master audits too). The grant is whatever the spoke gave (`control` or `view`); a spoke that gave nothing is reported but hidden from the list. The lease lives on the spoke, so its own desktop and the Master's clients contend through one lease. An unreachable spoke is reported with the time last heard, operations to it are refused with that reason, and it re-attaches with the same token. A spoke serves `/connect/v1/relay/*` when given `SpokeEndpoints`.
- **Replication support for NodeConnect (`galileo.replication`; `REPL-010`–`080`).** Migration 034 puts `app_settings` under change tracking with database triggers, so every write (including the settings store's bulk upserts) sets `dirty`, stamps `modified` and keeps the `base_rev` the edit started from; deletes leave tombstones until the sync owner releases them; applying replicated rows suspends tracking inside one transaction. Migration 035 adds core-owned sync tables (outbox, inbox, snapshots, run reports, transfer queue, per-peer state) behind `SyncStore`, so a sync plugin ships no migration. The Master issues revisions serially per table. A replicable-table registry (natural key, dependency order, node-local and secret fields, row filter) is in place with `app_settings` registered, and a test fails if a new table is neither registered, listed as not configuration, nor on the visible pending list. The session executor now sets a busy signal (`is_busy`, `on_idle`) and a `SettingsChanged` event exists for after a bulk apply. The twelve other configuration tables (Piers, devices, optical tubes and so on) are listed as pending registration and do not replicate yet.
- **A preview service for remote clients and guests (`galileo.preview`; `PREV-010`–`060`).** Renders a stretched, binned, size-limited JPEG of the current exposure, a Library frame or a stack, with an optional histogram and star statistics (count, HFR, FWHM from SEP in the process pool), and a 256-pixel tile pyramid whose stretch comes from the whole frame so tiles join without seams. Results are cached under a byte budget (least recently used out) and a new exposure behind the same reference is never served stale. While a session runs, previews shrink to 512 px / quality 70 rather than waiting. Guest mode encodes from pixels only, is held to 1024 px / quality 75, is never cached, offers no tiles or statistics, and `assert_clean` refuses any JPEG carrying EXIF, GPS, comments or trailing data. Nothing calls it yet.
- **Sky streaming for remote clients (`galileo.skystream`; `SKYSTR-010`–`080`).** Serves the bundled star and deep-sky catalogs by region, magnitude limit and level of detail, brightest first in pages with a resumable cursor, in a compact versioned binary form (delta-coded, quantised to 3.6″; about 6 bytes an object), plus ephemeris for an instant or a range, the site, horizon and live pointing, and a static sky image (stars, constellation lines, mount, field of view, horizon) for clients that cannot draw the sky. Every response carries the Master's as-of time. Capability limits (VR-class or not, concurrent clients, page size, rate) come from timing a page on this computer, not from a platform name; a slow machine says why VR is not offered. Streaming drops detail when a session runs and is capped and rate-limited per client. Nothing calls it yet.
- **Session history can move between nodes (`HIST-050`).** `SessionHistory.export_records` / `import_records` use `(origin_node_id, local_key)`, so a Master can hold every node's history with no collision (an imported session is filed under its origin and never touches a local one), a repeat import changes nothing and a corrected record updates in place. A node now has an identity (`galileo.node_identity`, a random id kept in the settings database and never replicated).
- **Manual focus is a function of the focus module (`ManualFocus`; `FOC-100`–`130`).** Relative and absolute moves, halt, position and temperature, with the focuser's own travel, the user's limits and backlash applied in one place, and held in/out moves that carry the Control Surface deadman (stopping on a lapsed keep-alive, lease change or safety stop). The desktop Focus screen now moves the focuser through it, so the screen and remote clients share one implementation; the screen looks and behaves as before.
- **A frame can be *On Master* (`galileo.library.core.location`; `LIB-200`–`220`, migration 036).** Frames carry a location (`local` / `on_master`) and the holding node. A frame is marked On Master only when the holder's whole-file hash equals the catalog's; only then may its local copy be deleted, and the row, hash, thumbnail and quality metrics stay. Retrieving fetches the file by hash over Connect Link (`data.pull`), verifies it, and restores it; a corrupt or interrupted transfer is discarded. Operations that need pixels call `ensure_local`. In the Library > Images screen such a frame shows a computer icon, **Retrieve** is in the right-click menu, and double-click retrieves then opens it. The integrity check no longer reports an On Master frame as missing. Moving frames to a Master is NodeConnect's job and is not built yet.
- **The Connect Link service (`ConnectLinkService`; `LINK-260`, `LINK-270`).** Composes the listener, pairing, audit, transfer and discovery. Its settings (enabled, port, pairing expiry, audit retention, advertising, bind address) are validated and stored in the shared database; keys stay in the secret store; the all-interfaces address is refused. The listener runs only while Connect Link is enabled *and* a plugin uses it, stops with the last plugin, and a departing plugin loses its routes and streams. Disabling closes the listener, ends every stream, withdraws the advertisement and leaves no timer or task running, while the pairings stay, so enabling again needs no re-pairing. Changing the port, bind address or advertising restarts the listener. Nothing starts it yet (the Options page, `LINK-250`, is not built).
- **The remaining configuration tables are replicable (`REPL-010`–`040`, migration 037).** Observatories, Piers, optical tubes, device configurations, autofocus and solver settings, filter offsets, horizon points, safety rules, safety devices and session templates now carry change tracking and tombstones like `app_settings`. Because their ids differ on every node, a row's parents are named on the wire (`observatory`, or `pier` = `[observatory, pier]`) and tombstones are keyed by those names; `from_wire` turns names back into this node's ids and raises if a parent has not arrived. The solver's web key is withheld from the default wire form, and a focuser's retained position and program paths stay on their machine. Only `scheduler_jobs` is still pending (the scheduler is being reworked). The sync engine itself (NodeConnect) is not built.
- **Device host fields refuse a loopback address (`PROF-130`, `GUIDE-100`).** In every Equipment page's server field and the Guiding screen's PHD2 host, finishing an edit with `localhost`, `127.x.x.x`, `::1` or `0.0.0.0` clears the field with a message asking for the computer's real name or LAN address, and a profile that was saved with one is marked in red and explained when it loads (the value is not changed). This is a behaviour change for anyone who relied on typing `localhost`: use the computer's name or LAN address. Inline help for *Server* and *PHD2 host* says so.
- **Options > Outreach (`LINK-190`) and the live image feed (`LINK-160`).** Open an outreach event for a set time, extend it, end it, eject all guests, make a new secret, and see the Wi-Fi and per-surface QR codes; save the Wi-Fi name, passphrase (kept in the system keychain), allowed networks, default duration, guest limit, image size and quality, the Piers to offer (shown by Observatory and name) and the surfaces to enable. While an event is open, each frame the imaging service finishes for an offered Pier is rendered in guest mode and pushed to the guests watching it; the feed subscribes only while an event is open. An event now ends when Connect Link is turned off. A failed save keeps what you typed. Inline help is `options.connect_link_outreach.md`. No surface (phone app, browser) exists yet, so visitors cannot actually join; the QR codes for them appear once a plugin provides one.
- **The Control Surface catalogue for devices, focus and safety (`CSURF-110`, `150`, `220`, `300`).** `register_device_operations` declares mount (status, slew, sync, track, abort, park as a confirm-class operation, unpark), camera (status, long-running expose, abort, cooling), filter wheel, rotator, dome, flat panel, weather, read-only safety status, focus (status, move, halt and held moves through `ManualFocus`) and the three emergency operations, each calling the same controller method the desktop calls. A device-layer refusal (parked mount, obstructed slew, mount limit, unsafe) comes back verbatim as `refused`, a lost connection as `unreachable`, and each operation says why it is unavailable on a Pier without that device. Nothing is registered by the application yet: a `DeviceAccess` that finds the connected devices of each Pier (they currently live in the main window's per-selection state) still has to be written. Imaging, sky, plate solving, guiding, flip, sessions, scheduler, calibration, Library and notification operations (`CSURF-120`–`240` otherwise) are not declared.
- **Options > Connect Link (`LINK-250`).** A new Options page shows whether Connect Link is listening and where, turns it on or off, sets the port, the pairing request lifetime, the audit-log retention and whether to advertise, and shows the certificate fingerprint. Pairing requests appear with their confirmation code and are approved (choosing the permissions to give; `config.*` is unticked by default) or rejected; paired devices are listed with their plugin, permissions and last contact and can be revoked (taking effect at once, closing any open connection) or deleted. The listener runs on its own thread and loop, created only when it is first needed, so a user who never turns Connect Link on has no thread, socket or certificate; it is shut down when Galileo exits. Pairing now takes a lock, because the page approves requests while the listener polls them. Built-in help is `options.connect_link.md`; the wiki's Options article has a Connect Link section. No plugin uses Connect Link yet, so turning it on today only shows "no installed plugin uses it".
- **The outreach event facility (`galileo.connect_link.outreach`; `LINK-100`–`210`).** An event is off by default and opens for a set time on the Master, only if Connect Link is running, a private-range subnet is set, Piers are offered and every enabled surface reports ready (a check that crashes counts as not ready). A random 160-bit secret lets visitors on the outreach subnet enrol anonymously; every refusal looks like a closed port, except that a holder of the secret is told when the event is full. The source address is checked against the subnet on enrolment and on every request, and a guest seen from outside is disconnected. A guest can do exactly three things (list Piers, receive the live image, switch Pier); everything else is refused and counted before reaching any plugin. Guest images come from the preview service's metadata-free guest mode. Guests are capped and rate-limited. One aggregate audit record per event (visitors, refusals by kind, guests per Pier) holds no tokens, addresses or secrets. The owner can extend, re-issue the secret, eject everyone and get the Wi-Fi and per-surface QR payloads (`segno` is a new dependency for the QR images). The secret and tokens exist only in memory, so a restart voids every guest. No screen or surface exists yet.
- **One loopback check (`galileo.net.is_loopback`, `PROF-130`, `GUIDE-100`).** Recognises `localhost`, `127.0.0.0/8`, `::1` and `0.0.0.0` in every form an address is typed. It is not yet applied to the device and PHD2 host fields, whose default is `localhost`; that changes the editors and is still to do.

- **Connect Link nodes can find each other on the LAN (`LINK-040`).** While the listener runs it advertises `_galileo-link._tcp` by mDNS with only its display name, node id, port, protocol version and role hint (no secret, and finding a node does not let anyone pair with it), and the advertisement is withdrawn when the listener stops. `Discovery.browse()` lists other nodes (never itself, skipping malformed ones) and `manual_address()` validates a host and port typed in by hand. If mDNS is unavailable the listener still starts and only logs a warning. The tests use a fake mDNS backend, so discovery across real networks (Windows, macOS, Pi) still needs checking by hand. No screen exists yet to show the results (`LINK-250`), so no inline-help or wiki change.
- **Connect Link can now move large files reliably (`LINK-070`).** A paired peer holding `data.push` uploads, and one holding `data.pull` downloads, in checksummed 1 MiB chunks at `/connect/v1/transfer/<sha256>`. An interrupted transfer resumes from the last verified chunk (a stale offset gets a 409 saying where to continue), each chunk and the whole object are verified before it is reported complete, and the receiver recognises an object it already holds by hash so a repeat upload sends nothing. Transfers are the lowest-priority traffic: they are refused with `Retry-After` while a session is running or when two are already in progress. `TransferClient` gives plugins (NodeConnect first) a ready-made resumable upload/download. No screen or control changed, so no inline-help or wiki change; the audit log currently records one row per chunk, which the gateway work (`LINK-230`) should coalesce.

### Changed

- **Internal: the Focus screen's manual move, the integrity check and the rate limiter.** The Focus screen's *Move* now goes through `ManualFocus` instead of building an autofocus service (no visible change, tests unchanged). `verify_integrity` skips frames that are On Master, since their file is deliberately elsewhere. The per-client token-bucket `RateLimiter` moved from the Connect Link gateway to `galileo.core.ratelimit` so sky streaming can share it. The session executor now sets a process-wide busy signal while it runs (`galileo.replication.busy`); sessions behave as before.
- **The Connect plugins checklist (`docs/CONNECT_PLUGINS_CHECKLIST.md`) now matches the code.** It still said no Connect Link code existed; `galileo/connect_link/` already implements L1, L2, L3, L5, L6, L8 and delegation with 25 tests. The checklist now lists what is built and what remains (`100–`270` and all the Control Surface, lease, preview, sky-streaming and replication prerequisites). Docs only; no behaviour change.

- **The changelog is now versioned, with one archive file per release.** Until now everything accumulated under `[Unreleased]` in one 108 KB file. `CHANGELOG.md` now holds `[Unreleased]` and a Releases index; v0.9.03alpha's entries are in `docs/changelog/0.9.03alpha.md` and everything that shipped in 0.9.02alpha or before is in `docs/changelog/0.9.02alpha-and-earlier.md` (the entries present at the `v0.9.02alpha` tag; earlier releases could not be separated because the file had no version headings). New `scripts/archive_changelog.py <version>` does the archiving at each release, and the changelog section of `CLAUDE.md` describes the process. Replaces the rotate-at-40-KB-into-monthly-files rule. Documentation and tooling only.

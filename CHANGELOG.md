# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). This project does not yet follow Semantic Versioning releases (see `README.md` status) — entries accumulate under `[Unreleased]` until the first tagged release.

**Older entries are archived in [`docs/changelog/`](docs/changelog/)**, one file per rotation (e.g. [`2026-09.md`](docs/changelog/2026-09.md)), so this file stays short enough to read in full. Search the archives (`grep -rn <term> docs/changelog/`) rather than reading them end to end. When this file grows past roughly 40 KB, move everything under `[Unreleased]` to the top of the current month's archive file (creating `docs/changelog/YYYY-MM.md` if needed) and leave `[Unreleased]` empty again.

## [Unreleased]

### Fixed

- **A guide camera associated with its own optical tube now gets that tube's focal length and aperture.** Connecting a device or changing the top-bar Optics selector pushed the *selected* tube's optics to every INDI device, including the guide camera behind a second tube. Each device associated with a tube on Equipment > Optics (by its saved device name) now receives its owner's optics, both when Galileo drives it and when it is only on the same INDI server (e.g. PHD2-owned); unassociated devices still follow the selected tube. `push_optics_to_server` gained a `per_device` override. No requirement or help change.

- **Options > Guiding now has a Save button.** The page silently saved on every edit, so there was no visible way to commit changes, unlike the other settings pages. Edits are now held until Save is clicked (status-bar confirmation). Help entry and `TC-GUIDE-030` test updated.

- **Repeated INDI driver warnings no longer flood the log.** A driver that warns on every exposure (e.g. the Guide Simulator's "No stars found in field -- check gsc catalog coverage") produced one identical line every ~2 s. Identical warning/error lines from a server are now logged once, held back for 5 minutes, then logged again with a "repeated N more times" count. The underlying warning is the driver's: the simulator needs the `gsc` catalog installed on the INDI server. No requirement or help change.

- **INDI Guide Simulator (and any PHD2-owned guide camera) no longer warns "Telescope focal length/aperture is missing".** That camera is driven by PHD2, so Galileo never connected to it and the optics push never reached it. When optics are pushed, Galileo now also writes them to every device on the same INDI server that defines `TELESCOPE_INFO`/`SCOPE_INFO`, and fills the `GUIDER_FOCAL_LENGTH`/`GUIDER_APERTURE` pair as well as the telescope pair (the same tube's optics, as Galileo has no separate guide scope). No requirement or help change.

- **Star Atlas mount-position poll no longer drops its worker thread while it is still running.** The poll released its `QThread` from the position signal, which fires before `run()` has returned, and never deleted it. It now releases and `deleteLater()`s the thread on `finished`. Hardening for native crashes (access violation / heap corruption in `faulthandler.log`) that surfaced when the poll created its next thread; not yet confirmed as the root cause. No requirement or help change.

- **INDI telescope focal length and aperture are now sent when the mount connects and when a Pier is selected.** The Mount page connects through its own path, which never pushed the active optical tube to the driver, so `TELESCOPE_INFO` stayed empty (drivers warned "Telescope focal length is missing"). It now pushes on connect, and switching Pier re-pushes the new Pier's active tube to every connected device. No requirement or help-content change (no new controls).

- **Test suite no longer touches the network for IERS data.** The 10 s download timeout (below) still let a slow CI route cost 10 s on the first visibility calculation, and astropy's own auto-download fallback could stall after it. A session-scoped autouse fixture in `tests/conftest.py` now disables astropy's IERS auto-download and marks Galileo's downloader as failed, so tests use astropy's bundled tables and run identically offline. Test-only change; no application behaviour changed.

- **Plugin panels on Equipment pages now use the plugin's own help file.** A panel such as Kasa or SwitchBot on Switches was documented under the host page (`equipment.switch`), so the help audit flagged its buttons as undocumented and the plugin's `plugin.<Name>.md` help file was reported as an orphan (`test_tc_help_060`/`test_tc_help_010` failed whenever such a plugin was installed). The panel is now tagged `plugin.<name>` when that help file exists, so its controls resolve against it. No "?" button is added, since the panel has no page title.
- **CI test run timed out in `test_sky.py` when the IERS server didn't answer.** `galileo.planning.visibility._configure_iers_cache` downloaded the Earth-orientation file with `urlretrieve`, which has no timeout, so an unresponsive `datacenter.iers.org` stalled the TLS handshake until pytest's 120 s limit killed the whole job (the failing "Code quality and tests" runs). The download now has a 10 s timeout, and a failed setup is remembered for the rest of the process instead of being retried (and re-waited on) by every altitude calculation. Offline behaviour is unchanged: astropy falls back to its own data.

### Changed

- **Galileo now opens on the Dashboard** instead of the Star Atlas, so the per-Pier timelines are the first thing you see at start-up. Only the initial screen changed; the sidebar order and every other screen are as before.
- **A plugin can put its settings under Options (`PLUG-170`).** Setting `options_label` and implementing `build_options_page()` adds an item after Plugins in the Options menu; a page that fails to build becomes a placeholder. AllSkyCam uses it instead of a Settings tab on its own page.
- **Documented the Kasa "Third-Party Compatibility" prerequisite** in the wiki's Equipment article, the Kasa plugin SDD and the Galileo-Plugins README: newer Kasa firmware ships with local control off, so a strip that works in the Kasa app is invisible to Galileo until that setting is turned on.
- **Equipment pages that host plugin panels (e.g. Switches) now scroll as a whole, with the plugin's panel at the top.** Previously the plugin panel shared the page with the Driver/Server table and results list and got only a squeezed slice of the height, so a power strip's outlets needed their own inner scrollbar. The panel now sits directly under the page title at its natural height, and one scrollbar scrolls the whole page so every outlet of every device is reachable. Pages without plugin panels are unchanged. Inline help and wiki need no change (no controls added or renamed).

### Added

- **The Dashboard is now a per-Pier activity timeline (`OBS-150`), back in the sidebar.** Each Pier of the selected Observatory gets a very compact timeline: lanes for the session, mount, meridian flip, guiding, plate solving, focusing and capture (cut into one box per frame), the RA/Dec guide error as a trace and as a 1″/2″ scatter plot, and a clock-time axis, so one glance shows what every Pier is doing and has been doing. `galileo.dashboard_timeline` records it (plain Python: `PierTimeline`, `PierActivity`, `activity_from_progress`); the page samples each Pier's in-memory state once a second whether or not it is on screen (the session controller's new `progress_snapshot()`, the mount adapter, the Pier's PHD2 service, and focus/solve bus events for runs started from their own screens), so the timelines are already filled in when you open it. Twelve hours are kept, in memory only — the record is not persisted and starts over when Galileo restarts. Hover a bar for its start time and length; double-click a timeline to make that Pier the working Pier. The table and the Open Pier button are gone, since the Dashboard no longer needs a Pier picker, and the red night-vision theme gets red-only colours. Not shown yet: HFR/star-count traces (the history store is not per Pier).
- **Plugins can publish a view on the Dashboard (`PLUG-180`).** A plugin that sets `dashboard_label` and implements `build_dashboard_widget()` gets a **Publish on Dashboard** box added by Galileo under its page in Options (stored in the plugin's own settings). Ticked, the view appears in a strip above the Pier timelines sized to the height the timelines leave free, so every Pier stays visible (the strip keeps a 140 px minimum and the page scrolls instead when there are many Piers). The view is built once, only for enabled plugins, and one that fails to build is skipped. The **AllSkyCam** plugin uses it (`ASC-100`; see its own changelog).
- **Docs:** SRS `OBS-150`/`PLUG-180`, RTM rows with `TC-OBS-150`/`TC-PLUG-180`, SDD 4.4 and 4.20, the AllSkyCam plugin SRS/SDD/RTM (`ASC-100`), the Dashboard inline help (rewritten) and the wiki's Planning, AllSkyCam and Plugin Developers' Guide articles.

- **SwitchBot Bot plugin requirements and design** (`docs/plugins/switchbot_bot/`, PSD/SRS/SDD/RTM, `SBOT-010` … `SBOT-050`) for a new first-party plugin, built in the Galileo-Plugins repository, that presses or switches SwitchBot Bot devices over Bluetooth LE as Switch devices — mainly to power a Seestar on and off. The plugin uses `bleak` with its own small Bot protocol layer instead of the suggested `switchbotpy`, which only works on Linux (it drives BlueZ `gatttool` via `pygatt`/`pexpect`) and Python ≤ 3.8; the reasoning is ADR-SBOT-001. Core `SRS.md`, `SDD.md`, `RTM.md` and `PSD.md` now point at it next to Kasa Switch and Generic Relay. No core code changed.
- **Plugins can now have a top-level sidebar section, a dockable pane, their own settings and the Observatory location (`PLUG-130` … `PLUG-160`).** Until now a plugin panel could only land under Science or on an Equipment device page. `panel_level = "top"` gives a plugin its own icon in the left sidebar (it may paint its own via `panel_icon_painter()`, otherwise the generic plugin icon is used). `dock_label` + `build_dock_widget()` offers a `QDockWidget` the user can move or float, opened and closed by the plugin through `ctx.set_dock_visible()`; the plugin is told when the user opens or closes it, but not merely because the main window closed (Qt reports both as "not visible", which would otherwise have been saved as "pane closed" on every exit). `ctx.settings()` stores a plugin's options in the shared database under `plugin.<name>` so plugins follow the same no-config-files rule as core, and `ctx.site_location()` hands a plugin the selected Observatory's `ObservingLocation`. Documented in `docs/SRS.md` (new `PLUG-130`–`PLUG-160`, `PLUG-070` reworded), `docs/SDD.md` §4.20, `docs/RTM.md`, and the wiki's Plugin Developers Guide; covered by `TC-PLUG-130` … `TC-PLUG-160` in `tests/test_plug.py`, which build a real offscreen `AppWindow`.
- **AllSkyCam plugin requirements and design** (`docs/plugins/allskycam/`, PSD/SRS/SDD/RTM, `ASC-010` … `ASC-090`) for a new first-party plugin, built in the Galileo-Plugins repository, that shows the latest image and an animation of the last *n* images from an indi-allsky all-sky camera in its own sidebar section and an optional docked pane. indi-allsky needs no changes: it has no REST API, but its existing `/latestimage` route redirects to the newest processed image. New wiki article "16. AllSkyCam".

### Changed

- **A plugin now declares where its panel goes, and core no longer assumes it (`PLUG-070`).** `panel_level` is `"science"` (the Science menu; `"primary"` / `"secondary"` still work as older spellings), `"equipment:<category>"` (a panel on that Equipment page) or `"top"` (see above). `UiRegistry` gains `get_science_panels()`, `get_top_level_panels()` and `get_dock_plugins()`. The Generic Relay plugin now declares `equipment:switch` like Kasa Switch (it was landing under Science), and VSTarget declares `science` explicitly. The Kasa/Generic Relay/VSTarget design documents are updated to match.

### Fixed

- **Enabling or disabling a plugin in Options > Plugins never reached the plugin.** The page passes the manifest name (`vstarget`) but loaded plugins are keyed by class name (`VSTPlugin`), so `PluginManager.enable/disable` flipped a flag nobody read and a disabled plugin kept running. Both now resolve a manifest name to the loaded classes, and a plugin hears about it through the new `on_enabled_changed(enabled)` hook so it can stop and resume background work (`PLUG-060`, covered by `TC-PLUG-060`).

### Changed

- **README now describes Galileo as an alpha pre-release.** The status badge and Status section moved from "pre-alpha" to the 0.9.0alpha pre-release (linking the GitHub release), so the README matches how the installers are published. Documentation only.

### Fixed

- **Cleared the four ruff errors failing the CI static-analysis job.** `polaralign` now writes `self.latitude or 1.0` (FURB110), two unused unpacked variables in `tests/test_plt.py` are underscore-prefixed (RUF059), and `tests/test_solve_page.py` builds its list with unpacking instead of concatenation (RUF005). No behaviour change.

- **Safety checks on the UI thread always failed to read the weather station / safety monitor.** The scheduler's and dome's "is it safe?" check polls the device with `asyncio.run`, which raises when called on the UI thread (Qt's event loop is already running), so the device was reported as unreadable — i.e. unsafe — and the coroutine was left un-awaited (the `RuntimeWarning: coroutine 'WeatherController.poll' was never awaited` seen when the app crashed). The poll now runs on a helper thread when a loop is already running (`_run_blocking`). Tests added.

### Changed

- **PHD2 now connects at start-up with the Pier's other devices.** The Guider page registered an auto-connect but, unlike every Equipment page, never ran it when built, so PHD2 only connected on a Pier switch or the top bar's Connect button. It now connects to the Pier's saved PHD2 host/port at launch, honouring "Connect on Startup". No control changed; no help/wiki update.

### Fixed

- **Pressing Run on a session crashed the app with nothing in the log.** The trace (in `faulthandler.log`, since a native crash never reaches the normal log) showed an access violation inside the run thread's `QThread` constructor. The run thread is now created without a Qt parent — the active run already owns it and waits for it to finish — as a mitigation; that did not cure it (the next trace was heap corruption `0xc0000374` on the Run button's own overlap-warning dialog). **Actual cause:** the *"is running now, but overlaps"* dialog was parented to the session card; the run's progress signals rebuild the cards (a finished session is reaped) and deleted the card while the modal dialog was open, a native crash. The dialog is now parented to the main window. Regression test added. No control changed; no help/wiki update.

### Added

- **A session now belongs to one camera.** Each session card has a **Camera** chooser (a new session starts on the camera selected in the top bar); the choice is saved with the session and locked while it is scheduled or running. A run builds its context from the session's camera — exposures, plate solves, autofocus, flats, cooling and the FITS header details — instead of whichever camera the top-bar selector happened to be on, and the top bar shows **Session camera: …** on every screen while the session runs. Requirement `SES-115` / `TC-SES-115` added; inline help, wiki, SRS and RTM updated. `build_session_context` and `_imaging_frame_context` gained an optional `camera_slot`.

### Fixed

- **Dragging a session block left to take it out of a loop now works.** Qt's default drag handling refused a drop while the pointer was still over the dragged block's own row — where a sideways indent/unindent drag ends — so the unindent never ran. The Sessions block list now accepts those drags explicitly. Regression test added (`TC-SES-140`); no control changed, so help/wiki need no update beyond the earlier wording.

### Changed

- **Session-loop scope is now spelled out in the docs.** The Sessions inline help and the Planning wiki article state that only blocks indented under a *FOR Filter* / *FOR Object* tile are inside the loop — drag right to put a block in its scope, left to take it out, and an unindented block runs once after the loop. Documentation only; no behaviour or control changed.

- **Polar alignment no longer needs the scope pointed at the pole first.** The run now starts by slewing the mount to the zenith from wherever it is, then takes a frame and solves it. If the solution is more than 1° from the zenith (a mount that has never been synced has no idea where it points) the mount is synced to the solution and slewed to the zenith again, up to three rounds; a frame that won't solve (hinted, then blind) ends the run with a message. Only then does it move to about Dec 70° and measure, choosing a spot off the meridian so the swing never needs a flip — which also retires the "would cross the meridian" refusal for the start position. Tests updated and added (start from any position, unsynced mount); inline help, wiki, SRS `PLT-080` and SDD updated; no control changed.

### Fixed

- **Star Map: turning on Satellites no longer makes Comets and Asteroids disappear.** Positions for all three overlays were computed in one `try`, so if the satellite calculation failed (e.g. the `sgp4` package missing from the environment) the error cleared every overlay. Each kind is now computed on its own, so a failure only affects that kind (and is logged). Satellites still need `sgp4` installed (`pip install -e .`). Test added; no control changed, so no help/wiki change.

### Changed

- **Star Map: Constellation boundaries and Daylight sky are now off by default.** A fresh install gets a dark, less cluttered sky; both are still one checkbox away. Anyone who has already toggled them keeps their saved choice. Inline help notes the new defaults; no wiki change (the articles don't state defaults).

### Fixed

- **Mount jog (Equipment > Mount N/S/E/W) now moves an Alpaca mount at the Medium and Coarse speeds.** The presets are 10°/s and 50°/s, but an Alpaca mount rejects a `MoveAxis` rate outside its `AxisRates`, so the press was refused and the mount didn't move; the error only went to the log. The Alpaca adapter now reads the mount's `AxisRates` once per axis and sends the fastest rate it allows when the requested one is higher, and the Mount page shows "The mount would not move: …" in the status bar if a jog still fails. Test added; no control changed, so no help/wiki change.
- **Switching Piers no longer leaves the previous Pier's results on the Solve and Imaging screens.** Solve's results table, solution panel, error plot and preview are one view shared by every Pier, so after a switch they still showed the old Pier's solves; they are now cleared (a solve still running keeps its row so its result lands somewhere; reloading for the same Pier, as Options > Solve does, keeps everything). Imaging already keeps a service per Pier, but a Pier with no frame yet left the old Pier's preview on screen; it now shows an empty preview. Focus was already repainted per Pier and needed no change. Test added; no control changed, so no help/wiki change.

### Changed

- **Plate-solve slews now log where the mount says it ended up.** Slew to Target was giving up a little outside the accuracy setting (e.g. 37.9″ against 30″) and the log couldn't show whether the mount was stopping short or the solve was off. After every slew the log now reads "Mount reports dRA … dDec … from the requested position at the end of the slew (it was … before)". Diagnostic only; if it shows the mount stopping short, the sync-then-slew loop will be reworked. No control changed, so no help/wiki change.

### Fixed

- **Maximum mount jog/nudge speed is now 10°/s instead of 50°/s.** Fine, Medium and Coarse are 1, 5 and 10°/s respectively on both Imaging and Equipment > Mount, reducing unexpectedly fast movements while keeping three distinct speeds.
- **Opening OnStep LX200 driver parameters in Equipment > Aux no longer crashes when a numeric INDI field reports `NaN`.** The Aux controls now use a finite editable fallback for invalid values and ignore subsequent non-finite refreshes, so the driver panel remains usable. No controls changed; regression test added.
- **OnStep numeric fields with very small increments no longer overflow the Aux slider.** The slider now uses a bounded normalized range while its spin box retains the driver's numeric limits and increment, allowing wide-range properties to load safely.
- **Polar alignment no longer takes a frame before the mount has reached its position.** A run started at the pole could capture and try to solve at the pole before the move away from it had begun, so the solve failed. The mount's "slewing" flag can still read false just after a slew command, and the workflow took that as having arrived. It now polls the mount's reported position after every slew (the move off the pole and each RA turn) and only settles and captures once it is within 1° of where it was sent; if it never gets there within `arrival_timeout_s` (120 s) the run stops and says so instead of solving the wrong place. Tests added; no control changed, so no inline-help or wiki change.
- **Linux AppImage still aborted after the GLib fix (`Fatal Python error: none_dealloc` in the Star Atlas grid).** The release build had resolved PySide6 6.12.0, newer than the 6.11.2 the app is developed on; the abort is a refcount error inside PySide6/shiboken. PySide6 is now capped at `<6.12` in `pyproject.toml` so the installers bundle 6.11.x. Raise the cap once a fixed PySide6 is verified. No help/wiki/design-doc impact.

- **Linux AppImage aborted on newer Ubuntu** (`Fatal Python error: none_dealloc` while painting the Star Atlas grid, preceded by `undefined symbol: g_task_set_static_name` from the host's gio/gvfs/dconf modules). The AppImage bundled the 22.04 build machine's GLib, which clashed with the host's newer GLib modules. `build_appimage.sh` now strips the bundled `libglib/libgio/libgobject/libgmodule/libgthread` so the host's are used. The Star Atlas polyline painter also calls `QPainterPath.moveTo/lineTo(x, y)` directly instead of building a `QPointF` per vertex (fewer PySide temporaries on the hot path). No user-visible behaviour change otherwise; no help/wiki/design-doc impact.

- **INDI mounts (seen with LX200 OnStep) no longer log "Error setting UTC Offset" / "Error setting site longitude coordinates" on connect.** Connecting sent the mount its time and site twice in quick succession (once from the adapter, once from the app's post-connect context push), and neither waited for the driver to finish the first serial exchange with the mount. The two paths are now one (`IndiAdapter.push_context`): each set waits for its property to leave Busy before the next, and an identical repeat within a minute (time) or with unchanged coordinates (site) is skipped. Internal to the INDI adapter; no UI, help or wiki change. If the errors persist, they come from the OnStep driver rejecting the values themselves (the INDI log will show), not from ordering.
- **CI static-analysis (ruff) failure fixed.** Two `except Exception as e:` handlers in `galileo/library/services/telescope_ftp.py` bound `e` without using it (F841, introduced by the merge repair), which failed the blocking ruff step. The binding is removed; no behaviour change, so no help/wiki/design-doc impact.
- **Installed builds no longer fail to plot satellites in the Star Atlas (`ModuleNotFoundError: No module named 'sgp4'`).** `sgp4` is imported lazily by `galileo.planning.minor_bodies` but was never declared as a dependency, so it was present in the development environment but not in the CI-built installers. It is now in `pyproject.toml` and `requirements.txt`. No inline-help or wiki change.
- **Repaired merge `5d0c7d5`, which broke the library package and the installer build.** The merge combined the refactor that split `file_processing`, `master_manager`, `light_calibration`, `telescope`, `sessions_widget` and `config_widget` into helpers/mixins with the other branch's edits to the *old* monolithic code, and git spliced the two together wrongly: `file_processing.py` no longer parsed (so all of `galileo.library` failed to import and ~65 library tests failed in CI), and `master_manager.py`/`telescope.py` referenced names that no longer existed. The refactored structure is restored and the other branch's changes are re-applied onto it: the master-scan header pre-check, FlatDark masters (flat-dark subtraction when calibrating, `FlatDark` session rows and resource status, the flat-dark lookup through the flat session), tile-compressed/multi-extension image reads in calibration, the Celestron Origin FTP support and hostname setting, DWARF/Origin hostname handling in `find_telescope`, and the per-Observatory weather history attribute. No new behaviour, and no inline-help or wiki change: no control was added or renamed.

### Fixed

- **INDI focuser: moving a focuser that exposes neither `ABS_FOCUS_POSITION` nor `REL_FOCUS_POSITION` no longer crashes with `RecursionError`.** `move_to` and `move_by` each delegated to the other when their own property was missing (typically when the driver's properties hadn't arrived, or the driver is unusual), recursing until Python's stack limit and flooding the log with a traceback. They now go straight to whichever property exists (`move_by` falls back to an absolute move, `move_to` to a relative one) and raise a clear `DevicePropertyError` when neither is present. Regression test added; no inline-help or wiki change.
- **"Suppress Delete Warnings" (Options > Library) now suppresses the delete popup that was still appearing.** It only skipped the confirmation question; the "File Soft-Deleted" information dialog shown after every delete from the Images screen ignored the setting, so deleting still produced a popup. That notice is now skipped too. The inline help entry says so.
- **Flat Assistant now parks the flat panel and turns its light on.** Panel flats (and the older single-filter flat wizard) *opened* the cover, so the panel wasn't over the scope, and the wizard never switched the light on at all (it only set a brightness). Both now close the cover (the panel's "park" — over the scope), switch the light on, set the brightness, and afterwards switch the light off and reopen the cover so the scope is free to image. The wiki already described this behaviour ("cover closed, light on"); no inline-help change needed as no control changed.

### Changed

- **Polar alignment: start at the pole, measure away from it, then aim with an X and a circle.** You point the scope at the pole to begin; solves right at the pole are unreliable (and an RA turn there barely moves the camera), so Galileo now first slews to about Dec 70° (`PolarAlignSettings.work_dec_deg`; skipped if the scope is already between Dec 60° and 75°). When starting at the pole it also picks an RA that keeps the whole swing on one side of the meridian, and the meridian check now includes the starting position. After the three solves, the Polar Alignment tab draws a **circle** (where the axis points now) and an **X** (the celestial pole) in the camera frame's orientation and tells you to bring the X into the circle; both update with every solve, and the circle turns green within a minute of arc. This needs the field geometry, so `SolveResult` gained an optional `cd` (CD matrix) filled by the ASTAP and local astrometry.net backends; other solvers fall back to the written corrections. Tests added; inline help ("Polar target") and the wiki updated.
- **The Solve screen's preview is debayered when the Imaging tab's Debayer box is ticked** (using the camera's Bayer pattern), so one-shot-colour frames show in colour there as they do on the Imaging page. The mosaic is debayered before the preview is sub-sampled; the solver itself still gets the raw frame. The preview follows the box as it stood when the solve started. Test added; no new control, so no inline-help or wiki change.
- **Mount nudge / jog speeds raised 5x again** (`NUDGE_RATES`: Fine 0.2→1, Medium 2→10, Coarse 10→50 °/s) because the previous increase was still extremely slow in practice. These speeds drive both the Imaging page's Mount Nudge and the Equipment > Mount jog pad. On INDI mounts the speed is snapped to the driver's standard slew rates, so Fine now selects "find" and Medium/Coarse select "max"; Alpaca mounts receive the value directly via `MoveAxis` and clamp it to what they support. No inline-help or wiki change: the docs don't quote the numbers and no control was added or renamed.
- **The Star Atlas is now the screen shown at start-up, and the Dashboard icon is hidden from the sidebar.** The Dashboard page is still built (`OBS-060`, `PRIMARY_SECTIONS` unchanged) but has no entry point for now. No inline-help or wiki change: no control was added or renamed.
- **Science menu: "Variable Stars" appears only when the VSTarget plugin is installed, and the Science section hides entirely (sidebar and Options) when no plugin supplies any item.** `SCIENCE_ITEMS` is now empty — the old built-in "Variable Stars" stub was a placeholder shown even with no plugin. `TC-SKYMAP-010` updated; the submenu count no longer assumes a plugin is present.
- **Plugins can add controls to an Equipment page.** A plugin declaring `panel_level = "equipment:<category id>"` (e.g. `"equipment:switch"`) has its `build_page()` widget embedded on that Equipment page (`UiRegistry.get_equipment_panels`) instead of appearing under Science. The Kasa Switch plugin uses it, so **Kasa switches are now on Equipment > Switches** with a "Scan for KASA switches" button and On/Off buttons per outlet, rather than under Science. No inline-help change needed: the controls belong to the plugin's own panel.

### Removed

- **Imaging: the View panel's Panels… button and its dialog are gone.** The saved panel layout (`UI-020`) is still applied at start-up, but there is no longer an in-app editor for it. Help, wiki, SDD and UAT scripts updated.

- **The retired `galileo.sequencer` package is gone; the session engine now lives at `galileo/session_exec.py`.** "Sequencer" was dropped as a concept early on and the running app only used `session_exec`; `basic.py` (`SequenceRunner`), `advanced.py` (nested instruction/condition/trigger engine) and `file_namer.py` were reachable only from tests, a plugin hook and a self-test import. All imports moved to `galileo.session_exec`. `PluginContext.register_instruction_type` (same name, so plugins keep working) now records the class in a new `galileo.session_exec.BlockRegistry`, and any class with an async `execute(context)` runs; plugin blocks still do not appear in the Sessions palette. Tests that exercised the dead engines were rewritten against `session_exec`/`ui.sessions` (TC-SES-010/300/330/340/350, TC-PLUG-020, TC-LIB-150, TC-NFR-REL-010, the scheduler fixture); TC-SES-020/070/090/310/320/360 and TC-NFR-REL-040 now skip, because that behaviour existed only in the deleted package. ### Added

- **Safety devices (weather stations, safety monitors) and their rules now belong to the Observatory, not a Pier (`OBS-030`).** One station watches the sky over every Pier under the roof, but each Pier had its own copy of the device and its own rules, and the scheduler judged a Pier by whichever copy was on screen — so a job could run on another site's weather. Now they are configured, saved and connected once per Observatory: migration `029` adds `safety_device_configs` and `observatory_safety_rules` and carries each Observatory's existing settings up from its lowest-numbered Pier (the per-Pier rows are removed; rolling back copies them to every Pier). The Safety page keeps its tabs and connection when you select another Pier of the same Observatory and rebuilds only when you change Observatory; the top-bar Pier Connect/Disconnect no longer tears the shared devices down (a Pier's Disconnect would have blinded every other Pier), so the tab's own button now toggles **Connect**/**Disconnect**. Every Pier's job queue is gated on that one verdict. **Fixed with it:** the verdict used the last reading taken while the Safety page was on screen, so unattended gating could rest on a stale or empty reading; `evaluate()` now re-reads a device whose reading is older than its poll interval, and a connected device that cannot be read counts as unsafe. In the domain model `Pier.safety_monitor` / `Pier.set_safety_monitor` and `Observatory.set_safety_monitor(scope=...)` are removed. SRS `OBS-030` (and the `OBS-140`, PSD, SDD wording that depended on it), RTM, Equipment/Planning wiki articles, Safety and common help updated; tests `TC-OBS-030` (Observatory scope, other Observatory not inheriting, migration up and down), `TC-OBS-140` (stale-reading refresh). Not covered: tested against fake stations, not a real one; Piers of one Observatory that really have different weather sources can no longer be modelled — use separate Observatories.

- **CI: informational test run on Python 3.14 (`tests-newest-python` in `quality.yml`).** The suite now also runs on the newest Python, never blocking a merge, so deprecations and 3.14/3.15 incompatibilities show up early. `requires-python` stays `>=3.11` because Raspberry Pi OS Bookworm ships 3.11. Expect the job to fail at install until `sep` (no 3.14+ wheel) and `lz4` (no 3.15 wheel) publish wheels; move it to 3.15 then. CI only; no code, help, wiki or design-doc change.

- **Scheduled sessions now run on every Pier, not only the selected one (`OBS-140`).** The scheduler tick used to service only the Pier selected in the top bar, so with three Piers an overnight schedule would have stalled on two of them until you clicked over to each. It now walks every Pier of the Observatory and starts each idle Pier's due job against that Pier's own devices (every Equipment page already kept each Pier's connection across a Pier switch; they now expose it as `adapter_for(pier_key)`, and `build_session_context(window, pier)` / `_imaging_frame_context(pier)` / `active_optical_tube(pier)` take a Pier). A non-selected Pier uses its primary camera and first optical tube, since the top-bar selectors describe only the selected one; a Pier with no camera and no mount connected waits instead of failing its job; one Pier's error no longer stops the others being serviced. Safety is gated on the Observatory's safety devices — see the entry below. The Dashboard reports each Pier's real connection state instead of showing every non-selected Pier as disconnected. A session started with **Run** is unchanged. New requirement `OBS-140` (SRS, RTM, SDD 4.4b/4.9b), tests `TC-OBS-140` (three-Pier tick, per-Pier context, unsafe Observatory holds every Pier, unconnected Pier waits alone, Dashboard), Dashboard help, wiki Planning article and README updated. Not covered: the cross-Pier tick has been tested with fakes, not on three real mounts.

- **Library: flat-dark calibration frames (`LIB-180`), ported from AstroFiler.** Dark frames taken at a flat's exposure are now a calibration type of their own instead of being mistaken for darks (or flats). They are recognised however `IMAGETYP` spells them ("Flat Dark", "FLATDARK", "Dark Flat"), filed under `Calibrate/FLATDARK`, grouped into `FlatDark` sessions, linked to the flat session they match, stacked into a `flatdark` master by Auto-Calibration, and — in `calibrate_light_frame`, `galileo-auto-calibration` and Library > Sessions > Calibrate — subtracted (less the bias) from the flat before it is normalised, so the flat no longer carries its own bias pedestal and thermal signal. Check-out of a light session includes the flat-dark master. Without a flat-dark the calibration is exactly as before. The wiki's Library article is updated; new tests `TC-LIB-180`.
- **Library: Celestron Origin download source (`LIB-190`), ported from AstroFiler.** Library > Images > Download and `galileo-download -t "Celestron Origin"` list and fetch the raw FITS files in the telescope's `RawData` folder over anonymous FTP. The telescope is addressed by IP or an `origin`/`celestron` hostname; its address is saved under Options > Library > Celestron Origin Configuration (blank uses the Origin's own hotspot address, 192.168.1.208). Inline help, wiki Options article and new tests `TC-LIB-190`.

- **Generic User Acceptance Test script, [`docs/UAT-generic.md`](docs/UAT-generic.md).** The same end-to-end night as `UAT.md`, but not tied to M13 or the INDI simulators: a Test profile at the top has the tester choose their own target (with a checklist for picking one that suits their site, date and optics) and record their own equipment, protocol and optics, and steps for devices they don't have are `N/A`. Adds steps for a meridian flip, a mosaic with rotation, and a cooled camera. Documentation only; no code, help or wiki change.

- **Schedule screen: drag a scheduled session back to Unscheduled.** Dropping a session block from the calendar onto the Unscheduled list now unschedules it (same as "Remove from Schedule"), instead of only being able to move it around the grid. Pier operations still just reposition, since they have no Unscheduled state. Updated the Schedule help.

- **Schedule screen: Upcoming Sessions panel.** A read-only list below the calendar shows every scheduled entry that hasn't finished, soonest first, each with its local start time and a text summary of its activities beginning with the target (e.g. `Slew To: M31 › Image: 10×300s Ha`). It refreshes with the page. Added to the Schedule help and the Planning wiki article.

- **Dark Capture block: Close Cover option.** A new checkbox closes the Pier's dust cover or flip-flat panel (when one is connected) before the darks and reopens it afterwards, so darks are taken with the light path covered. The Filter field stays, since some cameras (Seestar) use a dark cover filter instead. With no cover connected the block continues and logs that. Saved/templated sessions without the field load as off. Updated the Sessions help.

### Fixed

- **Library: frames whose image is not in the primary HDU are now calibrated.** Galileo's own tile-compressed FITS files keep an empty primary HDU with the image in an extension, but light calibration read only `hdul[0]`, so a compressed light or master was treated as empty. Calibration now finds the image in whichever HDU holds it (`galileo.library.core.utils.fits_image_data`).
- **Library: DWARF Mini and other DWARF variants import.** Only a `TELESCOP` of exactly "DWARF" was recognised, so a DWARF Mini (or a card with no `TELESCOP` but the usual `DWARF_RAW` folder layout) was rejected as having a bad header. Any `DWARF…` name, or the folder structure, now qualifies.
- **Library: darks link by exposure and temperature.** A light session's dark was matched on exposure as an exact text comparison and ignoring CCD temperature, so "60" never matched "60.0" and a dark from a warm night could calibrate a cold one. Exposure is now compared numerically and the CCD temperature must be within 5 degrees (the same rule is used for flat-darks).
- **Library: master frames are recognised by a punctuation-insensitive name.** Master detection looks at the normalised file name, `IMAGETYP` and `OBJECT`, so `Master_Flat-Dark` and `masterflatdark` are the same and a flat-dark master is no longer mistaken for a dark. Registering masters also skips non-master files from their header alone, without decompressing them first.

- **`docs/UAT.md` simulator setup corrected.** It started the INDI CCD simulator twice to get a guide camera; INDI has a separate Guide Simulator driver, so the `indiserver` command now loads `indi_simulator_ccd` and `indi_simulator_guide` once each, and the PHD2 note points at the Guide Simulator. The command's line continuations, which had been lost, are restored. Docs only.

- **Sessions › Load from Template error used the old "Target" name and was too strict.** The message said "requires an existing concrete Target block" although the block is now called **Slew To**. It now reads "Load from Template needs a Slew To block with a target chosen. Add one first." The check also only looked at the first block; it now accepts a concrete Slew To block anywhere in the session. Updated the Sessions help and SRS SES-190 wording.

- **Wiki pages renumbered with leading zeros** (`01.-` … `09.-`) so they sort correctly in GitHub's wiki contents list (previously `10.` sorted before `2.`). Wiki-internal links, the Home table, and the wiki URLs in `README.md` and `docs/UAT.md` were updated to match. The Plate Solving and Imaging wiki articles now mention Load & Slew setting the current object and rotation applying to a mosaic. Docs only.

- **Solve › Load & Slew now sets the current object.** After slewing to the loaded image's field the Pier's current object stayed whatever it was before, so a following Capture & Solve (Slew to Target) slewed back to the old object. The destination (named from the file's `OBJECT` card, else its coordinates) is now the current object. Updated the Solve help.

- **Log file no longer flooded by INDI mount trace messages.** The telescope driver's `[ALIGNMENT]` and `[SCOPE]` messages (several per second while tracking) made up about 94% of a typical day's log (14,500 of 15,500 lines). They are no longer written to the log; errors and warnings from drivers, and all other driver messages, are still logged. Internal change; no help/wiki impact.

- **Framing Assistant: rotation now applies to a mosaic.** Setting a rotation together with a mosaic grid used to be ignored (the dialog said so); now the whole grid turns about its centre, so pane positions and each pane's outline are tilted in the preview and in the captured pane coordinates, and the survey image is sized to the tilted grid's bounding box. With a rotator connected, **OK** also turns the rotator to the angle. With no rotator and no explicit grid the existing auto-sized covering mosaic is unchanged. `create_mosaic` and `mosaic_footprint_deg` gained an optional `rotation_deg` (default 0, so existing callers are unaffected). The session Image block's mosaic dialog has no rotation field and is unchanged. Rotation help entry updated; new test `test_tc_frame_040_mosaic_rotation_turns_the_grid`.

- **Removing a session from the Schedule grid now returns it to the Unscheduled tray** (its start time is cleared) instead of deleting the job. Right-clicking an entry in the Unscheduled tray now offers **Delete** (with confirmation) in place of Remove from Schedule, so deleting is the explicit, separate action. Pier operations, which have no tray to return to, are still deleted. Inline help updated.

- **A session scheduled on Planning > Sessions now appears in the Schedule page's Unscheduled list.** The Schedule page only refreshed on Pier changes, so a job added while it was hidden stayed invisible until something else forced a reload; it now reloads each time the page is shown. No help/wiki change (no control changed).

- **Start-up splash shows device connection attempts.** While the Equipment screens auto-connect, the splash now names each device being connected (name, host:port) and then records a ✓ Connected or red ✗ Failed line, instead of sitting on "Loading Equipment screen". Applies to the mount and all other device pages that connect through the shared adapter path; the camera sensor-info probe is not reported. Internal UI change; no help/wiki/design-doc impact.

- **Splash progress bar no longer covers the logo.** The start-up progress bar, operation list and percentage now sit in a strip added beneath the licence notice rather than over the Galileo artwork. Internal UI change; no help/wiki/design-doc impact.
- **Crash ("QWidgetItem has no attribute 'isVisible'") when connecting to PHD2.** The help tooltip timer scanned `QApplication.topLevelWidgets()` and hit a stale non-widget wrapper while a window was being torn down; it now skips anything that isn't a real `QWidget`. The root cause of the stale wrapper (likely the PHD2 connect dialog closing) was not identified from the crash report alone.

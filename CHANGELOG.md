# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions are pre-releases (`0.9.NNalpha`) tagged `v0.9.NNalpha`.

**Each release has its own archive file in [`docs/changelog/`](docs/changelog/)**, named after the version (e.g. [`0.9.03alpha.md`](docs/changelog/0.9.03alpha.md)); the older monthly files (`2026-09.md`, `2026-10.md`) hold entries from before versioned headings began. This file holds only `[Unreleased]` and the index below, so it stays short. Search the archives (`grep -rn <term> docs/changelog/`) rather than reading them end to end.

**At each release:** run `python scripts/archive_changelog.py <version>` (e.g. `0.9.04alpha`). It moves everything under `[Unreleased]` into `docs/changelog/<version>.md`, leaves `[Unreleased]` empty and adds a line to the index. Then bump the version in `galileo/__init__.py` and `pyproject.toml` (the registration ping follows `__version__` automatically), write `docs/release-notes/v<version>.md`, and tag.

## [Unreleased]

### Fixed

- **A device the desktop connected was held under a second category spelling (`HEAD-090`).** The device service stored desktop-connected filter wheels, flat panels and weather stations as `filterwheel`/`flatpanel`/`weatherstation`, while the Control Surface looks for `filter_wheel`/`flat_panel`/`weather`, so the phone could see them listed as connected yet get "no filter wheel". `DeviceService.adopt` now files every device under the Control Surface name. **Checked:** the name mapping; **not run:** against the phone.

- **The phone no longer reports "Pier has no mount/camera" for devices the desktop shows connected (`HEAD-090`).** With *Hold devices in the device service* on, a mount or camera connected before that (or kept by a screen across a Pier switch) was owned by its screen only, so the Control Surface could not see it and the phone refused with "this Pier has no mount/camera" even after Connect All. The top bar's Connect, and the periodic connect-state refresh, now hand every live adapter the screens hold for the current Pier to the device service (`desktop_devices.adopt_held`), so no separate connect from the phone is needed. **Checked:** imports and existing tests; **not run:** against a real phone and hardware. No visible controls changed, so no help or wiki change.

- **ASTAP solves that worked in standalone ASTAP but failed from Galileo (`PLT-060`).** Galileo called ASTAP with settings the standalone program does not use. (1) `SolverParams.downsample` defaulted to 2, so ASTAP was forced to `-z 2` and could lose too many stars on a small or binned frame; the default is now 0 (ASTAP chooses, as it does standalone) and the Options > Solve box reads **Auto** instead of **Off**. `-z 1` is now sent when you choose 1, so full resolution is possible. (2) The field-of-view hint was computed from the optical train's scale and the image height, ignoring binning, and overrode the header; it is now skipped when the frame header carries `FOCALLEN` and `XPIXSZ` (ASTAP derives the scale itself) and otherwise multiplied by the binning. (3) A solve that fails with a position hint (typically the mount's possibly-wrong reported position, limited to the search radius) is retried once without the hint so ASTAP reads the position from the header. (4) Failures are now logged at warning level with the full command. **Checked:** new `TC-PLT-060` tests pass; **not run:** against a real ASTAP install. A Pier that saved Downsample 2 earlier keeps it; set it to Auto if solves still fail.

### Added

- **Options > Solve: ASTAP options (`PLT-060`).** A free-text field of extra command-line options for ASTAP, saved per Pier (new `solver_settings.astap_args` column, migration 041) and passed after Galileo's own. An option repeated there replaces Galileo's (so `-z 4`, `-fov 1.2` or `-r 90` wins); `-d` sets the star database. `-f` and `-o` are ignored since Galileo reads ASTAP's answer through them. Inline help (`options.solve`) and the wiki's plate-solving article updated. Not yet in the replicated-settings spec, so it is not synced between nodes.

### Added

- **Star Atlas right-click menu: Save to Targets / Remove from Targets (`SKYMAP-120`).** Right-click a star or deep-sky object and choose **Save to Targets** to put it on Planning > Targets without leaving the map; it is then always plotted (orange) on every Star Atlas. For an object already saved, the item reads **Remove from Targets**. It is greyed out for planets, comets, asteroids, satellites and empty sky, which either move or aren't objects. Uses the existing `_save_target` / `_remove_saved_target`, so the map replots through `SavedTargetsChangedEvent`. Inline help and the wiki article updated. **Not done:** the mobile apps' object card has no Save button yet, as saving needs a write route in the MobileConnect plugin that doesn't exist. **Checked:** new test passes; **not run:** not looked at in the running desktop.

### Added

- **Star Atlas: every saved target is always plotted, and Find plots everything it could mean (`SKYMAP-120`).** Objects on the Targets list now appear on the map, in orange with their name and the icon of their type, whatever catalogs, magnitude limit and Show options are set; saving or removing a target updates the map at once (new `SavedTargetsChangedEvent` on the bus, published by `galileo.planning.saved_targets`; targets replicated from another node appear on the next marker poll). Find used to select and centre one object, which might not be the one meant and, if faint or in a switched-off catalog, was not even drawn. It now plots every object the text matches (best first, up to eight) in yellow with its name and type icon; the best is selected and centred, and clicking any other selects it so it can be designated (Add to Session, Save, current object). Searching again replaces them; Enter on an empty box clears them. The catalog drawing's icon code became one shared `_draw_dso_icon`, with no visible change. **Checked:** new `TC-SKYMAP-120` tests pass. The two existing `test_star_atlas.py` catalog tests that expect no `IC` catalog already failed before this change and still do. **Not run:** not looked at in the running desktop.

### Changed

- **The engine now knows the Piers of every Observatory, not just the one it runs (`HEAD-140`).** Its Pier list (and `pier.list`) carries each Pier's Observatory name, so a mobile app can show "Observatory - Pier" and let the person choose any Pier. Only the home Observatory's Piers still connect on their own at start-up; the others stay disconnected until a client connects them (`device.connect_all`). Sessions, schedules and safety now also see the other Observatories' Piers, though nothing runs on a Pier that is not connected. `test_head.py`'s Pier-list test expects the new `observatory` field. Note: 8 tests in `test_head.py` fail on this machine regardless ("AF_UNIX path too long"); run them with a short `TMPDIR` such as `/tmp/g`.

### Added

- **`device.connect_all` (`CSURF-320`).** Connects every device the Pier has configured in one call (what the desktop does when a Pier connects), refusing a Pier with nothing configured and naming any device that would not connect. For the mobile apps' new Connect All Devices button on Overview. New test `test_tc_csurf_320_connect_all_brings_up_every_configured_device`. Restart Galileo.

- **Held mount jog takes a speed (`CSURF-330`).** `mount.hold_start` accepts an optional `level` 1-9, the Mount page's jog speeds (0.002 to 10 deg/s; 7, 0.2 deg/s, when omitted), for the mobile apps' new speed slider. New test `test_tc_csurf_330_a_held_jog_can_name_its_speed_level`. Restart Galileo.

- **Plate solves can use any of the Pier's cameras (`CSURF-140`).** `solve.capture`, `solve.sync` and `solve.centre` take an optional `camera_slot` (the primary camera when omitted), and a new read operation `solve.cameras` lists the Pier's cameras as `slot`, `name` and `connected`, so a mobile app can let the person choose. A slot that is not connected is refused with the usual "the camera is not connected". New test `test_tc_csurf_140_solve_uses_the_camera_slot_asked_for_and_lists_the_cameras`; the existing solve-catalogue test now expects `solve.cameras`. Restart Galileo for the apps to see it.

- **Held mount jog accepts diagonals (`CSURF-330`).** `mount.hold_start` now takes `northeast`, `northwest`, `southeast` and `southwest` as well as the four compass directions: a diagonal moves both axes at the jog rate, and releasing or losing the hold halts both. Needed by the mobile apps' new diagonal jog pad; a Master without this change refuses the diagonals. New test `test_tc_csurf_330_a_diagonal_drives_both_axes`.

- **Imaging: "Subtract dark" checkbox (View group).** Subtracts the Library's dark master from the preview when one exists for the frame's telescope and camera at the same binning and an exposure within 1%; the status line reports the master used or why none was. Preview-only like Debayer (statistics, histogram and saved frames stay raw) and not remembered between sessions. Inline help and the Getting Started wiki article updated. The same checkbox is now also on the **Focus** screen (Camera box; applies to frames taken after ticking it; HFR measurement stays on the raw frame) and the **Solve** screen (Plate Solve Capture Options; redraws the frame on show, matching on the frame's own FITS headers; the solver still gets the frame as saved, the solver never sees it). All three share `galileo/dark_master.py`, which also logs the dark master's file name (with the rig, exposure and binning) each time one is applied. Inline help for Focus and Solve and their wiki articles updated.

- **Star Atlas right-click menu: Park / Unpark.** The menu now ends with **Park** when the connected mount is unparked and **Unpark** when it is parked (read from the mount's park state; hidden when no mount is connected or it doesn't report one). Inline help and wiki updated.

- **IC catalog, and searched objects are kept (Star Atlas, What's Up Tonight, Search, mobile).** `IC` joins Messier, Caldwell and NGC as a selectable catalog on Search, What's Up Tonight and the Star Atlas (the bundled OpenNGC data already held the IC objects; they simply couldn't be picked). An object found by name that is not in the bundled catalog (an online Simbad lookup) is now stored in the database (new `user_objects` table, migration `039`) and merged into the catalog from then on, so it is always shown in Search, What's Up Tonight (ranked ahead of the candidate cap) and the Star Atlas, and passes the catalog/magnitude filters; a name matching an existing object (by designation or within 1 arcmin) is not duplicated. The Star Atlas reloads when a search adds an object. For the MobileConnect apps, `sky.search` now looks unknown names up online and stores them, takes an optional `catalog` (one or several, comma-separated) and returns each object's `catalogs` and `user_added`; new read operation `sky.catalogues` lists the catalogs the Master supports. The mobile app screens themselves are not changed yet. Inline help for Search, What's Up Tonight and the Star Atlas, and the wiki, updated; test `TC-SKY-020` added.

- **What's Up Tonight: Astrospheric hourly forecast under the day/night bar (Options > Planning > API key).** Enter an Astrospheric Professional API key under Options > Planning and What's Up Tonight draws rows (Cloud, Seeing, Transparency, Temperature, Dew point, Wind, plus **Smoke AQI** and **Aurora Kp**) of cells directly under the day/night bar, each cell lined up with its hour and coloured as Astrospheric rates it (raw value inside), from the Astrospheric Data API v2 (`galileo/planning/astrospheric.py`, `_AstrosphericStrip`). The fetch runs off the UI thread, is cached 15 minutes, and re-runs whenever the screen is shown or the date changes, so a newly entered key works without a restart. If Astrospheric can't be used, the line under the bar says why (key rejected / credits used up, rate limited, outside coverage, network error) instead of staying blank. Informational; it does not change ranking. The key is stored in the `planning` settings namespace in the database. Temperature and dew point (kelvin from the API) are shown in °C; Astrospheric does not document units for seeing, transparency or wind, so those are raw values. Each Astrospheric call costs about 130 API credits (cached 15 minutes). The Aurora row is NOAA's 3-hour Kp forecast and the Smoke row is today's NOAA HMS smoke rating as one block across the night (NOAA has no hourly smoke forecast); both are free, need no key, and appear even without an Astrospheric key (`galileo/planning/sky_conditions.py`). Astrospheric's Transparency already includes its own smoke impact. Not yet tried against the live API. New requirement `WUT-120` (SRS, SDD 4.8b, RTM, `TC-WUT-120`); inline help and the wiki Planning article updated. The API key field has a **Save** button beside it (Enter also saves), like other Options pages; it previously saved only when the field lost focus, so a key entered and then navigated away from was lost. The parser reads the live API's actual response shape (one `HourlyForecast` list with every variable per hour), which differs from Astrospheric's published example; before this the strip reported "no forecast" for every location. (Replaces an earlier version that put a one-line summary in the advisory text, where a failure was invisible.)

- **Every button in the MobileConnect apps now has a real operation behind it (Control Surface).** The apps used 45 operations; core registered 37 of the ones they call. A fresh engine now registers 92 and none of the apps' are missing. New: **`device.connect` / `device.disconnect`** (`CSURF-320`): connect or release one configured device of a Pier (mount, camera, filter wheel, focuser, rotator, dome, flat panel, switch, weather), refused in words when the Pier has none configured, and disconnect refused while a session runs; **held mount jog** (`mount.hold_start`/`hold_beat`/`hold_stop`, north/south/east/west, only while held) and the **focus hold operations** that existed but were never switched on, now backed by one deadman `HoldManager` the engine runs, cancelled by lease loss or an unsafe-weather event (`CSURF-330`); **`focus.autofocus` / `focus.autofocus_cancel`** using the Pier's saved autofocus settings, publishing progress as the state key `focus.autofocus` (`CSURF-340`); **`flip.defer`**, which holds back a pending automatic meridian flip for up to 30 minutes but never past the hour-angle limit (`CSURF-350`); and **`session.skip`**, which ends the current block as Stop would and carries on with the next, refusing safety-critical shutdown blocks (`CSURF-360`). Not yet checked on real hardware or a live Master. Known gaps: the desktop's "reversed axes" jog setting isn't applied by the engine; revoking a paired device mid-hold doesn't cancel the hold (the keep-alive running out does); a solve started during an autofocus isn't refused.

- **Planning > Targets: a saved-targets list; the catalog screen is now Search.** The old Targets screen (catalog search with result tiles) is renamed **Search**, and a new **Targets** screen under Planning lists the objects you have saved, as the same tiles. Press **Save** on any tile on Search or What's Up Tonight to add it (saving twice does nothing); on Targets the same button reads **Remove** and takes it off. The list is stored in the database (new `saved_targets` table, migration 038, `SKY-130`) so it survives restarts (it is replicated between nodes like the other configuration tables), and is redrawn each time Targets is opened. The list is replicated between Master and Remote nodes like the other configuration tables (the table is under change tracking from creation) and is published to the mobile apps by MobileConnect (`GET/DELETE /mobileconnect/v1/targets`; the phone and Quest Targets screens are in Galileo-MobileConnect). Inline help: new `planning.search` (renamed from `planning.targets`) and `planning.targets` files, plus a Save entry on What's Up Tonight; wiki Planning article updated.

- **`docs/Astrofiler Back Propogation.md`.** A running list of Library changes (`galileo/library`, `galileo/ui/library`, `galileo/commands`) to be applied to upstream AstroFiler; seeded with the faster SFTP download change. From now on every Library change is recorded there in the same turn. Docs only.

### Changed

- **Imaging-page nudge Speed list no longer shows °/s.** The deg/s figures next to each level were not accurate for the actual mount (levels map to a driver's own slew rates), so the list now shows just the level number (1 slowest to 9), as the Mount page's jog Rate already did. The speeds actually sent are unchanged. No inline help or wiki text mentioned the figures.
- **Saved and scheduled sessions are kept until they complete or are deleted; templates keep their target.** (1) Save and Schedule now store the session (blocks, camera) in the database (new `saved_sessions` table, migration `040`), later edits to it are stored too, and it comes back on the Sessions screen after a restart; a scheduled session is re-attached to its Scheduler job so it can still run — jobs were stored without their blocks, so after a restart a scheduled session could neither run nor be seen. Delete, or completing, removes it; Deschedule keeps it; a session never saved is not kept. This replaces the Save button's `.gses` file, which nothing read back (and which broke the rule that configuration lives in the database). Sessions that were scheduled before this change have no stored blocks and cannot be recovered; reschedule them. (2) **Save as Template** now keeps the Target block's target instead of turning it into a placeholder, so a template is valid as it stands. Load from Template still puts the session's own target in place, and running a template with a chosen target (`session.run`, the apps) replaces its target; templates saved earlier keep their placeholder and still need a target chosen. SRS `SES-060`/`SES-180`/`SES-190`, SDD 4.6a, inline help and the wiki updated; tests `TC-SES-060`, `TC-SES-180`, `TC-SES-190` updated/added.

- **Library: Seestar frames are precalibrated only when downloaded from the Seestar.** Correction to the 0.9.07alpha entry "Library no longer treats Seestar frames as precalibrated": frames Galileo captures from a Seestar as INDI/Alpaca BLOBs are raw and are ingested uncalibrated, but frames downloaded from the Seestar (Library > Download, `galileo.commands.download`) are already calibrated by the telescope, so `registerFitsImage`/`submitFileToDB` gained a `precalibrated` argument that the Seestar download paths set and those frames are ingested with `fitsFileCalibrated=1`. Sessions built from them still show the per-frame state rather than a "Precalibrated" source label (that label remains iTelescope-only). Covered by `TC-LIB-130`.

- **Wiki reorganised for the user manual; links here updated.** The wiki's Getting Started Guide was split into `01.-Installation` (what you need, installing and starting Galileo, plus installing INDI and an ASCOM Alpaca bridge, which were separate articles) and `02.-Getting-Started` (window tour through first exposure). The Options article was removed and each settings page is now described in the article for the feature it configures (horizon in Star Atlas, autofocus defaults in Focus, solver settings in Plate Solving, Library folders and tabs in the Library, Connect Link and notifications in NodeConnect, outreach in WebConnect, plugin management in the new Plugins Documentation appendix). Equipment became `03.-Setting-up-Equipment`, the screen articles gained "Using ..." titles, the plugin articles became appendices (`A.-Plugin-Developers-Guide`, `B.-Plugins-Documentation` with `B1`/`B2`), and new articles cover WebConnect and MobileConnect. `README.md`, `docs/UAT.md` and `docs/UAT-generic.md` linked to the old page names and now point at the new ones. Documentation only, no code change.

### Removed

- **Solve: the "Dark" checkbox.** It took a new dark frame after each solve exposure and subtracted it before solving; it is gone from Plate Solve Capture Options (the new **Subtract dark** box, which only affects the picture, remains), and its help entry and wiki mention were removed. Solves no longer capture a dark frame. The `SolveSettings.subtract_dark` option in `galileo.platesolve` is left in place, unused by the UI.

### Fixed

- **Connecting all of a Pier's INDI devices at once reported that none of them were available (`EQP-040`).** Connect All Devices (and the engine's start-up connect) brings up a Pier's devices at the same time. They share one connection to the INDI server, and only the device that opened it waited for the server to finish announcing its devices; the others read the device list too early, saw nothing, and failed with "INDI server has no device named X (available: none)". The desktop connects its devices one after another, which is why the same Pier worked there. Every caller now waits for the server's property burst (immediate once it is over). New test `test_tc_eqp_040_a_second_connect_waits_for_the_servers_first_property_burst`, which fails without the change. Restart Galileo.

- **Library > Sessions now shows masters created by Auto-Calibration straight away.** The Sessions tree was reloaded after the Auto-Calibration dialog only if it returned "accepted", but the dialog never accepts (Close and the window X both count as rejected), so new masters didn't appear until you regenerated sessions. It now reloads whenever the dialog closes. No control changes, so inline help and wiki are unchanged; recorded in `docs/Astrofiler Back Propogation.md`.

- **Autofocus V-curve was scrambled: HFR was huge at moderate defocus and tiny when far out of focus.** The star measurement (`_measure_stars`) let SEP deblend defocused donuts into fragments that each read as a small star, counted faint noise detections and neighbouring stars, and sized apertures too small for faint donuts, so the median HFR jumped around instead of rising with defocus. It now turns deblending off, detects at 3σ with a minimum area, uses only isolated stars (brightest 150), sizes each star's aperture from its own detected area, and takes a true half-flux radius with unclipped background. On synthetic crowded fields (279 stars) HFR now rises steadily from sharp to far out of focus (HFR ~2 to ~14 px); `TC-FOC-010` has a regression test for it. The star count is now used to judge each reading: a reading with no stars, or with under half the sweep's best star count *and* an HFR below the sweep's median (a hot pixel or noise speck, not a real sharp focus), is left out of the V-curve fit and named in the log; a high HFR from few stars (genuinely defocused) is kept. If fewer than 4 readings remain the run fails with a message suggesting a longer exposure or smaller step instead of fitting noise (`unreliable_points`, `AutofocusResult.rejected_positions`, test in `TC-FOC-010`). The sweep also refuses a downward-opening parabola and reports a failure instead of moving to the worst position. Not yet checked on real frames, and HFR values differ from earlier versions, so saved HFR thresholds may need adjusting. No UI control changes.

- **Scheduled sessions now start even if you never opened Planning > Sessions.** The timer that fires due calendar entries was only started when the Sessions page was built, and pages are built lazily, so a job placed on the Schedule calendar sat at "pending" with an empty log forever. The Schedule page now starts the timer too. The log dialog's empty text no longer claims execution "isn't wired up for this build" (it is); it says the entry has not run. No help, wiki or design-doc change needed.
- **No more "Python quit unexpectedly" popups from short-lived runs.** The Plugins page's marketplace workers (`_LatestThread`, `_FetchThread`, `_DownloadInstallThread`) were `QThread`s; building the window and exiting (the test suite, `python -m galileo.ui.help --audit`, or quitting) while the version lookup was mid-HTTPS-handshake made Qt abort with "QThread: Destroyed while thread is still running" and macOS showed a crash report. They are now daemon Python threads reporting through queued Qt signals, so a request still in flight at exit is just dropped. Behaviour of the Plugins page is unchanged (no help, wiki or design-doc change needed).

- **Generating tetra3 databases (Options > Solve) now fails politely when the star catalogue can't be downloaded.** A network timeout or connection error used to log a long traceback and leave only a terse `URLError` line in the status text. It now logs a one-line warning, removes the partial download, reports "Could not download the star catalogue — check your internet connection and try again", and shows a warning dialog listing any databases that failed. No new controls, so inline help, wiki and design docs are unchanged. Not exercised against a real network failure.

- **Connecting to an INDI server with the protocol left on Alpaca no longer just logs a traceback.** On the Equipment device pages, if the scan fails with the chosen protocol, Galileo now retries with the other one (switching the protocol dropdown, and the port if it was still the old protocol's default) and reports the switch in the status bar. If neither protocol finds a server, a "Server not found" dialog says so and only a one-line warning is logged. No new controls, so inline help, wiki and design docs are unchanged. Not run against live servers or covered by a new test.

- **The sky survey background now falls back to more backup sites when CDS is unreachable.** The Mellinger photo-mosaic behind the star atlas only tried CDS's two hosts (`alasky` and `alaskybis.cds.unistra.fr`), which share one DNS domain and one institution, so a CDS or DNS outage left the atlas with no sky image. It now also tries CDS's older `alasky.u-strasbg.fr` name and the independent IAS Orsay mirror (`healpix.ias.u-psud.fr/CDS_P_Mellinger_color`), remembering whichever answers first. The added hosts could not be reached from the development machine (its DNS was failing), so they are untested live. No visible controls changed, so inline help, wiki and design docs are unchanged.

- **The mount jog pad and the Imaging nudge pad now use arrows (↑ ↓ ← → and ↖ ↗ ↙ ↘) instead of N/S/E/W letters, and the Mount page's Rate box is wide enough to read.** The Rate drop-down sat beside its label squeezed to about one character; it now sits below the jog pad at a usable width. Hovering a button still names the direction. No change to what the buttons do. The wiki's Imaging table was updated.


- **Test suite and lint pass again on CI.** Closing a test's main window opened the modal "Support Us" quit dialog and hung the run until the timeout (tests now stub it); two ruff findings (`RUF012` mutable class attributes in `telescope_sftp.py`, `B905` in `scripts/download_stats.py`) are fixed; `test_head`/`test_link_gateway` now match the Gateway's reworded "take control of this Pier" refusal; and the sky/visibility tests no longer fail when astropy's bundled Earth-orientation (IERS) data is older than 30 days. No user-visible change, so no help, wiki or design-doc update.

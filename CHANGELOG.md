# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions are pre-releases (`0.9.NNalpha`) tagged `v0.9.NNalpha`.

**Each release has its own archive file in [`docs/changelog/`](docs/changelog/)**, named after the version (e.g. [`0.9.03alpha.md`](docs/changelog/0.9.03alpha.md)); the older monthly files (`2026-09.md`, `2026-10.md`) hold entries from before versioned headings began. This file holds only `[Unreleased]` and the index below, so it stays short. Search the archives (`grep -rn <term> docs/changelog/`) rather than reading them end to end.

**At each release:** run `python scripts/archive_changelog.py <version>` (e.g. `0.9.04alpha`). It moves everything under `[Unreleased]` into `docs/changelog/<version>.md`, leaves `[Unreleased]` empty and adds a line to the index. Then bump the version in `galileo/__init__.py` and `pyproject.toml` (the registration ping follows `__version__` automatically), write `docs/release-notes/v<version>.md`, and tag.

## [Unreleased]

### Added

- **Farewell dialog on quit ("Support Us"; logo 25% larger).** The Starseekers.ca logo on both this dialog and About is now 320 px wide (was 256). The Support Us window is sized from the dialog's natural width (a 25% widening, since trimmed back by 25%), its text now reads as a Patreon appeal, the version heading is removed, the text is vertically centred against the logo with a wide (60 px) gutter between them, and the "Do not show this again" checkbox sits under the logo. Its text is 4 pt larger than the default (set in the dialog HTML, since the theme stylesheet ignored a widget font change) and the copyright notice is removed from it (About keeps it). Quitting Galileo (power button or window close) now shows a dialog in the same format as About, with a thank-you (including a Patreon link and a one-time-contribution PayPal link) and a request to support Starseekers.ca in place of the "Cross-platform..." line, plus a **Do not show this again** checkbox. Ticking it saves the current version in `ui.hide_quit_dialog_version` in the settings database and the dialog no longer appears until Galileo is upgraded to a different version, when it is shown again automatically (covered by a TC-ARCH-090 test). About is unchanged. It has no per-control help screen (a standard message box), so no inline-help or design-doc change was needed.
- **Library > Images: select several frames at once.** Shift-click selects a range and Ctrl-click adds or removes individual rows. With more than one row selected, the right-click menu offers only **Delete**, which soft-deletes every selected frame after a single confirmation (frames still On Master are skipped). Inline help (`library.images`) and wiki updated.

- **View Log button in the sidebar's small icon menu.** Opens a log viewer window showing this run's full log file (`galileo_<date>.log`, DEBUG and above, with tracebacks), not just the INFO tail the per-screen panes show. It has a level filter (Debug / Info / Warnings / Errors only), text search, auto-refresh that follows the newest line, Copy and Open Folder. Satisfies `LOG-020`; new `galileo.ui.log_viewer`, `galileo.diagnostics.get_current_log_file`, a View Log entry in the common help and a wiki mention in the Getting Started guide.

### Changed

- **Equipment > Aux is renamed Control Panel and is now an INDI Control Panel, like the one in EKOS.** (Only the label changed in the UI; the internal id, saved settings and `EQP-AUX-*` requirement IDs keep the `aux` name.) **Connect** opens the whole INDI server and loads every device it reports as a tab; each device tab holds a sub-tab per INDI property group (Main Control, Options, Image Settings, ...) with the driver's own switches, numbers and text fields, a state dot per property, and the log tail underneath. Galileo no longer asks you to pick one device (there is no Driver, Scan or Device control any more), and devices are not connected for you — use each device's own Connection switch, as in EKOS. The open device and group tabs and any half-typed value survive the 2-second refresh; a device that defines more properties after it connects gets its tabs rebuilt in place; a lost server connection is reported instead of retried silently. **Save** now stores just the INDI server and port for the Pier (an INDI Aux device name saved by an earlier version is ignored), and the Pier reconnects to that server at start-up. **The page is now INDI-only:** the Alpaca single-device panel and the Driver choice are removed, because Alpaca Switch devices already work on the Switches page; an Alpaca Control Panel setting saved by an earlier version is ignored. The connection line is a single row across the top (a wide Server field, Port, Connect at the right edge), and in the property tabs every property's controls start in the same column, left-aligned beside a fixed-width label column, instead of being pushed to the right. New requirement `EQP-AUX-020` (SRS, SDD 4.1/4.2, RTM), port `AuxServerPanel`, adapter `IndiServerPanel`, tests `TC-EQP-AUX-020`; inline help (`equipment.aux`) and the wiki Equipment article updated.

- **Library no longer treats Seestar frames as precalibrated.** Galileo now downloads the raw FITS from a Seestar, which are not calibrated, so only iTelescope sessions are still treated as delivered-calibrated. Seestar lights are now ingested as uncalibrated (`fitsFileCalibrated=0`), show their real calibration status in the Sessions tree instead of "Precalibrated", and are calibrated with the session's masters before stacking (Stack, photometric stack, `galileo.commands.stack`, `variable_star_photometry`). Already-imported Seestar frames keep their old calibrated flag until reset (`galileo.commands.reset_calibration_test_state`) or re-imported. No help/wiki text referred to the rule.

- **INDI camera downloads are faster.** The INDI client read the socket 64 KB at a time with the operating system's default receive buffer, which caps throughput over Wi-Fi, and it decoded each image (base64 and zlib) while holding the property-cache lock, so every other property read in the app stalled until a large frame had been decoded. The socket now uses a 4 MB receive buffer and 1 MB reads, the decode happens outside the lock, the camera asks the server for only its `CCD1` image property rather than every BLOB the device offers, and the decoded FITS is no longer copied a second time. Measured on this PC: parsing and decoding a 60 MB frame takes about 0.8 s, so on a Raspberry Pi-class client the remaining time is mostly the network and the driver. For a slow link, switching on the driver's compression (INDI `CCD_COMPRESSION`) shrinks the transfer further; Galileo already decompresses `.z` frames. Internal change, no new controls, so no help, wiki or SRS update. Covered by the existing INDI tests; no new test for the speed-up.

- **Polar alignment now starts where the mount points, turns 15° between frames, and lets the mount settle.** Starting at the zenith (and then moving to Dec +70°) moved the scope somewhere its focus differs from the setting you had, and frames taken right after a slew showed trailed stars that would not solve. "Slew from Zenith" is now unticked by default (the zenith start is still there, e.g. for a never-synced mount, and no longer moves on to Dec +70°: it measures at the zenith and turns 15° in RA from there; the Dec 70° working position is gone), the default rotation is 15° instead of 30°, and the run now takes no frame until the mount reports it has stopped (it used to accept "within 1° of the target" even while still decelerating) and then pauses at least 5 s (`POLAR_SETTLE_S`; the Solve screen's Settle value is used if larger; `polar.start`'s `settle_s`, `step_deg` and `slew_from_zenith` defaults changed to match). Tests: `TC-PLT-080` (two new cases; zenith-path cases now ask for it explicitly); help, wiki, SRS `PLT-080` and SDD updated.

- **Downloading images from a remote SFTP device is much faster.** Every file used to open its own SSH connection (key exchange and login, slow on a Raspberry Pi) and every delete opened another, so a night's worth of frames paid that cost hundreds of times. A download batch now keeps one connection per host open and reuses it for all transfers and deletes (closed when the batch ends, and reopened if it drops). Login no longer probes the SSH agent and `~/.ssh` keys when a password or key file is configured, and the SFTP window is widened so the prefetching reader keeps more requests in flight. Internal change to transfer plumbing: no new controls, so no help, wiki or SRS update. Covered by the existing SFTP tests; no new test for the speed-up.

- **The Darks Assistant now actually moves the filter wheel to the chosen filter.** It only wrote the filter's name into the dark frames' headers, so the wheel stayed wherever it was. The wheel is now moved to the chosen filter (and waited for) before the first exposure, skipped when it is already there, and a failed move stops the run with the reason instead of capturing at the wrong position. Test: `TC-CAL-080` (one more case); help updated.

- **The Darks Assistant now shows each dark frame in the Imaging preview.** Its captures used a private imaging service that never announced its frames, so the preview, histogram and statistics stayed on whatever was there before while a run captured darks, and a remote client's live view did not update either. The service is now tied to the Pier like a session's, so each dark is announced on the bus (`FrameCapturedEvent`) and shown when that Pier is the one displayed. Covered by the existing announce test `TC-IMG-150`; the dialog wiring itself has no automated test (no harness opens the assistant). The Flats Assistant has the same gap and was not changed.

- **Auto-Centre no longer fights a running session or guider.** Nothing used to stop an Auto-Centre pass exposing and slewing in the middle of a science frame. A pass is now skipped (and logged) while a session is running on the Pier or the Imaging screen is capturing, and the option is disabled and unticked while PHD2 is guiding, so it can't restart itself when guiding stops. Test: `TC-PLT-100` (one more case); help, wiki, SRS `PLT-100` and SDD updated.

### Fixed

- **Control Panel: connecting to an INDI server no longer makes the window grow across monitors.** The device and property tabs reported the combined width of every tab and the widest property row as the window's minimum size. The tabs now ignore content size, scroll their tab bar, elide long device names, and each property group scrolls inside its tab. No new controls, so no help or wiki change; covered by `TC-EQP-AUX-020`.

- **Live-stacked mosaics are now placed by where each pane is on the sky, and the pane layout keeps its overlap at any declination.** The live mosaic put each pane on a plain grid by its number, so a mount that pointed a few arcminutes off left the panes misaligned, the picture was probably mirrored against the sky, a rotated grid and a camera turned by a meridian flip were ignored, and the overlaps showed hard seams with the latest pane simply winning. Separately, `create_mosaic` added each east-west step straight to RA, so at Dec +60° panes sat half as far apart on the sky as planned (about 55 % overlap instead of 10 %). Now: panes are laid out on the plane tangent to the sky at the mosaic's centre (an RA step is divided by cos(Dec), and RA wraps within 0–360°); the canvas is that plane, north up and east left; with Live Stack on, each pane's first frame is plate-solved in the background with the Pier's solver (aimed at the planned centre) and the pane is moved to its solved position, with the first solution also fixing the canvas's orientation and scale so a flipped or rotated camera lines up; false solves (too far from plan or at the wrong scale) are ignored and a failed or missing solve just leaves the pane at its planned place; overlaps are feathered and their background levels matched; the canvas grows if a solved pane falls outside it and is trimmed to the captured panes at the end. A mosaic built without sky geometry still uses the plain grid. The pane-by-pane solves appear on the Solve screen like any other solve. Tests: `TC-IMG-180` (seven more cases, and the live-stack case now expects the sky orientation), `TC-FRAME-040` (a declination case; the span checks now measure on the sky); inline help unchanged (no controls), wiki, SDD and SRS `IMG-180` updated.

- **Mosaic frames were blurred because the exposure started the moment the mount stopped slewing.** After each re-slew to a new pane Galileo waited only for the mount to report it was no longer slewing, and a mount reports that while it is still settling. A mosaic capture now waits a settle time before the next exposure (new **Mosaic settle time** in Options > Imaging, stored in the database, 5 s by default, 0 to disable). The wait happens only when moving to a new pane, applies to mosaics run from the Imaging screen and from a session's Image block, and Stop cuts it short. Plain session slews are unchanged. Tests: `TC-IMG-180` (one more case) and the `TC-IMG-170` settings round-trip; inline help, wiki and SRS `FRAME-090` updated.

- **Plate Solve's Filter box only ever offered "Current".** The Solve page asked the connected filter wheel for `get_filter_names()` and moved it with `move_to_filter()`, which belong to the filter-wheel controller; the page actually holds the device adapter, which has `filter_names`, `position` and `move_to(slot)`. The lookup failed silently, so the list stayed empty, and choosing a filter would have failed at capture time too. The box now lists the wheel's filters, its first entry reads "Current (*filter in the beam*)" and is refreshed after each solve, and picking another filter moves the wheel to that slot before the exposure. The old test used a mock offering the controller methods, which hid this; `TC-PLT-070` gains a case using an adapter-shaped wheel. Inline help updated; the wiki's overview already said the filter can be set.

- **Imaging Stop button went grey between runs of a looping capture, and a Stop pressed then was ignored.** When one run of a Loop finished, the page re-enabled Capture/Loop and disabled Stop, then restarted the loop on the next event-loop pass; in that gap Stop was dead, and a Stop click there cleared the loop flag too late to cancel the already-queued restart, so capturing carried on. A looping capture now keeps Stop enabled across the restart, and the restart is cancelled if Stop was pressed (or the restart cannot begin, in which case the buttons are released). Manual single and quantity runs still disable Stop when they end, as before. The page has no automated UI test, so this is verified by reading and the existing imaging tests only; no new controls, so no help, wiki or SRS update.

- **Imaging status line flickered between the old and new capture text.** The capture's countdown timer was only stopped when its Pier was still on screen, so a finished capture's last "Frame 25 of 25 — …" kept being repainted over the next capture's status. The timer is now always stopped when a capture ends, and a tick from a capture that is no longer current paints nothing. No help/wiki change (no control changed).
- **Help audit no longer trips on Qt's table corner button or on installed plugins.** `galileo.ui.help.audit` now skips the unnamed select-all corner button Qt puts in a table, and `test_tc_help_060` audits core screens only, because the screens of whichever third-party plugins are installed (VSTarget currently ships no help files) made it fail depending on the machine. Fixes `test_tc_help_040` and `test_tc_help_060`; no user-visible change.

- **`galileo-load-repo` now detects master calibration frames in the source folder and moves them into the repository's `Masters` folder.** It previously skipped masters entirely (the image pass ignores them) and never ran the master pass the Images screen's Load New button does, so masters were left behind in the source folder. They are now moved to `<repo>/Masters` and registered as masters. Load New in the app already did this. No control changed, so no help or wiki update.

- **Library > Images > Regenerate now looks for master calibration frames only in the repository's `Masters` folder.** It used to open the header of every FITS file in the whole repository to find masters, which made Regenerate slow on large libraries (the same scan then ran again for ordinary images). The same narrowing applies to `registerExistingFiles` (`galileo-register-existing`). Masters stored outside `<repo>/Masters` are no longer picked up as masters by Regenerate. No control changed, so no help or wiki update.

- **A mismatched Connect Link certificate and key no longer leaves MobileConnect, WebConnect and NodeConnect with no Options page.** When the stored TLS certificate and its private key did not belong together (a certificate saved by one writer and a key by another, or a database restored against a different secret store), the listener refused to start with `KEY_VALUES_MISMATCH`, each Connect Link plugin logged "stays inert", and Options showed a blank placeholder in place of its page. The certificate store now checks the pair and, when it does not match, logs a warning and generates a new one (paired phones and browsers must pair again, as their pinned fingerprint changed), and creating it is locked so two plugins starting at once cannot interleave the two writes that caused the mismatch. Test: `TC-LINK-010` (one more case).

- **Capture & Solve from a phone showed no picture until the solve finished, and the button said "a plate solve is already running on this Pier" while it ran.** The Master now announces each frame a solve captures (`solve.frame`: version, width, height) the moment it arrives, so the app can show the frame being solved. The message was the button reading its own running solve back as a reason it could not be pressed; the MobileConnect app no longer shows it while the operation it started is the one running. No change to the desktop.

### Added

- **Every Galileo release now rebuilds the plugin ZIPs.** The release workflow gains a `rebuild-plugins` job that, once the installers are published, dispatches the Galileo-Plugins repository's *Build Plugin ZIPs* workflow (which now also accepts a manual run), so each plugin's ZIP and `plugins.json` are rebuilt and re-published alongside the installers. A plugin whose version number did not change has its release asset replaced, not duplicated. One-time setup: add a repo secret `PLUGINS_REPO_TOKEN` (a fine-grained personal access token on Galileo-Plugins with Actions read/write); without it the job fails but the installers are already released. CI only, no change to the app, so no help, wiki or SRS update.

- **`scripts/download_stats.py` reports how many times each installer has been downloaded.** GitHub counts every download of a release asset, and the web site's buttons link straight to those asset URLs, so the count covers the site and the Releases page together. The script lists each release's installers with their counts, then totals per platform (Windows, macOS, Linux x86_64 / aarch64) and overall; `--json` gives the same as data. It uses the `gh` CLI when installed, else the public API (`GITHUB_TOKEN` optional). Counts are cumulative and include re-downloads and bots. Developer tooling only: no change to the app, so no help, wiki or SRS update.

- **Everything the Solve screen shows is now available to a remote client (`CSURF-140`).** `solve.capture` takes the Solver Action (`nothing`, `sync`, or `slew`, which aims at the Pier's current object like the desktop); a new `solve.load` solves a Library frame and slews to where it points (Load & Slew), with `solve.frames` listing recent frames to choose from. The engine now publishes `solve.running`, `solve.accuracy_arcsec`, `solve.points` (each solution's offset from its target, which is the bullseye) and `solve.last`, whose solutions carry the JNow position, the error from the target, scale, rotation, field of view and the focal length, focal ratio and scale ratio they imply against the optics set up, which are the desktop's Solution Coordinates. Before, a remote client got only the raw J2000 position, and on a real Master the Solve screen's state was not published at all. Tests: `TC-CSURF-140` (a third case).

- **Choose the guide star by tapping, and see the whole guide frame (`GUIDE-080`, `CSURF-160`).** The Guider screen's picture has a **Star** / **Full frame** switch. *Star* is PHD2's close-up as before; *Full frame* is the whole guide frame, so every candidate star is visible. Tap (or click) either picture while PHD2 is looping and PHD2 is asked to pick the best star in a 40-pixel box around that point (`find_star` with a region); a drag still pans, and a tap while guiding is ignored so a stray touch cannot drop the star. PHD2's event server does not stream frames, so Galileo asks it to save one (`save_image`), reads the FITS file and deletes it, about every second while the frame view is showing: this works when PHD2 runs on the same computer or a folder Galileo can read, and otherwise the frame view stays empty with the cut-out still available. The Control Surface gains `guiding.select_star` (`x`, `y`, and `space`: `frame` or `cutout`; a cut-out tap is mapped onto the frame from PHD2's star position), `guiding.status` gains `frame` (`ref`, `version`, `available`, size), and the whole frame is served as the picture `guide:<pier>` beside `current:` and `stack:`, which is how MobileConnect shows it. Fetching only continues for ten seconds after a client last asked for the frame. Not tried against a real PHD2: the region form of `find_star` follows PHD2's documentation. Tests: `TC-CSURF-160` (one more case), `TC-GUIDE-080` (one more case).

- **Node health and Restart / Shut down (`CSURF-310`).** The Dashboard now ends in one line showing how the computer is coping: CPU, memory, free disk space on the Galileo data drive, CPU temperature where the computer reports one, and uptime, with a ⚠ or ⛔ when a figure is getting tight (CPU/memory over 85%/95%, under 10/2 GB free, over 75/85 °C). Beside it are **Restart** and **Shut down** buttons that ask first and are refused while a session is running. The Control Surface offers the same to the phone and browser: `node.health` returns the reading and is also published as the observable state `node.health` every 5 s, and `node.restart` / `node.shutdown` are confirm-class (two-step) and refused with a reason during a session. This matters for headless Raspberry Pi observatories, where a full SD card or a hot CPU was invisible until imaging failed. Adds `psutil` as a dependency. The MobileConnect Overview screen shows and uses it (in that repository). Tests: `TC-CSURF-310` (five cases); `TC-OBS-150` now expects the node bar's two buttons.

- **Pre-run summary for a session (`CSURF-185`).** The new `session.estimate` operation takes a saved template (and a target for its placeholder) and returns what the ASIAIR Autorun shows before you press start: estimated duration and finish time, storage needed against free space, when the target crosses the meridian, and a warning for each limit the session would run into: dawn, the target's horizon limit, a meridian crossing with no Meridian Flip block, or too little disk. Figures the Master cannot work out (no site, no camera sensor size) are left out rather than guessed. The estimate uses planning times per block, so it is a guide, not a stopwatch. The phone and browser screens that display it are not built yet. No change to the desktop.

- **The frame being solved, and the circle, cross and vector to draw on it (`CSURF-145`, `PREV-070`).** The latest frame captured for plate solving or polar alignment is now a preview source, `solve:<pier>`, and `polar.state` gains `frame`: that frame's version and size, and where the axis point (circle) and the celestial pole (cross) fall in its pixels, with the arcminutes per pixel. A client can therefore show the frame refreshing in a loop with the circle, cross and the vector between them over it, which is what someone turning the knobs needs; before, only the error figures were available. `PolarAlignWorkflow` reports the geometry (`TargetGeometry`; the existing `target_offset_arcmin` is unchanged) and `SolveWorkflow` has an `on_frame` hook. Tests: `TC-CSURF-145` (the existing case extended, and one for the frame source).
- **Full polar alignment from the phone, tablet and browser (`CSURF-145`).** The Control Surface now offers `polar.start`, `polar.stop` and `polar.status`, which run the Solve screen's own polar-alignment routine on the Pier: three plate solves at different RA positions, then live adjustment while the altitude and azimuth knobs are turned. Until now remote clients could not do polar alignment at all, although the desktop could. The live picture (phase, step, the error split into altitude and azimuth with the instruction in words, a good/fair/poor band using the desktop's 1′/5′ thresholds, a trend of recent totals, and where the pole lies against the axis in the latest frame) is published as the observable state `polar.state` on every solve, so a client at the mount sees each turn of a knob without polling; `polar.status` returns the same picture, and it stays readable after the run. The routine runs until `polar.stop`. A Pier runs one at a time, and none during a session or a plate solve (and a plate solve is refused while it runs); no camera, no mount, no Observatory latitude/longitude or an unset solver are refused with a reason before anything moves. The MobileConnect iOS Solve screen and WebConnect's new **Polar** tab use it (in their own repositories). Tests: `TC-CSURF-145` (two cases).

### Changed

- **The Capture button on the Imaging screen is now sized to its label** (with Loop and Stop beside it) instead of stretching across the whole settings panel.
- **Alerts while the phone app is closed: documented as the Master's e-mail/text channels.** `MCON-340`, PSD D4, the MobileConnect SDD, the Notification settings help and the wiki Options page now state that the app shows alerts only while connected, and that e-mail/text alerts configured on the Master are the supported way to be told about a finished session, lost guiding or a safety stop overnight. No relay or external push service is added. Documentation only; no code changed.
- The Connect Link gateway's refusal for an operation sent without the Pier's control lease now reads "you do not have control of this Pier (X does)" / "take control of this Pier first", since apps show it as is. Internal names are unchanged.
- **Star Atlas sky survey is now Mellinger's Milky Way mosaic, and fetches nothing when zoomed in past 3°.** The Digitized Sky Survey colour tiles were a patchwork (each photographic plate has its own background level and some have no blue), so the sky looked patchy and discontiguous; the Quest atlas spike had already rejected them for that reason. Axel Mellinger's all-sky mosaic is one continuous picture, tiles stop at order 4 (it has no finer detail), and a view narrower than a 3° field draws what is already held instead of fetching, so panning deep in is never held up by the network. The Master serves the same tiles, so MobileConnect gets both changes. Cache moves to `sky_survey/MellingerRGB`; old DSS tiles can be deleted.

### Added

- **Power and dew controls on the Imaging screen: "Show on imaging" and a More menu (`EQP-SW-150`).** On Equipment > Switches, each port, dew heater or adjustable output of a power box such as the WandererBox now has a **Show on imaging** tick (kept per Pier). The Imaging screen's new **More** button lists the ticked channels, each with an On/Off button and, for a dew heater, a 0–100 % box with **Set**; it re-reads the device every time it opens, says why when nothing is connected or ticked, and asks before switching a channel off while a session runs. For the web and mobile apps the Control Surface gains `switch.panel`, `switch.set` (on/off and dew percentage, leased) and `imaging.controls`, which returns the ticked channels together with the flat panel's state so a phone can show switches and flat-panel controls on the one Imaging screen. New module `galileo.imaging_switches`. SRS `EQP-SW-150`, `MCON-420`/`MCON-430` and `WCON-430` amended, SDD, RTM, inline help and wiki updated. **Not done here:** the web and mobile screens themselves live in the WebConnect/MobileConnect plugins and the MobileConnect app, which still have to draw `imaging.controls`.

- **Phone alerts through ntfy, with e-mail as the backup (`NOTIF-020`, `NOTIF-050`).** Carrier e-mail-to-SMS gateways, the only "text" route Galileo had, have been shut down (AT&T, probably T-Mobile) or are being retired (Verizon, by March 2027), so overnight alerts silently went nowhere. Options > Notifications gains a **Phone alerts (ntfy)** section: install the free ntfy app, press **Generate topic**, subscribe to it, and finished sessions, errors and safety aborts arrive as phone notifications (safety aborts urgent). It is one HTTPS request from the Master, with no account, relay or inbound port, so PSD D4 still holds. E-mail now acts as the backup and is sent only when the push fails (switchable), per-event switches work for ntfy as for the other channels, and an optional access token for a private server is kept in the OS credential store. The SMS gateway section stays but is flagged as unreliable. New: `NtfyChannel`, `valid_ntfy_topic`, `get_/set_ntfy_token`, `generate_ntfy_topic`; `build_channels` takes `ntfy_token`; `run_test_send` supports `"ntfy"`. SRS `NOTIF-020`/`NOTIF-050`, SDD 4.19, the MobileConnect notes, inline help and the wiki Options page updated.

- **`docs/App Recommended Features.md`: draft gap analysis for the mobile apps.** Compares the planned MobileConnect feature set with a competitive review of widely available apps, and lists recommended additions (power/dew control, demo mode, guiding depth, node health and others) plus decisions needed. Documentation for review/edit only; no requirements changed yet.
- **A phone or tablet can run a live stack and see it.** `imaging.capture` takes `live_stack` (a series of three or more frames is registered and averaged, as the Imaging screen does). `imaging.status` now reports the exposure under way (`seconds`, `elapsed`) and, while stacking, the stack (`frames`, `requested`, `total_exposure_s`, `method`, `rejected`). The stack is served as its own picture, `stack:<pier>`, beside `current:<pier>`, which is now always the latest single exposure (before, a live stack replaced it). `ImagingService` keeps `last_sub_frame` and `exposure_started_at` for this. No desktop screen changes.
- **Real sky behind the Star Atlas.** The map now draws Digitized Sky Survey colour photographs behind the stars, from tiles at a resolution matching the zoom, so the Milky Way, nebulae and galaxies are simply there and sharpen as you zoom in. A **Sky survey** checkbox turns it off. The images are STScI's, so nothing ships with Galileo: tiles are downloaded as they come into view, cached on your computer (up to 1 GB) and credited on the map, and the map works as before while they're unavailable. The MobileConnect plugin's design documents gain `MCON-690`, which serves the same tiles to the app.
- **Landscape ground on the Star Atlas.** Everything below 0° altitude is now hidden behind an opaque, made-up landscape receding to the horizon, rather than a nearly opaque flat shade, so stars and survey photographs no longer show through. It lightens with a daylight sky and the **Ground** option still turns it off. The horizon profile's fill stays transparent red, from 0° upward.

- **MobileConnect plugin design note** (`docs/plugins/mobileconnect/SDD.md` 5.2): records how the first draft in `Galileo-Plugins/mobileconnect` differs from the design, because Connect Link's route table matches exact paths and its stream has no connection hook. Documentation only; nothing in Galileo itself changed.

- **Polar alignment: "Slew from Zenith" option.** Checked (default, as before) the run slews to the zenith, solves to confirm the mount, then moves to the measuring position. Unchecked, it solves where the mount already points (syncing the mount to the solution if it is off), then turns in RA from there for the second and third positions, skipping only the zenith slew (this takes one extra check frame before the three measuring frames, and nothing moves the mount first, so it must already point at a clear field away from the pole and meridian). Added as `PolarAlignSettings.slew_from_zenith`, a checkbox on the Solve > Polar Alignment tab, inline help and the wiki.

- **WebConnect: the page marks itself stale and disables operations when its live stream drops (`WCON-780`).** Done in the plugin (`Galileo-Plugins/webconnect`); the checklist now records it. Emergency operations stay attemptable. Documentation only in this repository.

- **Catalog image pack now includes the large click-to-enlarge images, and the enlarged view reads from the local cache.** Clicking a thumbnail on Planning > Targets or What's Up Tonight fetched a 640 px image live from the CDS survey service, so it failed whenever that service was down. `scripts/build_thumbnail_pack.py` (via `build_pack(sizes=...)`) now downloads each object at both 150 px and 640 px (`--no-large` for tiles only; expect a much bigger ZIP), and Options > Planning > Download Catalog Images unpacks both into the thumbnail cache. `_show_full_image` now checks the cache first and only contacts the survey service when the image is missing, saying so (and pointing at Download Catalog Images) if that fails. Existing packs still install; they just lack the large images until rebuilt and re-uploaded.

### Changed

- **The Library now defaults to `~/REPOSITORY` and `~/REPOSITORY.incoming`.** Previously the repository and incoming (source) folders were empty until set under Options > Library, so Auto-Save to Library did nothing on a fresh install. When either is unset, `galileo.library.config.load_config` now fills in `REPOSITORY` / `REPOSITORY.incoming` in the user's home folder and creates them; a folder you have chosen is never overridden. Applies to database-backed settings only, not `--config` files. Updated Options > Library help and the wiki.

- **Connect plugins checklist: stale Connect Link lines corrected, NodeConnect confirmed built.** Two lines still said Options > Outreach was not built (it was, 2026-11-02); they now say only a guest surface and a wiki article remain. NodeConnect's transfer, UI and packaging were checked and are already complete (79 tests pass, the ZIP builds); the remaining items are the Raspberry Pi 5 measurement, a real two-machine run and the release, which waits for your say-so. Documentation only; no behaviour changed.

- **The startup registration ping now reports the real app version.** `galileo/registration.py` sent a fixed `"GA02.0"` handshake that never changed between releases; it is now `"GA" + galileo.__version__` (e.g. `GA0.9.05alpha`), so bumping the version in `galileo/__init__.py` updates the ping with nothing extra to remember. The server at `www.gordtulloch.com:5050` must accept this format (it is the same one-line, no-response TCP handshake). No UI/help/wiki change.

### Fixed

- **Code-quality CI.** Five `ruff` findings had failed the `static-analysis` job on every push, so the steps after it weren't running, and one of those would have failed too: `map_standard` in `galileo/adapters/indi/switch_map.py` was over the complexity limit. The findings are fixed, and that function is split into one method per part of the panel. An internal refactor with no visible effect.

- **Connect Link discovery on a Mac.** If mDNS can't bind every network interface ("address in use", seen on a Mac), Galileo now advertises on the default one rather than not at all, so apps and other nodes can still find it without typing its address. Computers where binding all of them works behave as before.

- **macOS: FITS files opened in GIMP instead of Tenmon.** A viewer set in Options > Library that was a `.app` bundle (a folder) could not be executed, so Galileo silently fell back to the system default for `.fits`, which was GIMP. New `galileo/ui/library/viewer.py` (used by Library > Images and Sessions) launches `.app` viewers with `open -a`, and with no viewer configured prefers an installed Tenmon over the system default. Windows/Linux behaviour is unchanged. Help updated.

- **What's Up Tonight's day/night band was centred on dawn instead of mid-night.** The band started at the *system clock's* local noon, so whenever the computer's timezone differed from the observatory's longitude (a Pi left on UTC, a laptop travelling) the dark period slid toward one end. It now runs from the site's own solar noon to the next, computed from the Observatory's longitude, so solar midnight is always mid-band; the hour labels are placed by time (even clock hours) since the window no longer starts on the hour. Hour labels are still in the system clock's time. No help/wiki change (behaviour now matches what they describe).

- **Star Atlas showed no stars on a fresh Linux install (catalogs listed, sky empty).** The star catalog (Yale Bright Star Catalogue, ~9,100 stars) was only ever downloaded from VizieR on first run; if that server was unreachable or slow the atlas fell back to ~60 named stars and never cached anything. A copy of the catalog now ships with the app (`galileo/planning/data/bright_star_catalog.json`, included in the PyInstaller/AppImage builds) and is used when there is no cache, so stars appear offline on every OS. VizieR is only a last resort. No UI/help/wiki change.

# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). This project does not yet follow Semantic Versioning releases (see `README.md` status) — entries accumulate under `[Unreleased]` until the first tagged release.

## [Unreleased]

### Added

- `CLAUDE.md` guidance file documenting the codebase's architecture, requirement-traceability chain, test conventions, and module map for AI-assisted development.
- `requirements.txt` / `requirements-dev.txt`, mirroring `pyproject.toml`'s dependency groups for environments not using `pip install -e .`.
- `run.sh` / `run.ps1` launch scripts that locate the project's `.venv` (or fall back to `python`/`python3` on `PATH`) and start the app from the repository root regardless of caller working directory.
- Startup splash screen (`galileo/app.py`) showing `assets/images/logo.png` with its transparent background preserved, held on screen for 5 seconds before the main window appears.
- N.I.N.A.-style application shell (`galileo/ui/app_window.py`, `galileo/ui/theme.py`, `galileo/ui/icons.py`):
  - Dark/light QSS themes (palette sampled from N.I.N.A.'s own default theme) with a customizable accent color.
  - A primary icon sidebar (Equipment, Sky Atlas, Framing, Flat Wizard, Sequence, Imaging, Scheduler, Library, Variable Stars, Options), each icon drawn at runtime via `QPainter` rather than shipped as image assets.
  - A Power (quit) button plus three small utility buttons at the bottom of the sidebar: theme toggle (live icon/color re-render), online manual link, and an About dialog.
  - A top bar with Observatory and Pier selectors (see Persistence below).
  - A status bar.
- Equipment section: a context-sensitive secondary sidebar for device categories (Camera, Mount, Filter Wheel, Focuser, Rotator, Guider, Switch, Flat Panel, Weather, Dome, Safety Monitor), each with a Driver (Alpaca/INDI) / Server / Port / Connect panel that performs a real device scan, plus a live scrolling log pane (see Logging below).

- `.local` mDNS hostname resolution (`resolve_mdns_host`, via the `zeroconf` package) for both the INDI and Alpaca adapters, so hostnames like a Seestar's `seestar.local` Alpaca bridge resolve correctly on Windows (which does not resolve `.local` names without Bonjour installed) — ported from the approach proven in the author's VSTarget project.
- A `Port` field (default 32323 for Alpaca, matching the project's own Seestar S30/S30 Pro reference hardware; 7624 for INDI) alongside Driver/Server on each Equipment device page, editable per-device rather than a hardcoded guess.
- Persisted Observatory/Pier settings:
  - `ObservatoryRecord` (Name, Latitude, Longitude, Timezone, Physical Address, Owner) and `PierRecord` (Name, Observatory foreign key) Peewee models (`galileo/library/models/observatory.py`), added to the shared application database.
  - Manager functions `list_observatories`/`create_observatory`/`list_piers`/`create_pier` (`galileo/observatory.py`).
  - Top-bar "New Observatory…" / "New Pier…" creation dialogs; Pier's Observatory is set automatically from whichever Observatory is currently selected.
- Persisted per-Pier device configuration: each Equipment device-category page now has a Save button (bottom right, above the log pane) that stores its Driver/Server/Port and the device picked from the scan results against the currently selected Observatory/Pier (`DeviceConfigRecord`, `galileo/library/models/device_config.py`; `get_device_config`/`save_device_config` in `galileo/observatory.py`). Switching Pier (or Observatory) reloads every device page's fields from that Pier's saved settings. On application startup, if a saved Observatory/Pier exists it is loaded automatically, and if that Pier has a saved camera device, Galileo attempts to connect to it immediately rather than leaving the user to reconnect by hand.
- Camera page now supports any number of additional, independently configured non-guide cameras sharing the same Driver/Server/Port connection as the primary imaging camera — e.g. a Seestar S30 Pro's wide-field camera, exposed as a second device on the same Alpaca bridge. A "+" button next to the "Camera" heading appends a new camera panel (each with its own Device/Pixel Size/Sensor Width/Sensor Height/Sensor Name fields and a Remove button, except the always-present, non-removable Primary panel); the panel list sits in a scroll area since it has no fixed upper bound.   - A process-wide in-memory tail buffer (`get_recent_log_lines`) feeds a live, auto-scrolling, 10-line-tall (scrollable to ~300 lines of history) log pane on every Equipment device screen, refreshed on a shared timer.

- This `CHANGELOG.md`.
- New SRS requirement `EQP-FOC-030`: `FocuserController` now clamps every absolute/relative move to the connected focuser's reported `0..MaxStep` range before issuing it, rather than passing an out-of-range command straight to the device. This applies uniformly across both transports — a real ASCOM/Alpaca `IFocuserV3` driver is documented to hard-stop at its limits itself, but INDI focuser drivers give no equivalent guarantee, and even where hardware does self-protect, a silently-clamped move would leave the controller's cached position out of sync with the device. A clamp is logged at WARNING when it changes the requested position. Matching `docs/SRS.md`, `docs/SDD.md` (§4.1), and `docs/RTM.md` updates, plus `TC-EQP-FOC-030` tests in `tests/test_eqp.py`.
- `AlpacaFocuserAdapter` (`galileo/adapters/alpaca.py`) now talks to a real Alpaca focuser instead of behaving like a stub: `connect()` reads `MaxStep`, `MaxIncrement`, and `Absolute` from the live device (feeding the new clamp above and correctly handling a relative-only focuser's `Move` semantics), `move_to()`/`move_by()` read back `Position`/`IsMoving` after issuing a move instead of assuming the requested value was reached, and `get_status()` refreshes the same cached fields on every poll. Needed to test against physical Seestar hardware rather than only the INDI simulator path.
- Mount page rebuilt as a bespoke live status/control screen (`AppWindow._build_mount_page`, `galileo/ui/app_window.py`), matching the field set of the reference N.I.N.A. Mount screen (`assets/samples/mount.png`): a status panel (Name/Description/Driver info/version, Site latitude/longitude/elevation, Sidereal time, Epoch, time-to-meridian, Right Ascension/Declination, Altitude/Azimuth, Side of Pier, Tracking — `EQP-MNT-020`), Manual Coordinates (RA/Dec and Alt/Az target entry with independent Slew actions), and Manual control (tracking-rate selection, Primary/Secondary jog rate, an N/S/E/W/Stop jog pad, Home, a Park button that toggles to Unpark once parked, and client-side Primary/Secondary-reversed jog toggles — `EQP-MNT-010`), refreshed on the same 2-second polling pattern as the Focuser page. `AlpacaMountAdapter.get_status()` reads the standard ASCOM `ITelescopeV3` properties this needs (previously only `ra`/`dec`/`altitude`/`azimuth`/`pier_side`/`is_tracking`/`is_slewing` were tracked, with no live read at all), plus new `slew_to_altaz()`, `find_home()`, `move_axis()` (continuous jog), and `set_tracking_rate_mode()` methods; `IndiMountAdapter` gained the same method surface, limited by this codebase's INDI adapter still being a lightweight stub (same caveat as the Camera/Focuser INDI adapters).
- Filter Wheel page rebuilt the same way (`AppWindow._build_filter_wheel_page`), matching the reference N.I.N.A. Filter Wheel screen (`assets/samples/wheel.png`): a status panel (Name/Description/Driver info/version — `EQP-FW-010`), a current-filter selector with an explicit Change action, and a Filters list showing every filter the wheel reports with the current one highlighted (`EQP-FW-020`). `AlpacaFWAdapter` — previously a bare stub with no `connect()` override or status read at all — now reads `Names`/`Position` from the live device on connect and via a new `get_status()` (also reading `Name`/`Description`/`DriverInfo`/`DriverVersion`); `IndiFWAdapter` gained a matching `get_status()`, limited by this codebase's INDI adapter still being a lightweight stub.
- Imaging page (`AppWindow._build_imaging_page`, `galileo/ui/app_window.py`) rebuilt from its "not implemented yet" placeholder into a live capture screen (IMG-010 … IMG-100), modeled on the classic CCD-capture-tool split of settings-on-the-left / preview-and-log-on-the-right (`assets/samples/ccd.png`) — Capture Settings (Exposure, Type, Filter) and View controls (Star overlay, Zoom, Reset View) plus a Statistics readout (Mean/Median/Min/Max/Star count/HFR) on the left; a pan/zoomable `QGraphicsView` auto-stretch preview, a log-scale histogram bar chart, an exposure countdown/progress bar, and the shared log pane on the right. A manual Capture button (IMG-070) runs the async expose/download call on a background `QThread` (new `_CaptureThread`) rather than blocking the UI thread for the whole exposure — unlike the rest of this window, which still calls device adapters with a blocking `asyncio.run()` directly on the UI thread since those calls (scan/connect/status) are quick — so the countdown label (IMG-090) keeps ticking during a multi-second/minute exposure. A Save Frame… action (IMG-100) saves the currently displayed frame independently of any sequence. `ImagingService.capture_and_preview()`/`capture_single()` (`galileo/ui/imaging.py`) gained a `frame_type` parameter (default `"Light"`, preserving existing test behavior) so the UI's Type selector actually reaches the camera backend.
- Top-bar Camera selector: a third combo box (after Observatory and Pier) appears when the selected Pier has more than one configured camera (e.g. a Seestar S30 Pro's Primary + Wide Angle cameras) and the Imaging screen is active — with a single camera there's nothing to choose, so it stays hidden everywhere else. Populated from `list_device_config_slots`/`get_device_config` (`galileo/observatory.py`), labeled "Primary Camera"/"Camera N" plus the saved device name; refreshed whenever the Pier changes or the Imaging section is selected (new `AppWindow._refresh_camera_combo`, `_on_camera_activated`, `_camera_slot_label`, `_camera_backend_key_for_slot`). The Imaging page's manual capture and Save Frame actions now resolve the camera from whichever slot is currently selected (`AppWindow._active_camera_slot`) instead of always using the Primary camera.
- New SRS requirement `SKY-100`: the Sky Atlas page's object-name search is now wired to the former Obsy project's target-selection code (`SkyAtlas.search_online()`, `galileo/planning/sky_atlas.py`, ADR-005) — a live Simbad lookup, ported from Obsy's `target_query` view, is tried first, falling back to the existing offline catalog `search()` only when Simbad is unreachable, times out, or finds nothing (so `SKY-070`/`NFR-OFFLINE-010`'s no-internet guarantee is unaffected — that guarantee only ever covered the fallback path). Several API details needed adapting rather than a literal port, all confirmed against the live Simbad service: the currently-installed astroquery already returns `ra`/`dec` as decimal degrees (Obsy's `SkyCoord` sexagesimal-string parse is for an older response format) and lowercase `main_id`/`otype` columns (Obsy's `MAIN_ID`/`OTYPE_main`); Obsy's unconditional `wildcard=True` now finds nothing for a plain name like `"M31"` against this Simbad backend (it only matches Simbad's own identifier spacing, e.g. `"M31*"`/`"M 31"`), so wildcard mode is now only used when the query itself contains a `*`/`?`, otherwise Simbad's normal alias-resolving lookup is used; and requesting the `V`/`FLUX_V` magnitude field on the same query as the name/type match — as both Obsy and this port's first pass did — silently drops *any* object with no cataloged V magnitude, which is most nebulae and clusters (a plain search for M42, M45, or "Orion Nebula" returned nothing at all, with no error, while M31 worked — the exact "only M31 ever comes back" symptom reported after the first pass), so magnitude is now a separate, best-effort per-object lookup capped to searches with 10 or fewer matches (avoiding an unbounded number of extra requests for a broad wildcard search) rather than part of the primary query. Also matched `AlpacaAdapter`/`SimbadClient`'s existing per-call `Simbad()` instance pattern rather than Obsy's global-singleton mutation.
- Sky Atlas search results now show a details panel (`AppWindow._build_sky_atlas_page`) when a result is selected — Type, Magnitude, Constellation (computed via `astropy.coordinates.get_constellation`, ported from Obsy's `target_query` use of the same, new `galileo.planning.sky_atlas.constellation_for()`), Right Ascension, and Declination, plus a downloaded sky-survey cutout image — matching what Obsy's target search actually populated for a Simbad hit (its `target_query` view together with `Target.save()`'s DSS-cutout fetch, `targets/models.py`). `SkyAtlas._fetch_thumbnail()` (SKY-080) was a stub returning `b""`; it's now a real implementation ported from that `Target.save()` logic — a 15×15 arcmin FITS cutout from STScI's DSS search service, min/max-normalized and resized to a 150×150 JPEG via the new `Pillow` dependency, run off the UI thread via `asyncio.to_thread` (`_fetch_dss_thumbnail_sync`) and degrading to `b""` on any failure so a missing image never blocks the rest of the details panel. The search box and result-selection handler now also show explicit status-bar feedback ("Searching…" / "Fetching sky-survey image for …" / "No matching objects." / "Sky Atlas search failed — see log.") and a wait cursor during each blocking network call, since a search or image fetch that appeared to do nothing for several seconds (no progress indicator, no on-screen message either way) was easy to mistake for a hang or a swallowed error.
- New dependency `Pillow>=10.0` (`pyproject.toml`, `requirements.txt`) for the DSS-cutout-to-JPEG thumbnail conversion above.
- Real INDI device support, replacing the previous stub adapters that never touched the network (which is why scanning a StellarMate reported "No INDI camera devices found"):
  - `galileo/adapters/indi_client.py`, a native Python client for the INDI XML wire protocol. It is used instead of `pyindi-client` because that package wraps the libindi C++ library, which has no Windows port and so cannot be installed on Windows; a pure-Python client works the same on Windows, macOS, Linux and Raspberry Pi with no extra dependency. It keeps one shared, reference-counted connection per server with a live property cache, and works from the UI's short-lived `asyncio.run` loops.
  - Camera (exposure with gain/binning/frame type, FITS download into a numpy array, cooling, sensor info, capabilities), Mount (slew, sync, park, tracking, jog, live status), Filter Wheel, Focuser (absolute and relative moves, limits, temperature), Rotator, Dome, Flat Panel and Weather adapters now drive the standard INDI properties of a real device.
  - A scan lists only the devices whose driver matches the category (via each driver's `DRIVER_INTERFACE`); Safety Monitor has no INDI interface, so it lists nothing.
  - Disconnecting leaves a device connected if another client (e.g. Ekos/KStars) had already connected it.
  - Driver warnings/errors appear in the log pane; routine driver chatter is kept out of it.
- `tests/indi_fake_server.py` (a loopback INDI server speaking the real wire protocol) and `tests/test_indi_adapter.py` (17 tests) covering discovery, connect/disconnect, exposure download, mount/filter-wheel/focuser control and error paths end to end.

### Changed

- The on-screen log pane on every Equipment device-category screen now shows INFO level and above only, while the on-disk datestamped log file keeps every DEBUG-level record — `galileo/diagnostics.py`'s in-memory tail buffer handler (feeding `get_recent_log_lines`) now has its own `INFO` level, separate from the root logger's `DEBUG` level that still gates what reaches the file handler. Previously the on-screen pane showed DEBUG noise not meant for a user glancing at the app's status.
- Device interactions (connect/disconnect, move/slew/park, exposure start/abort, temperature/tracking/switch/brightness/shutter/cover sets, etc.) are now logged at INFO, so they show up in the on-screen log pane instead of being silent. `AlpacaAdapter._put()` — the single HTTP-write choke point every Alpaca command already funnels through — now logs the attribute and parameters it sends; INDI adapters gained an equivalent `IndiAdapter._log_interaction()` helper, called from every write/action method across all device categories (no shared dispatch point exists there, since the INDI transport is still a lightweight stub). Periodic reads (Alpaca `_get`, `poll()` on Weather/Safety Monitor) are deliberately left unlogged at INFO to avoid flooding the pane during status polling (e.g. the Focuser page's 2-second status refresh).
- Focuser page's Move button now logs the full move transaction at INFO — "move requested" when clicked, the adapter's own device-interaction/move-result line, and (in `AppWindow`, shared across both backends) edge-triggered "started moving"/"stopped moving"/"settling at"/"finished settling" lines derived from Is Moving/Is Settling *changes* between status polls, not logged every poll (which would flood the pane during a multi-second move). `IndiFocuserAdapter` (previously always reporting `is_moving`/`is_settling` as `False`, since it has no real hardware to reflect) now simulates a realistic non-blocking moving→settling→idle timeline from wall-clock time windows set by `move_to()`, so the Focuser page's status fields — and the new logging — actually exercise this behavior without real hardware. Against real Alpaca hardware, Is Moving/Is Settling already reflect the device's own real state (`get_status()` queries it live), so no simulation was needed there.
- `galileo/app.py` now calls `galileo.library.database.init_db()` on startup — previously only the CLI tools (`galileo-load-repo`, etc.) initialized the database, so the GUI never persisted anything at all.
- Alpaca and INDI adapters accept a combined `host:port` address (in addition to separate `host`/`port` arguments), matching the convention `alpyca` and the Alpaca Management API use.
- `README.md` rewritten to describe the application's actual current state (working shell, Equipment scanning, Observatory/Pier persistence, Sky Atlas/Framing panels, logging service, versus still-placeholder Sequencer/Imaging/Scheduler/Library/Variable Stars/Flat Wizard/Options screens) instead of the original "pre-alpha, no code written yet" description, and added a "Getting Started" section.
- `docs/PSD.md`, `docs/SRS.md`, `docs/SDD.md`, `docs/RTM.md` updated for the logging service's actual behavior and requirement/coverage counts (235 SRS requirements, up from 233; 249 RTM-covered requirements, up from 247).
- Fixed `pyproject.toml`: the `dependencies` array was nested under `[project.scripts]` instead of `[project]` due to TOML table-ordering (a key/value pair belongs to the nearest preceding table header), so `pip install` was silently never installing the project's own declared dependencies.
- `CLAUDE.md` now requires a `CHANGELOG.md` entry alongside every future change to this repository.
- `README.md`'s Tech Stack section now addresses the GIL directly (UI responsiveness is Qt's native C++ rendering, not an interpreter question; CPU-bound work runs off the main thread in a `ProcessPoolExecutor`), matching the rationale already in `docs/SDD.md` §2.1's accepted-risks table.
- `.local` hostname resolution (`resolve_mdns_host_sync`, shared by the INDI and Alpaca adapters) now asks the operating system first and only falls back to `zeroconf`. Windows resolves `.local` names natively on current versions, and `zeroconf`'s compiled extension can be blocked by a Windows Application Control policy, which made every `.local` address (e.g. `Stellarmate.local`) unusable on such a machine. The fallback's error message now includes the real import failure instead of always claiming the package was missing.
- `docs/SDD.md` (§2 rationale, §2.3 concurrency table, §4.2), `CLAUDE.md`, `pyproject.toml` and `requirements.txt` now describe the native INDI client rather than `pyindi-client`, so nobody adds it as a dependency expecting it to be needed (it can't be installed on Windows).

### Fixed

- 18 failing tests across the suite, including:
  - `AlpacaFlatPanelAdapter` was missing entirely, so no Alpaca adapter existed for the `FlatPanel` device category.
  - `DevicePool.get_properties()` looked up devices by category key instead of by device name.
  - `ConnectionMonitor.check_once()` discarded an async `get_properties()` result without awaiting it, defeating its own timeout detection.
  - `GuidingService.start_guiding()` skipped the guiding-state confirmation wait whenever a guider client was injected (i.e. always in practice).
  - `Event` subclasses' declared fields (`timestamp`, `recoverable`, `explanation`, etc.) never actually reflected the value passed at construction.
  - A session-scoped pytest fixture was writing a synthetic sky-atlas catalog into the real per-user AppData directory instead of an isolated tmp path, leaking stale data across unrelated runs.
  - A Windows-incompatible manual `asyncio.get_event_loop()` call in a test, a `MagicMock(name=...)` misuse (the constructor kwarg sets the mock's repr, not a `.name` attribute), and a profile export/import test that used the same directory for both internal storage and the "exported" copy.
- The Camera/Equipment "Connect" action always reporting "No devices found," reachable server or not, because `AlpacaAdapter.list_available_devices()` was a hardcoded stub that never made a network call.
- The Camera/Equipment "Connect" action failing with "connection actively refused" against real devices — root-caused to two compounding issues: Windows not resolving `.local` mDNS hostnames without Bonjour, and the UI silently defaulting to the wrong Alpaca port for non-standard servers (now both fixed above).
- Camera page: a camera panel added via "+" *after* a scan had already run (e.g. scanning, seeing a second detected camera, then clicking "+" for it) had an empty, unselectable Device list — the scan only populated the panels that existed at scan time. New panels now seed their Device list from the most recent scan's results.
- The application printing `QFont::setPointSize: Point size <= 0 (-1), must be greater than 0` to the console — traced to every Equipment device screen's log pane: `QFontDatabase.systemFont(FixedFont)` can return a font defined only by pixel size (`pointSize() == -1`) on some Windows configurations, and Qt's built-in Ctrl+Wheel text-zoom on `QPlainTextEdit` does arithmetic on that `pointSize()`, occasionally landing on a non-positive value and calling `QFont::setPointSize()` with it. A read-only log tail has no legitimate use for interactive font zoom, so the new `_LogPane` (`galileo/ui/app_window.py`) simply ignores Ctrl+Wheel events (regular scrolling is unaffected) rather than trying to keep the underlying font's point size valid through Qt's stylesheet cascade.
- `AlpacaAdapter._get()`/`_put()` (`galileo/adapters/alpaca.py`, base class for every Alpaca device category) discarded a real device's Alpaca JSON error envelope entirely — `_put()` didn't even read the response body, so a driver rejecting a command (nonzero `ErrorNumber`, e.g. a focuser move outside its range) failed silently instead of raising. Both now parse the envelope and raise `DevicePropertyError` on a nonzero `ErrorNumber`; `_get()` also now calls `raise_for_status()` on the HTTP response, matching the pattern already used by `get_configured_devices()`.
- Mount page always reporting "No Alpaca Mount devices found," even against a live Alpaca server exposing a mount (e.g. a Seestar's integrated mount) — `list_available_devices()` filtered the Management API's `DeviceType` field by Galileo's internal `DeviceCategory.MOUNT` value (`"Mount"`), but the ASCOM Alpaca spec calls this device type `"Telescope"` on the wire; there is no Alpaca `"Mount"` type. The same mismatch meant every actual mount command (`base_url`, used by slew/park/tracking/sync) was being sent to `/api/v1/mount/...` instead of `/api/v1/telescope/...`, so a real Alpaca mount would also have failed to connect/control even once discovered. Added an internal `DeviceCategory` → Alpaca wire-type map (`_ALPACA_WIRE_TYPE` in `galileo/adapters/alpaca.py`) used by both discovery filtering and URL construction, also correcting the same latent mismatch for Weather Station (Alpaca `ObservingConditions`) and Flat Panel (Alpaca `CoverCalibrator`).
- Mount page's Save button and Log pane unreachable on a screen/window not tall enough for the page's full content — unlike the Focuser/Camera pages, the Mount page's status table plus Manual Coordinates/control panels were packed directly into one fixed `QVBoxLayout` with no scroll area, so anything past the visible viewport was simply clipped with no way to reach it. `AppWindow._build_mount_page` (`galileo/ui/app_window.py`) now matches the Focuser/Camera pages' own layout convention: only the status/Manual Coordinates/Manual control region scrolls (in its own `QScrollArea`), while the connection row stays fixed at the top and Settings/Save/Log stay fixed at the bottom, so the log tail is always visible without scrolling the whole page. Also shrank the N/S/E/W jog buttons (64px → 44px) and tightened section spacing so the scrollable region is shorter in the common case.
- `AlpacaAdapter._get()` (`galileo/adapters/alpaca.py`) treated a driver reporting ASCOM's standard "not implemented" error (`ErrorNumber=0x400`, e.g. a real Seestar's `SiteElevation`/`SideOfPier`, which it doesn't implement) as a fault, raising `DevicePropertyError`.

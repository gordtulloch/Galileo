# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). This project does not yet follow Semantic Versioning releases (see `README.md` status) — entries accumulate under `[Unreleased]` until the first tagged release.

**Older entries are archived in [`docs/changelog/`](docs/changelog/)**, one file per rotation (e.g. [`2026-09.md`](docs/changelog/2026-09.md)), so this file stays short enough to read in full. Search the archives (`grep -rn <term> docs/changelog/`) rather than reading them end to end. When this file grows past roughly 40 KB, move everything under `[Unreleased]` to the top of the current month's archive file (creating `docs/changelog/YYYY-MM.md` if needed) and leave `[Unreleased]` empty again.

## [Unreleased]

### Fixed

- **INDI mounts (seen with LX200 OnStep) no longer log "Error setting UTC Offset" / "Error setting site longitude coordinates" on connect.** Connecting sent the mount its time and site twice in quick succession (once from the adapter, once from the app's post-connect context push), and neither waited for the driver to finish the first serial exchange with the mount. The two paths are now one (`IndiAdapter.push_context`): each set waits for its property to leave Busy before the next, and an identical repeat within a minute (time) or with unchanged coordinates (site) is skipped. Internal to the INDI adapter; no UI, help or wiki change. If the errors persist, they come from the OnStep driver rejecting the values themselves (the INDI log will show), not from ordering.
- **CI static-analysis (ruff) failure fixed.** Two `except Exception as e:` handlers in `galileo/library/services/telescope_ftp.py` bound `e` without using it (F841, introduced by the merge repair), which failed the blocking ruff step. The binding is removed; no behaviour change, so no help/wiki/design-doc impact.
- **Installed builds no longer fail to plot satellites in the Star Atlas (`ModuleNotFoundError: No module named 'sgp4'`).** `sgp4` is imported lazily by `galileo.planning.minor_bodies` but was never declared as a dependency, so it was present in the development environment but not in the CI-built installers. It is now in `pyproject.toml` and `requirements.txt`. No inline-help or wiki change.
- **Repaired merge `5d0c7d5`, which broke the library package and the installer build.** The merge combined the refactor that split `file_processing`, `master_manager`, `light_calibration`, `telescope`, `sessions_widget` and `config_widget` into helpers/mixins with the other branch's edits to the *old* monolithic code, and git spliced the two together wrongly: `file_processing.py` no longer parsed (so all of `galileo.library` failed to import and ~65 library tests failed in CI), and `master_manager.py`/`telescope.py` referenced names that no longer existed. The refactored structure is restored and the other branch's changes are re-applied onto it: the master-scan header pre-check, FlatDark masters (flat-dark subtraction when calibrating, `FlatDark` session rows and resource status, the flat-dark lookup through the flat session), tile-compressed/multi-extension image reads in calibration, the Celestron Origin FTP support and hostname setting, DWARF/Origin hostname handling in `find_telescope`, and the per-Observatory weather history attribute. No new behaviour, and no inline-help or wiki change: no control was added or renamed.

### Changed

- **The Star Atlas is now the screen shown at start-up, and the Dashboard icon is hidden from the sidebar.** The Dashboard page is still built (`OBS-060`, `PRIMARY_SECTIONS` unchanged) but has no entry point for now. No inline-help or wiki change: no control was added or renamed.
- **Science menu: "Variable Stars" appears only when the VSTarget plugin is installed, and the Science section hides entirely (sidebar and Options) when no plugin supplies any item.** `SCIENCE_ITEMS` is now empty — the old built-in "Variable Stars" stub was a placeholder shown even with no plugin. `TC-SKYMAP-010` updated; the submenu count no longer assumes a plugin is present.
- **Plugins can add controls to an Equipment page.** A plugin declaring `panel_level = "equipment:<category id>"` (e.g. `"equipment:switch"`) has its `build_page()` widget embedded on that Equipment page (`UiRegistry.get_equipment_panels`) instead of appearing under Science. The Kasa Switch plugin uses it, so **Kasa switches are now on Equipment > Switches** with a "Scan for KASA switches" button and On/Off buttons per outlet, rather than under Science. No inline-help change needed: the controls belong to the plugin's own panel.

### Removed

- **Imaging: the View panel's Panels… button and its dialog are gone.** The saved panel layout (`UI-020`) is still applied at start-up, but there is no longer an in-app editor for it. Help, wiki, SDD and UAT scripts updated.

- **The retired `galileo.sequencer` package is gone; the session engine now lives at `galileo/session_exec.py`.** "Sequencer" was dropped as a concept early on and the running app only used `session_exec`; `basic.py` (`SequenceRunner`), `advanced.py` (nested instruction/condition/trigger engine) and `file_namer.py` were reachable only from tests, a plugin hook and a self-test import. All imports moved to `galileo.session_exec`. `PluginContext.register_instruction_type` (same name, so plugins keep working) now records the class in a new `galileo.session_exec.BlockRegistry`, and any class with an async `execute(context)` runs; plugin blocks still do not appear in the Sessions palette. Tests that exercised the dead engines were rewritten against `session_exec`/`ui.sessions` (TC-SES-010/300/330/340/350, TC-PLUG-020, TC-LIB-150, TC-NFR-REL-010, the scheduler fixture); TC-SES-020/070/090/310/320/360 and TC-NFR-REL-040 now skip, because that behaviour existed only in the deleted package. The SDD (§4.6/4.7), RTM, CLAUDE.md, README, wiki plugin guide and Galileo-Plugins README are updated, and leftover "sequencer" wording in comments, help text and a Settings tooltip now says session.

### Added

- **Safety devices (weather stations, safety monitors) and their rules now belong to the Observatory, not a Pier (`OBS-030`).** One station watches the sky over every Pier under the roof, but each Pier had its own copy of the device and its own rules, and the scheduler judged a Pier by whichever copy was on screen — so a job could run on another site's weather. Now they are configured, saved and connected once per Observatory: migration `029` adds `safety_device_configs` and `observatory_safety_rules` and carries each Observatory's existing settings up from its lowest-numbered Pier (the per-Pier rows are removed; rolling back copies them to every Pier). The Safety page keeps its tabs and connection when you select another Pier of the same Observatory and rebuilds only when you change Observatory; the top-bar Pier Connect/Disconnect no longer tears the shared devices down (a Pier's Disconnect would have blinded every other Pier), so the tab's own button now toggles **Connect**/**Disconnect**. Every Pier's job queue is gated on that one verdict. **Fixed with it:** the verdict used the last reading taken while the Safety page was on screen, so unattended gating could rest on a stale or empty reading; `evaluate()` now re-reads a device whose reading is older than its poll interval, and a connected device that cannot be read counts as unsafe. In the domain model `Pier.safety_monitor` / `Pier.set_safety_monitor` and `Observatory.set_safety_monitor(scope=...)` are removed. SRS `OBS-030` (and the `OBS-140`, PSD, SDD wording that depended on it), RTM, Equipment/Planning wiki articles, Safety and common help updated; tests `TC-OBS-030` (Observatory scope, other Observatory not inheriting, migration up and down), `TC-OBS-140` (stale-reading refresh). Not covered: tested against fake stations, not a real one; Piers of one Observatory that really have different weather sources can no longer be modelled — use separate Observatories.

- **CI: informational test run on Python 3.14 (`tests-newest-python` in `quality.yml`).** The suite now also runs on the newest Python, never blocking a merge, so deprecations and 3.14/3.15 incompatibilities show up early. `requires-python` stays `>=3.11` because Raspberry Pi OS Bookworm ships 3.11. Expect the job to fail at install until `sep` (no 3.14+ wheel) and `lz4` (no 3.15 wheel) publish wheels; move it to 3.15 then. CI only; no code, help, wiki or design-doc change.

- **Scheduled sessions now run on every Pier, not only the selected one (`OBS-140`).** The scheduler tick used to service only the Pier selected in the top bar, so with three Piers an overnight schedule would have stalled on two of them until you clicked over to each. It now walks every Pier of the Observatory and starts each idle Pier's due job against that Pier's own devices (every Equipment page already kept each Pier's connection across a Pier switch; they now expose it as `adapter_for(pier_key)`, and `build_session_context(window, pier)` / `_imaging_frame_context(pier)` / `active_optical_tube(pier)` take a Pier). A non-selected Pier uses its primary camera and first optical tube, since the top-bar selectors describe only the selected one; a Pier with no camera and no mount connected waits instead of failing its job; one Pier's error no longer stops the others being serviced. Safety is gated on the Observatory's safety devices — see the entry below. The Dashboard reports each Pier's real connection state instead of showing every non-selected Pier as disconnected. A session started with **Run** is unchanged. New requirement `OBS-140` (SRS, RTM, SDD 4.4b/4.9b), tests `TC-OBS-140` (three-Pier tick, per-Pier context, unsafe Observatory holds every Pier, unconnected Pier waits alone, Dashboard), Dashboard help, wiki Planning article and README updated. Not covered: the cross-Pier tick has been tested with fakes, not on three real mounts.

- **Library: flat-dark calibration frames (`LIB-180`), ported from AstroFiler.** Dark frames taken at a flat's exposure are now a calibration type of their own instead of being mistaken for darks (or flats). They are recognised however `IMAGETYP` spells them ("Flat Dark", "FLATDARK", "Dark Flat"), filed under `Calibrate/FLATDARK`, grouped into `FlatDark` sessions, linked to the flat session they match, stacked into a `flatdark` master by Auto-Calibration, and — in `calibrate_light_frame`, `galileo-auto-calibration` and Library > Sessions > Calibrate — subtracted (less the bias) from the flat before it is normalised, so the flat no longer carries its own bias pedestal and thermal signal. Check-out of a light session includes the flat-dark master. Without a flat-dark the calibration is exactly as before. The wiki's Library article is updated; new tests `TC-LIB-180`.
- **Library: Celestron Origin download source (`LIB-190`), ported from AstroFiler.** Library > Images > Download and `galileo-download -t "Celestron Origin"` list and fetch the raw FITS files in the telescope's `RawData` folder over anonymous FTP. The telescope is addressed by IP or an `origin`/`celestron` hostname; its address is saved under Options > Library > Celestron Origin Configuration (blank uses the Origin's own hotspot address, 192.168.1.208). Inline help, wiki Options article and new tests `TC-LIB-190`.

- **Generic User Acceptance Test script, [`docs/UAT-generic.md`](docs/UAT-generic.md).** The same end-to-end night as `UAT.md`, but not tied to M13 or the INDI simulators: a Test profile at the top has the tester choose their own target (with a checklist for picking one that suits their site, date and optics) and record their own equipment, protocol and optics, and steps for devices they don't have are `N/A`. Adds steps for a meridian flip, a mosaic with rotation, and a cooled camera. Documentation only; no code, help or wiki change.

- **Schedule screen: drag a scheduled session back to Unscheduled.** Dropping a session block from the calendar onto the Unscheduled list now unschedules it (same as "Remove from Schedule"), instead of only being able to move it around the grid. Pier operations still just reposition, since they have no Unscheduled state. Updated the Schedule help.

- **Schedule screen: Upcoming Sessions panel.** A read-only list below the calendar shows every scheduled entry that hasn't finished, soonest first, each with its local start time and a text summary of its activities beginning with the target (e.g. `Slew To: M31 › Image: 10×300s Ha`). It refreshes with the page. Added to the Schedule help and the Planning wiki article.

- **Dark Capture block: Close Cover option.** A new checkbox closes the Pier's dust cover or flip-flat panel (when one is connected) before the darks and reopens it afterwards, so darks are taken with the light path covered. The Filter field stays, since some cameras (Seestar) use a dark cover filter instead. With no cover connected the block continues and logs that. Saved/templated sessions without the field load as off. Updated the Sessions help.

### Fixed

- **Library: frames whose image is not in the primary HDU are now calibrated.** Galileo's own tile-compressed FITS files keep an empty primary HDU with the image in an extension, but light calibration read only `hdul[0]`, so a compressed light or master was treated as empty. Calibration now finds the image in whichever HDU holds it (`galileo.library.core.utils.fits_image_data`).
- **Library: DWARF Mini and other DWARF variants import.** Only a `TELESCOP` of exactly "DWARF" was recognised, so a DWARF Mini (or a card with no `TELESCOP` but the usual `DWARF_RAW` folder layout) was rejected as having a bad header. Any `DWARF…` name, or the folder structure, now qualifies.
- **Library: darks link by exposure and temperature.** A light session's dark was matched on exposure as an exact text comparison and ignoring CCD temperature, so "60" never matched "60.0" and a dark from a warm night could calibrate a cold one. Exposure is now compared numerically and the CCD temperature must be within 5 degrees (the same rule is used for flat-darks).
- **Library: master frames are recognised by a punctuation-insensitive name.** Master detection looks at the normalised file name, `IMAGETYP` and `OBJECT`, so `Master_Flat-Dark` and `masterflatdark` are the same and a flat-dark master is no longer mistaken for a dark. Registering masters also skips non-master files from their header alone, without decompressing them first.

- **`docs/UAT.md` simulator setup corrected.** It started the INDI CCD simulator twice to get a guide camera; INDI has a separate Guide Simulator driver, so the `indiserver` command now loads `indi_simulator_ccd` and `indi_simulator_guide` once each, and the PHD2 note points at the Guide Simulator. The command's line continuations, which had been lost, are restored. Docs only.

- **Sessions › Load from Template error used the old "Target" name and was too strict.** The message said "requires an existing concrete Target block" although the block is now called **Slew To**. It now reads "Load from Template needs a Slew To block with a target chosen. Add one first." The check also only looked at the first block; it now accepts a concrete Slew To block anywhere in the session. Updated the Sessions help and SRS SES-190 wording.

- **Wiki pages renumbered with leading zeros** (`01.-` … `09.-`) so they sort correctly in GitHub's wiki contents list (previously `10.` sorted before `2.`). Wiki-internal links, the Home table, and the wiki URLs in `README.md` and `docs/UAT.md` were updated to match. The Plate Solving and Imaging wiki articles now mention Load & Slew setting the current object and rotation applying to a mosaic. Docs only.

- **Solve › Load & Slew now sets the current object.** After slewing to the loaded image's field the Pier's current object stayed whatever it was before, so a following Capture & Solve (Slew to Target) slewed back to the old object. The destination (named from the file's `OBJECT` card, else its coordinates) is now the current object. Updated the Solve help.

- **Log file no longer flooded by INDI mount trace messages.** The telescope driver's `[ALIGNMENT]` and `[SCOPE]` messages (several per second while tracking) made up about 94% of a typical day's log (14,500 of 15,500 lines). They are no longer written to the log; errors and warnings from drivers, and all other driver messages, are still logged. Internal change; no help/wiki impact.

- **Framing Assistant: rotation now applies to a mosaic.** Setting a rotation together with a mosaic grid used to be ignored (the dialog said so); now the whole grid turns about its centre, so pane positions and each pane's outline are tilted in the preview and in the captured pane coordinates, and the survey image is sized to the tilted grid's bounding box. With a rotator connected, **OK** also turns the rotator to the angle. With no rotator and no explicit grid the existing auto-sized covering mosaic is unchanged. `create_mosaic` and `mosaic_footprint_deg` gained an optional `rotation_deg` (default 0, so existing callers are unaffected). The session Image block's mosaic dialog has no rotation field and is unchanged. Rotation help entry updated; new test `test_tc_frame_040_mosaic_rotation_turns_the_grid`.

- **Removing a session from the Schedule grid now returns it to the Unscheduled tray** (its start time is cleared) instead of deleting the job. Right-clicking an entry in the Unscheduled tray now offers **Delete** (with confirmation) in place of Remove from Schedule, so deleting is the explicit, separate action. Pier operations, which have no tray to return to, are still deleted. Inline help updated.

- **A session scheduled on Planning > Sessions now appears in the Schedule page's Unscheduled list.** The Schedule page only refreshed on Pier changes, so a job added while it was hidden stayed invisible until something else forced a reload; it now reloads each time the page is shown. No help/wiki change (no control changed).

- **Start-up splash shows device connection attempts.** While the Equipment screens auto-connect, the splash now names each device being connected (name, host:port) and then records a ✓ Connected or red ✗ Failed line, instead of sitting on "Loading Equipment screen". Applies to the mount and all other device pages that connect through the shared adapter path; the camera sensor-info probe is not reported. Internal UI change; no help/wiki/design-doc impact.

- **Splash progress bar no longer covers the logo.** The start-up progress bar, operation list and percentage now sit in a strip added beneath the licence notice rather than over the Galileo artwork. Internal UI change; no help/wiki/design-doc impact.
- **Crash ("QWidgetItem has no attribute 'isVisible'") when connecting to PHD2.** The help tooltip timer scanned `QApplication.topLevelWidgets()` and hit a stale non-widget wrapper while a window was being torn down; it now skips anything that isn't a real `QWidget`. The root cause of the stale wrapper (likely the PHD2 connect dialog closing) was not identified from the crash report alone.

### Added

- **User Acceptance Test script, [`docs/UAT.md`](docs/UAT.md).** An ordered, end-to-end manual test that follows a night imaging M13: install and launch, Observatory/Pier, Options, equipment (an INDI server running the simulator drivers), Star Atlas and planning, framing, slew, test exposures, solve, focus, guiding, building and running a session, safety, scheduling, History, calibration frames, Library processing and shutdown. Each step has an expected result and a pass/fail column, blocker steps are marked, and there is a sign-off table. Documentation only; no code, help or wiki change.
- **Target name is a search box in Sessions > Target Parameters.** Typing in Name now searches the sky-atlas catalog (name and designations) and lists matches; picking one fills in the name, RA and Dec. Manual entry still works. Help entry for Name updated.
- **Add Session from Template on the Sessions screen.** A new button beside Add Session offers the saved templates and creates a new session holding all of the chosen template's blocks (including its placeholder Target), so a stored procedure no longer needs an existing session to load into. New `SessionsScreen.add_session_from_template`; help entry added to `planning.sessions.md`.
- **Progress bar on the Targets screen search.** Searching now opens a small dialog with a progress bar that moves through the phases — catalog search, altitude charts, building each result tile, fetching thumbnails — instead of leaving the UI apparently frozen with only a status-bar message. No new controls, so no inline-help change.
- **Image block Filter is preloaded from the filter wheel.** In Sessions > Image Parameters, Filter is now an editable drop-down listing the active filter wheel's filters (blank keeps the current filter), as the Filter Change, Focus and FOR Filter blocks already did; with no wheel connected it stays typeable. Tests updated for the combo. The control keeps its label, so no help-file change.
- **"Searching N objects" notice on Planning > What's Up Tonight.** Ranking runs for a noticeable time, so a small dialog now names how many catalog objects (after the catalog/magnitude filters and candidate cap) are being ranked, and closes when ranking finishes. No new controls, so no inline-help change.
- **Start-up progress on the splash screen.** The slow initial load now shows a progress bar and the list of operations being run (diagnostics, crash reporting, database/migrations, UI code, plugin discovery, main window, top bar, each screen, Options, theme, watchdog) — the running one in white, the last few finished ones ticked and dimmed — so users can see how far start-up is. New `galileo.ui.startup_progress` (`report()` is a no-op unless `app.main` installs a reporter, so tests and `--selftest` are unaffected). No new controls, so no inline-help entries.

### Changed

- **Sessions "Target" block renamed "Slew To".** The palette entry, block-list text, and dialog title (now "Slew To Parameters") say what the block does. Internal class and saved-template format are unchanged, so existing sessions and templates load as before. Help heading renamed to match.
- **About Galileo dialog asks for Patreon support.** The dialog now explains that the project costs real money to run (web site, developer licenses, test equipment) and links to https://www.patreon.com/starseekersca. Text-only change; no new controls, so no inline-help entries.

- **Altitude graphs on Targets and What's Up Tonight show just the night.** The per-object rise/transit/set graph now spans sunset to sunrise instead of a fixed 24 h from UTC noon (which put labels at odd times like 17:30), labels whole local hours in smaller text, is twice as wide, and shades the background by the Sun's altitude so dusk and dawn fade in and out. Charts now also carry `sun_altitudes`; if it is missing the old full-range plot is used. No new controls, so no help/wiki change.

- **What's Up Tonight ranking notice reworded.** The dialog shown while ranking now reads "Analyzing N objects that meet criteria…" instead of "Searching N objects…", since the objects have already been filtered by then. Text only; no help/wiki impact.
- **Changelog rotated.** `[Unreleased]` had grown to 162 KB against the ~40 KB threshold, so its contents moved verbatim to the top of `docs/changelog/2026-10.md` under "[Unreleased] as of 2026-10-13" (archive title range extended to 2026-10-13). Documentation housekeeping only; no code or behaviour change.

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). This project does not yet follow Semantic Versioning releases (see `README.md` status) — entries accumulate under `[Unreleased]` until the first tagged release.

**Older entries are archived in [`docs/changelog/`](docs/changelog/)**, one file per rotation (e.g. [`2026-09.md`](docs/changelog/2026-09.md)), so this file stays short enough to read in full. Search the archives (`grep -rn <term> docs/changelog/`) rather than reading them end to end. When this file grows past roughly 40 KB, move everything under `[Unreleased]` to the top of the current month's archive file (creating `docs/changelog/YYYY-MM.md` if needed) and leave `[Unreleased]` empty again.

## [Unreleased]

### Changed

- **The changelog is split so it no longer dominates the context window of anyone (or any tool) reading it.** `CHANGELOG.md` had grown to ~250 KB in one `[Unreleased]` section, so every edit to it meant loading the whole history. All existing entries moved verbatim to [`docs/changelog/2026-09.md`](docs/changelog/2026-09.md); this file now holds only new entries, with a rotation rule (above) for when it grows again. `CLAUDE.md`, `CONTRIBUTING.md`, `TODO.md` and the VSTarget PSD now point at the archive where they cite past entries.
- **`galileo/ui/app_window.py` (a single ~7,900-line file, one `AppWindow` class) is now the package `galileo/ui/app_window/`, split into 22 files along the module's own pre-existing section comments (one file per page/concern — Camera page, Mount page, Imaging page, Framing Assistant, etc.), with `AppWindow` reassembled from mixins in `__init__.py`.** The file's size was itself a maintainability problem, independent of any single bug: window chrome, every device-category dialog, and Pier/Observatory CRUD were all in one module, and it accounted for over a third of the project's mypy findings by sheer bulk, burying the real bugs in there under noise. No behavior changed — this is a pure move, verified via `python -c "import galileo.ui.app_window"`, `ruff check galileo/ui/app_window/` (same pre-existing findings as before, none new), and the full set of `tests/test_*.py` files that exercise `AppWindow` (`test_driver_info`, `test_eqp`, `test_focus_page`, `test_guider_page`, `test_img`, `test_lib`, `test_optics_page`, `test_rotator_page`, `test_sched`, `test_sky`, `test_solve_page`, `test_star_atlas`) still passing. Splitting one class across files created a real mypy wrinkle — each mixin, checked alone, can't see that it'll share `self` with every other mixin once combined — fixed via a generated `Protocol` (`_state.py`) applied as an explicit `self: AppWindowState` type per mixin method (mypy's own documented pattern for mixin classes, no runtime effect). Net result: project-wide `mypy . --ignore-missing-imports` went from 623 errors to 620 — a net improvement, not the regression a naive per-file split would have been. Found by CODE_REVIEW.md (Finding 9); verified via mypy/ruff/pytest as above.

# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). This project does not yet follow Semantic Versioning releases (see `README.md` status) — entries accumulate under `[Unreleased]` until the first tagged release.

**Older entries are archived in [`docs/changelog/`](docs/changelog/)**, one file per rotation (e.g. [`2026-09.md`](docs/changelog/2026-09.md)), so this file stays short enough to read in full. Search the archives (`grep -rn <term> docs/changelog/`) rather than reading them end to end. When this file grows past roughly 40 KB, move everything under `[Unreleased]` to the top of the current month's archive file (creating `docs/changelog/YYYY-MM.md` if needed) and leave `[Unreleased]` empty again.

## [Unreleased]

### Added

- **Connect Link listener, certificate and pairing (slice 2; `LINK-010`, `LINK-020`, `LINK-260`).** `LinkServer` is an `aiohttp` HTTPS listener (TLS 1.2+, bound to the LAN address by default, never `0.0.0.0` unless chosen) whose single gate answers only *request pairing* and *poll pairing* without a token; every other request, including to a path that does not exist, gets the same bare 401, so a caller learns nothing about the routes. `PairingService` holds a request with a six-digit confirmation code (shown to the peer and listed for the owner), expires it (default 5 minutes), rate-limits per source address, refuses when the list is full, and hands an approved peer its token exactly once. `CertificateStore` generates a self-signed EC P-256 certificate on first use (certificate in the database, private key only in the OS credential store; a user-supplied pair replaces it if the key matches) and exposes the fingerprint peers pin. Revoking a peer refuses its token on the next request. New dependencies `aiohttp` and `cryptography`. Not yet built: the route registry, event stream, transfer, handshake, discovery and the Options page. Tests `TC-LINK-010`, `-020` in `tests/test_link_net.py`.

- **Connect Link foundation (slice 1 of the build: peers, permissions, audit; `LINK-030`, `LINK-090`, `LINK-240`, `LINK-260`).** New `galileo.connect_link` package and migration `033` with two core-owned tables, `link_peers` and `link_audit`. `PeerStore` creates peers with a token shown once and kept only as a salted HMAC hash, authenticates it, refuses revoked or expired peers at once, and limits grants to the permissions the pairing plugin declares (never `outreach.view` to a paired peer, never `config.*` to a service credential). `resolve_client` implements delegated identity: a service credential may act for a client of its own plugin, with the client's scopes, and is refused for revoked, expired, unknown, cross-plugin or service clients. `AuditLog` records actor, carrier, plugin, route, outcome, reason and plugin-defined fields, drops any field that looks like a secret, prunes to a configurable retention (default 90 days) and never raises into the request path. Nothing listens on the network yet: the listener, pairing, dispatcher and gateway come next. Tests `TC-LINK-030`, `-090`, `-240`; no screen changed, so no help or wiki change.

- **Plugin dependencies (`PLUG-200`).** A plugin's `plugin.toml` may now list `requires = ["pkg>=1.0", ...]` (PEP 508). On install or update Galileo runs `pip install --target` into `<plugin folder>/.deps` — never Galileo's own environment — puts that folder on the plugin's import path while it is loaded, and rolls the whole install back (previous version restored) if any package cannot be resolved, offline included. Removing the plugin removes its folder and so its packages. This is what lets the Connect plugins carry their own web/crypto libraries. Tests `TC-PLUG-200`.

- **Power boxes and relay boards now work on the Equipment > Switches page, over INDI and Alpaca.** Connect a device and the page shows its ports grouped by type (DC, USB, dew heaters, adjustable outputs, device-wide controls) with an On/Off button per switchable port, a 0–100 % duty and **Set** for each dew heater, a voltage and **Set** for a regulated output, and a Readings box for voltage, current, power and temperatures. A port the hardware cannot switch is shown as *not switchable* with no button; a control the driver is not currently offering (a dew heater in an automatic mode) is greyed out with the reason as a tooltip; and every driver property the page does not place stays reachable in an **Other** section, so nothing is hidden. Switching a port off while a session is running on the Pier asks first. INDI devices that follow INDI's standard power interface — `POWER_CHANNELS`, `USB_PORTS`, `DEW_CHANNELS`/`DEW_DUTY_CYCLES`, `VARIABLE_CHANNELS`/`VARIABLE_VOLTAGES` and the rest, which is what the Pegasus and Terrans drivers use — need no vendor-specific code; this was built against the driver sources and a fake INDI server, **not yet against a real power box**. An Alpaca Switch device is shown as one group of toggles, with any other writable channel as a plain value carrying only the range the device declares (Alpaca does not say whether a number is a voltage or a duty, so no unit is assumed) and read-only channels as readings. (`EQP-SW-020`–`140`; new `galileo/core/switches.py`, `galileo/adapters/indi/switch_map.py`, `galileo/ui/app_window/_switch_page.py`.) Help: `equipment.switch`.
- **Plugins can teach Galileo about a power box whose INDI driver does not follow the standard interface.** `PluginContext.register_switch_profile(profile)` takes a declarative `SwitchProfile` — the device names it claims, a signature of (property, kind) pairs, and which properties are channels and readings — and core applies it with the same engine it uses for the standard interface. A device is matched to a profile by the properties it offers, never by its INDI name alone (two Wanderer drivers report the same name), a profile that matches nothing or ties is reported rather than guessed at, and a malformed profile is refused with a logged reason without affecting any other. A disabled plugin's profiles are not offered and an unloaded plugin's are dropped. (`PLUG-210`, `EQP-SW-080`.)
- **Requirements and design for the above, and for the WandererBox plugin** (SRS `EQP-SW-020`–`140` and `PLUG-210`; SDD §4.1, §4.2, §4.2a, §4.3, §4.20; RTM rows and counts, SRS total 324→338 and RTM total 396→410; and `docs/plugins/wandererbox/` PSD, SRS `WBOX-010`–`100`, SDD, RTM). ### Fixed

- **INDI driver messages in the log now say which server sent them, and connection/exposure errors no longer quote another device's message.** Several servers share one log and device names repeat across them (an all-sky `ZWO CCD ASI224MC` on spao-obs, a guide camera of the same name on spao-ntt62), so the all-sky camera's exposure chatter looked like it belonged to the other server. Log lines are now `INDI message host:port [device] text`. Separately, "failed to connect", "exposure failed" and timeout errors quoted the newest message from anywhere on the server — a failed Hydreon RG-11 connect reported "[ZWO CCD ASI224MC] Download complete." — and now use the latest message from the device concerned (or a server-level one), else "no message from driver". Internal logging/diagnostics; no help, wiki or design-doc change needed.
- **Crash (Windows access violation) while slewing, still happening after the queued-connection fixes — worker threads no longer build a Windows Proactor event loop.** The `faulthandler` log showed the UI thread dying in the constructor of the next mount-polling thread while the resume-tracking thread was inside `asyncio.run`. The mount-position poll, limit monitor, resume-tracking and filter-move threads each called `asyncio.run`, which on Windows creates and tears down an IOCP (Proactor) loop every few seconds. They now run on a private selector loop (`_run_mount_coro`), which mount adapters (sockets and threads only) work fine on. This is a hypothesis fitted to the traces, not a confirmed root cause; if it still crashes, send the new `faulthandler.log`. No help, wiki or design-doc change needed.
- **Crash (Windows access violation) while slewing and panning the Star Atlas: the same missing queued connection fixed earlier for the Mount page's limit monitor, in many more places.** A worker thread's signal connected to a plain function runs that function on the worker thread, so the handler updated widgets and the status bar from the wrong thread. After a slew the "resume tracking" thread did exactly this (status-bar message), which corrupted Qt and made the next `QThread` construction crash (the Star Atlas reticle poll in the latest `faulthandler.log`). Now delivered on the UI thread: resume-tracking, Darks, Flats, Framing rotation, Imaging annotate and preview render, Observatory look-up, Plugins page downloads, Settings thumbnail cache, the top bar's filter move, and the session runner's progress/finished signals. The library dialogs' worker signals (`auto_calibration_dialog`, `download_dialog`) still use the old pattern. No help, wiki or design-doc change needed.
- **Diagnostic switch `GALILEO_DISABLE_MOUNT_GUARD=1`** stops the Mount page's 5 s limit/flip monitor from starting, to help isolate a start-up access-violation crash that appears in the monitor's first thread construction. Off by default; not a fix. No help, wiki or design-doc change needed.
- **The Mount page's limit/flip monitor no longer leaves a finished thread object attached to the main window every 5 s.** Each pass created a `QThread` parented to the window that was never deleted. The thread is now unparented, kept alive until it has finished, and then deleted. Internal; no help, wiki or design-doc change needed.
- **Application crash (Windows access violation) a while after a slew, with no user input.** The Mount page's limit/flip monitor runs every 5 s on a worker thread, and its result handler was connected without a queued connection, so it ran on that worker thread and updated widgets and the status bar from there. That corrupts Qt's memory, and the process then dies later in an unrelated place (the `faulthandler` log shows the crash inside the next worker thread's constructor, again and again). The monitor's result and the jog pads' failure signals (Mount page and Imaging nudge) are now delivered on the UI thread. Other worker-thread signals that update the UI without a queued connection (Darks, Flats, Framing, Settings, the top bar's optics/camera and the Observatory dialog) have the same pattern and are not yet changed. No help, wiki or design-doc change needed.
- **The N/S/E/W jog buttons moved an INDI LX200 OnStep mount far too slowly to notice.** The buttons did send their commands (the log shows each press and release), but the adapter only knew INDI's standard slew-rate names (`SLEW_GUIDE` … `SLEW_MAX`); OnStep numbers its rates `0`–`9`, so no rate was ever selected and the mount kept its power-on speed. Numbered rate lists now get the same four speed tiers by position, so the Rate choice on the Mount page takes effect. No wiki or design-doc change needed.
- **The Home button did nothing on INDI mounts that have no homing sensor, such as LX200 OnStep.** It always sent the `FIND` switch, but OnStep's `TELESCOPE_HOME` offers only `SET` and `GO`. Home now sends `FIND` where it exists and `GO` otherwise, and its help explains that Home is not the park position.
- **The INDI and Alpaca Switch adapters were empty stubs.** Their `switches` list was never filled and `set_switch` only changed a local variable — it never reached the device — so a Switch device could be selected but not used. Both now read the device and write to it, and the state shown is read back from the device, never remembered from the last command.

### Changed

- **The application log no longer records peewee's SQL statements.** They were logged at DEBUG, hundreds of lines a minute, and drowned out the device messages. Database warnings and errors are still logged.
- **The log now shows the jog rate number.** A Mount-page jog logs `hold E at rate 9 (10°/s)`, and an INDI mount also logs `set_slew_rate {'rate': '9'}` for the rate it selected. The `move_axis` line's value is renamed `deg_per_s`, because it is the speed in °/s the level stands for, which previously made rate 9 look like 10.
- **The Mount page's jog Rate is now a level from 1 (slowest) to 9 (fastest)** instead of Fine / Medium / Coarse. On an INDI OnStep mount, level *n* selects OnStep's slew rate *n* (9 = its maximum); other drivers use the nearest rate they offer, and Alpaca mounts get the matching speed in degrees per second (0.002 to 10). The default is 5. The Imaging page's nudge pad keeps Fine / Medium / Coarse. Inline help updated.
- **Equipment / Mount page buttons are now one uniform size** (Scan, Connect, Slew, tracking, Home/Park/Unpark/Set Home/Set Park, Save), with a little extra width so the longest label ("Set Home Position") is no longer clipped. The square N/S/E/W jog pad keeps its own 44 px size.
- **The Equipment > Switches page is no longer a scan-and-save page.** It now has the Aux page's Scan / Device / Connect / Save flow and a live control panel (see above), and a saved Switch device connects when its Pier is opened, like the other Equipment pages, and disconnects with the Pier-level Disconnect. Panels plugins add to the page (Kasa, Generic Relay, SwitchBot) still sit above it unchanged. Internal: the shared fake INDI server in `tests/` can now host extra devices and push unsolicited updates, opt-in so tests that count its standard devices are unaffected.

### Removed

- **Equipment / Mount page no longer shows a "Settings: None" row.** It was a hard-coded placeholder that never reflected the mount or driver. The matching inline-help heading is removed too. No wiki or design-doc change needed.

### Fixed

- **Splash screen, About box and window title showed a stale version.** `galileo/__init__.py` still said `0.9.0alpha` although the published pre-release is `v0.9.02alpha`; it is now `0.9.02alpha`, and `pyproject.toml` carries its PEP 440 spelling `0.9.2a0`. No help, wiki or design-doc change needed.

- **Switching Observatory or Pier no longer shows the logo, version and copyright notice.** The progress splash shown while a switch loads is now a plain dark panel with just the operation list and progress bar; the full branded splash stays for application start-up. No help, wiki or design-doc change (internal presentation only).
- **Galileo failed to start with "Failed to run migrations ... 031_add_focuser_mode.py: No such file".** An earlier build had recorded a migration named `031_add_focuser_mode` that was later renamed to `032_add_focuser_mode_and_travel`; `peewee-migrate` re-reads the file of every applied migration, so databases that had applied the old name could no longer open. The file is restored as a documented no-op (`031_add_focuser_mode.py`); the columns are still added, idempotently, by 032. No user-visible behaviour, help, wiki or design-doc change.
- **The N/S/E/W pads gain diagonal NW/NE/SW/SE buttons** (Imaging and Equipment > Mount) that hold both axes moving together and stop both on release, as in KStars. Help, SRS and wiki updated.
- **The N/S/E/W pads now move the mount while the button is held (Imaging "Mount Nudge" and Equipment > Mount).** Modelled on KStars' mount motion pad: pressing a button starts the axis and releasing it stops it, so the mount moves for exactly as long as you hold the button. Before, the Imaging pad fired a fixed-length pulse on click and the Mount page started motion on click and never stopped it until **Stop**. Commands are sent in order from one worker thread so a release can never overtake its press, and a held button that is hidden, disabled, or whose window loses focus stops the mount so it cannot run away. The Imaging pad's **Duration** control is removed (nothing to set; `nudge_mount`/`_NudgeThread` replaced by `nudge_command` and the shared `galileo/ui/app_window/_hold_to_move.py`). Inline help (`imaging`, `equipment.mount`), SRS `IMG-130`, and the wiki updated.

- **The Focus screen's manual Move button now works while a Loop is running.** Loop (and Capture) disabled Move, so you could move the focuser once and then not again until you stopped the loop, which defeats focusing by eye. - **Starting a manual capture on a second Pier no longer risks crashing the app.** The capture worker's progress, finished and failed signals were connected to closures that repaint the preview and histogram without a connection type, so they could run on the capture thread; with two Piers capturing, two threads touched Qt widgets at once and the process died inside `pyside6.abi3.dll`. They are now `QueuedConnection`, delivered on the UI thread. Not yet confirmed against the original two-Seestar crash. No requirement or help change.

Tests updated for the combo. The control keeps its label, so no help-file change.

# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). This project does not yet follow Semantic Versioning releases (see `README.md` status) — entries accumulate under `[Unreleased]` until the first tagged release.

**Older entries are archived in [`docs/changelog/`](docs/changelog/)**, one file per rotation (e.g. [`2026-09.md`](docs/changelog/2026-09.md)), so this file stays short enough to read in full. Search the archives (`grep -rn <term> docs/changelog/`) rather than reading them end to end. When this file grows past roughly 40 KB, move everything under `[Unreleased]` to the top of the current month's archive file (creating `docs/changelog/YYYY-MM.md` if needed) and leave `[Unreleased]` empty again.

## [Unreleased]

### Added

- **Sessions can now actually run: the Run button executes the session's blocks, and the scheduler uses the same engine** (`galileo/sequencer/session_exec.py`, `galileo/ui/session_runner.py`, `galileo/ui/sessions.py`, `galileo/scheduler.py`, `SES-030`/`040`/`050`/`080`/`170`/`230`/`350`, `SCHED-060`). Until now a session could be authored and scheduled but nothing ever ran its blocks. New `SessionExecutor` walks the block list (loops included) and drives the connected Pier's real devices: Target slews and tracks, Image/Dark/Flat capture through the Library-registering `ImagingService`, Filter Change (with the saved focus offset), Cool/Warm camera, Autofocus, Plate Solve & centre, Guide Start/Stop/Dither, Park/Unpark, Meridian Flip, Dome open/close/sync, Notification, and FOR Filter / FOR Object loops (mosaic Image blocks use the mosaic capture order). **Run** now executes immediately on a worker thread, first refusing with a list of reasons if a block needs equipment that isn't connected or the ordering is invalid; the card then shows Pause/Resume and Stop, a "block 3 of 7 · frame 12 of 40" line, and a green ▶ on the executing block, and is locked while it runs. A bad frame is logged and skipped (three in a row abandon that Image block); a failed slew, plate solve, park or dome-open ends the session, because carrying on would image the wrong sky or leave equipment unsafe. If the safety monitor reports unsafe, only shutdown blocks (park, dome close, guide stop, warm) still run. The scheduler reuses all of it: `ObservatoryScheduler.due_jobs()`/`run_job()` start a session whose timeline start has arrived (checked every 15 s for the active Pier) and record frames, the session log and the outcome; `RepeatNTimes` jobs now count completed runs. Not done: only the active Pier's queue is serviced (other Piers' devices aren't live), `SCHED-030` constraints and "start at culmination" aren't evaluated when picking a job, the safety-monitor hook isn't wired to a device yet, and `SES-070` frame-to-block provenance isn't written to FITS headers.
- **Edit buttons (pencil) for Observatory and Pier in the top bar** (`_core.py`, `_observatory_pier.py`, `galileo/observatory.py`). A pencil button now sits beside each delete button. Observatory's opens the same dialog as New Observatory with every saved field filled in (name, latitude, longitude, elevation, timezone, address, owner, notification type, email, cell); Pier's renames it. Duplicate names are refused. Saving updates the database through new `update_observatory`/`rename_pier`, refreshes the selector, and re-applies the site and horizon to the Star Atlas and slew guard. The dialog covers every `observatories` column and the Pier name (`connect_on_startup` has its own top-bar checkbox), so no migration was needed. Tests in `tests/test_obs.py`.
- **macOS app icon (`packaging/macos/galileo.icns`, `assets/images/galileo.icns`).** The macOS `.app`/`.dmg` built by the release workflow previously had the generic PyInstaller icon, because `packaging/build.py` only passes `--icon` when `galileo.icns` exists and none was ever committed. The icon is now generated from `assets/images/Icon Proof.png` (cropped, centered with a little padding, 16–512 px plus @2x/retina sizes), so the next CI macOS build picks it up with no workflow change. A second copy in `assets/images/` is what `install/install.sh` (the git-clone macOS installer) already looked for. Not yet verified on a macOS runner.

- **`Galileo --selftest [REPORT_FILE]` and CI gates for the installers** (`galileo/selftest.py`, `.github/workflows/release.yml`, `NFR-INSTALL-010/020/030`). The flag runs a headless check of an installed or frozen build: required imports, bundled data files, Qt start-up, database creation with migrations in a temp file, and a real job through the CPU worker pool (the part a frozen build most often breaks). It writes `SELFTEST OK` or the failures to the report file as well as stdout, since a windowed Windows exe has no console. The release workflow now runs the pytest suite (excluding soak/hardware/integration) in a `test` job that gates all builds, and self-tests each platform's frozen app before wrapping it into an installer. Test: `test_tc_nfr_install_030_selftest_passes_from_source`. Verified on the Windows frozen build; the other platforms are untested until the workflow's first run.
- **Installation docs describe both install routes** (`README.md` Installation section, wiki *Getting Started Guide* and *Home*). Prebuilt per-platform installers are now the recommended route, with the first-run macOS Gatekeeper / Windows SmartScreen / AppImage FUSE notes, uninstall steps and where user data lives; the git-clone bootstrap scripts are documented as the auto-updating alternative.
- **Single-file installers for Windows, macOS, Linux x86_64 and Raspberry Pi (aarch64)** (`packaging/`, `.github/workflows/release.yml`, `NFR-INSTALL-010/020/030`). Galileo can now be shipped as one self-contained download per platform, with no Python, Git or pip on the user's machine: `Galileo-Setup-<ver>-win-x64.exe` (Inno Setup), `Galileo-<ver>-macos-{arm64,x86_64}.dmg` (ad-hoc signed; Developer-ID signing and notarization switch on when the `APPLE_*` repo secrets exist) and `Galileo-<ver>-linux-{x86_64,aarch64}.AppImage`. `packaging/build.py` freezes the app with PyInstaller (each platform builds natively); the workflow builds all five on a `v*` tag and attaches them to the GitHub release. The existing git-clone bootstrap scripts remain as the developer/auto-update path. The Windows freeze was built and launched locally; the Inno, DMG and AppImage wrappers and the CI workflow have not been run yet. Note this replaces the Nuitka/WiX plan in SDD §2.4 with PyInstaller, chosen for reliability with PySide6/scipy/astropy.
- **Installed (frozen) builds write logs to the per-user log directory** (`galileo/diagnostics.py`). The log folder used to be `<app root>/logs`, which is read-only inside Program Files, a `.app` or an AppImage.
- **Solve: Polar Alignment** (`galileo/polaralign.py`, `galileo/ui/solve.py`, `PLT-080`). The Polar Alignment tab, which was a placeholder, now works, using the same method as KStars/Ekos. Start Polar Alignment solves three frames, turning the mount in RA (30° by default, east or west, both settable) between them, and finds where the mount's RA axis really points from where each frame was pointing in the Earth-fixed horizon frame when it was taken, so it does not rely on the mount's own RA readout. Solved altitudes are raised for refraction (a checkbox, on by default) but the target is the geometric pole. It shows how far the axis is from the pole, in words ("Lower the polar axis by 12′00″", "Move the polar axis west by … (turn the mount … in azimuth)"), for either hemisphere, and then keeps solving so the figure updates as you turn the altitude and azimuth knobs. That update models the knobs themselves and allows for the mount's tracking meanwhile, so it is exact wherever the camera points, provided the mount is level; Stop ends it. It refuses, without moving the mount, a rotation that would carry the mount across the meridian, where it would flip, and logs if the mount turns noticeably less than asked. It needs a camera, a mount and the Observatory's latitude and longitude, and says which is missing. The frames appear in the results table like any other solve.
- **Mount page: Rate selector for the N/S/E/W pad, and all jog/nudge speeds 10x faster** (`_mount_page.py`, `ui/imaging.py`). The pad now has a Fine/Medium/Coarse Rate drop-down, the same one the Imaging page's Mount Nudge uses, replacing the separate Primary/Secondary rate boxes. The speeds behind those names are now 0.2 / 2 / 10 deg/s (were 0.02 / 0.2 / 1) because users reported extremely slow movement; this applies to both pages. On INDI mounts the faster values also select the next-faster of the driver's own slew-rate steps (e.g. Fine now uses Centering rather than Guide).
- **Mount page: separate Unpark button, park status, and Tracking On / Tracking Off** (`_mount_page.py`, `adapters/indi.py`, `adapters/alpaca.py`, `EQP-MNT-010`/`020`). The single Park/Unpark toggle is now a Park button plus an Unpark button (each greyed out when it doesn't apply) with a "Park status" line. Under Manual control, Tracking On and Tracking Off sit beside Set tracking rate, with a line showing whether the mount is tracking and at which rate. Both adapters' `get_status()` now report `tracking_rate` (Sidereal/Lunar/Solar/King, or Custom on INDI); the Alpaca adapter makes one extra request per status poll for it.
- **Mount page: Meridian Flip and Limits sections** (`galileo/mount_limits.py`, `_mount_page.py`, `_threads.py`, `core/slew_guard.py`, migration `026_add_mount_limits.py`, `EQP-MNT-060`/`EQP-MNT-070`). "Flip if HA >" (degrees) flips a tracking mount that is still on the west side of the pier once it is that far past the meridian, then resumes tracking; the page shows whether the flip is inactive/armed/done and the pier side (e.g. "East (pointing West)"). Optional altitude limits (min/max, with "Tracking only") and a maximum hour angle (hours) stop the mount and say which limit was hit when it is tracking or slewing outside them, and slews whose target is outside the limits are refused with a status-bar message. The monitor runs every 5 s on a worker thread even when another page is showing. Settings apply immediately and are saved per Pier with Save. A flip the mount didn't perform isn't retried for 10 minutes.
- **Sessions: Dither and Meridian Flip removed from the block palette** (`galileo/ui/sessions.py`). They can no longer be added to a session. The block classes remain so sessions and templates saved earlier still load. `SES-130`/`SES-140` in the SRS still list them and have not been updated.
- **Sessions: new Dark Capture block, and Flat Capture now matches the Flats Assistant** (`galileo/ui/sessions.py`, `session_block_dialogs.py`, `tests/test_ses.py`). Flat Capture's parameters are now the Imaging page's Flats Assistant fields (flat method, exposure or Calculate, number of frames, filter or All, ADU method, exposure increment) instead of a bare count and target ADU. The new Dark Capture palette block takes the Darks Assistant's fields (optional filter plus a comma-separated list of exposure lengths). Saved templates that still have a Flat Capture target ADU load fine; the old value is dropped. Run-time execution of these blocks is not wired up, same as the other Sessions blocks.
- **Sessions: FOR Object now builds its list by searching the sky atlas** (`session_block_dialogs.py`, `sessions.py`). Right-click the block, type in the search box, and pick a result to add it. Each entry has a ✕ to remove it, and duplicates are ignored. Each object is saved with its RA/Dec, so looping can slew to it later without another lookup. The block's `objects` field changed from a list of names to a list of name/RA/Dec records, so any FOR Object blocks saved earlier today will not load.
- **Sessions: FOR Filter / FOR Object loop blocks with indentation** (`galileo/ui/sessions.py`, `session_block_dialogs.py`, `tests/test_ses.py`). Two new palette blocks repeat everything indented beneath them, once per filter or once per object. Dropping a block under a loop puts it in the loop's body. Dragging a block right indents it and dragging left unindents it. A loop moves and indents together with its body, and deleting a loop moves its body out one level. Right-click a loop to pick its filters from the active filter wheel (plus free-text extras) or enter object names, one per line. Block `indent` is saved with sessions and templates; older files load unindented. Run-time execution of loops is not wired up, same as the other blocks. Also fixed moving a block down the list landing one row too far.
- **Sessions: Filter Change block now offers a dropdown of the active imager's filters** (`session_block_dialogs.py`). It replaces the free-text box. The dropdown stays editable, so it still works with no wheel connected.
- **What's Up Tonight now shows real aurora (Kp) and smoke forecasts** (`galileo/safety.py`, `_whats_up_page.py`, `recommend.py`). New `NoaaKpClient` (NOAA SWPC planetary Kp index, `SAFE-090`) and `NoaaSmokeClient` (NOAA Hazard Mapping System smoke polygons within ~0.5° of the site, mapped to an AQI-equivalent, `SAFE-100`) are ported from the MCP project's `mcpAurora`/`mcpSmoke`, using only the standard library (no numpy/shapely/lxml). Both feed the existing advisory line and ranking penalties, and `AURORA_SMOKE_SOURCES_WIRED` is now `True`, so an unavailable aurora/smoke estimate (offline, or outside HMS's North-America-only coverage) again lowers confidence. Like the weather forecast they only apply to today's date.

### Fixed

- **Notification block called the notification service with the wrong arguments** (`galileo/ui/sessions.py`, `galileo/notify.py`). `NotificationBlock.execute` passed only the message to `NotificationService.emit(event_type, detail)`, so it would have failed on a real service (the test used a mock). It now sends a new `NotificationEvent.SESSION_MESSAGE` with the message as detail, and says so clearly if no service is configured.
- **Intel Mac installer build failed its self-test (`.github/workflows/release.yml`).** `cryptography` 49+ publishes no macOS wheel, so on the `macos-15-intel` runner pip compiled 50.0.2 from source against Homebrew's newer OpenSSL; PyInstaller then bundled a different, older `libssl.3.dylib`, and `import paramiko` in the frozen app died with `Symbol not found: _SSL_get0_group_name`. The macOS builds now install with `cryptography<49` (48.x has a prebuilt wheel with OpenSSL linked in). Windows and Linux builds are unchanged. Not yet confirmed on a re-run.

- **Two more CI-only test flakes fixed** (`tests/phd2_fake_server.py`, `tests/test_guide.py`, `tests/test_guider_page.py`, `tests/test_nfr.py`). `test_tc_guide_050` (and the matching guider-page test) dropped the fake PHD2's clients right after `connect()`, but `connect()` returns at the TCP handshake, before the fake's accept thread has registered the client, so on a faster-scheduling Linux runner it hung up on nobody and never saw a disconnect; the fake now has `wait_for_client()` and both tests use it. `test_tc_nfr_perf_010` enforces a 3 s wall-clock limit for rendering a 100 MP frame; profiling shows `_compute_stats` (SEP star detection) alone takes ~3.2 s on the dev machine, so it sits at the edge of ordinary hardware and failed on the CI runner (3.09 s). It now takes the best of three renders and carries a new `perf` marker that the CI release gate excludes (it still runs in a normal local `pytest`). NFR-PERF-010 itself is **not** met on the dev laptop at the moment; making star detection faster on 100 MP frames is open work.
- **Installer scripts could not run on the CI runners** (`packaging/macos/build_dmg.sh`, `packaging/linux/build_appimage.sh`, `.github/workflows/release.yml`). Both were committed from Windows without the executable bit, so the macOS DMG and Linux AppImage steps failed with "Permission denied" / exit 126 on the first full CI run (the freeze and `--selftest` steps before them passed on all platforms). The bit is now set in git and the workflow calls them through `bash`. The Intel Mac build also moved from the retired `macos-13` runner (its job sat queued forever) to `macos-15-intel`.
- **INDI filter wheel: `move_to` could return before the move had started** (`galileo/adapters/indi.py`, `EQP-FW-010`). It sent the slot command and immediately checked the property state; if the driver's Busy reply hadn't arrived yet the state still read Ok from before, so the wait returned at once and `position` read the old slot. It now waits (up to 2 s) to see the driver's reply to this command before waiting for it to finish. Fast machines hid it; the first CI run on a Linux runner exposed it as `test_tc_eqp_fw_010_names_and_zero_based_position` failing with `0 == 2`. Test: `test_tc_eqp_fw_010_move_waits_for_a_slow_driver_to_acknowledge` delays the fake driver's reply to reproduce it.
- **Release workflow no longer hangs on a stalled `apt` step** (`.github/workflows/release.yml`). The `apt-get` calls now run non-interactively with network retries, and the jobs have timeouts (30 min for `test`, 60 for builds), so a stuck runner fails fast instead of holding the pipeline for hours.
- **Two tests that only failed on Linux fixed** (`tests/phd2_fake_server.py`, `tests/test_nfr.py`), found by the first CI run. The fake PHD2 server now calls `shutdown()` before `close()` when dropping clients, because on Linux `close()` alone doesn't hang up while another thread is blocked reading the socket, so `test_tc_guide_050` never saw PHD2 "quit". `test_tc_nfr_sec_020` searched with a case-sensitive `*security*` glob, which missed `docs/archive/SECURITY.md` on Linux; it now matches case-insensitively and only under `docs/` (it could previously be satisfied by files inside a local `.venv`).
- **Four stale tests fixed** (`tests/test_driver_info.py`, `tests/test_weather_safety_pages.py`). They were failing because the code moved on, not because of bugs: the Alpaca mount status now also reads `trackingrate` on every poll, and the Safety page's "+" button pops its menu up on click instead of using `setMenu()` (so the "+" fits a 28px button). The tests now expect both. This was blocking the release workflow's pytest gate.
- **Mount adapters now use their own Pier's slew guard** (`adapters/indi.py`, `adapters/alpaca.py`). They were checking the shared fallback guard, so the per-Pier horizon set up in `_apply_horizon` and bound at connect time was never the one consulted; the horizon-obstruction check and the new mount limits now both come from the guard bound to the adapter, falling back to the shared one when none is bound.
- **Library no longer pauses on first open** (`galileo/app.py`). Opening Library built all six screens on the UI thread, and most of that time was importing scipy/astropy (via `galileo.library.core`), regardless of how few images there were. Those imports now run on a background thread shortly after the main window appears.

- **Equipment > Safety page: "+" button now visible, driver info populates on connect, intro text removed** (`_weather_page.py`). The "+" add-device button was a menu button whose drop-down arrow squeezed its label out at 34 px; it is now an accent button that pops the menu on click, matching the other Equipment pages. Driver info/version were only filled when a device was picked from the list, so a saved device auto-connecting (or Connect with a typed name) left them as dashes; they are now read on connect. The "Connect a Weather Station device…" / Safety Monitor subtitle was removed.

- **What's Up Tonight entries are no longer all marked "Reduced confidence"** (`galileo/planning/recommend.py`, `_whats_up_page.py`). The aurora and smoke advisories have no data source yet (`SAFE-090`/`SAFE-100`), so they were always "unavailable" and degraded every entry on every night regardless of the weather forecast. Their absence now only lowers confidence once `AURORA_SMOKE_SOURCES_WIRED` is set. Entries can still be reduced for a missing horizon profile, missing forecast, or unavailable Moon position — the tooltip lists which.

- **What's Up Tonight's cloud-cover penalty and "Why:" note now reflect tonight's night hours, not the whole day** (`galileo/planning/recommend.py`, `galileo/safety.py`). The forecast was consulted, but `_weather_factor` averaged all 24 hourly values (daytime included) and any non-zero average added "Forecast cloud cover reduces tonight's usable window" — so the note appeared nearly every night. The Open-Meteo request now asks for 2 days in the site's local timezone; cloud cover is averaged over 21:00–04:59 local only, the note appears only when the reduction exceeds 15%, and it states the percentage.

### Added

- **Equipment gains an "Aux" device category (`EQP-AUX-010`) for loading a miscellaneous INDI driver, or an ASCOM Alpaca Switch device, that has no dedicated Galileo category — e.g. the INDI Dust Cover Simulator used as this feature's reference screenshot — and controlling whatever fields and switches it defines, in a tabbed panel built from the driver's own property groups rather than a fixed per-category UI.** Unlike every other category's typed port (`slew_to_coordinates`, `move_to`, ...), `DeviceCategory.AUX` (`galileo/core/devices.py`) has no fixed operation set: new `AuxController.get_property_groups()`/`write_property(name, values)` work against plain `AuxPropertyGroup`/`AuxProperty`/`AuxElement` dataclasses (kind `text`/`number`/`switch`/`light`, group, permission, state) that an adapter builds from whatever the connected driver actually reports — a first-class Equipment category with its own scan/connect/save flow, distinct from the pre-existing `EQP-060` raw-property inspector (a read-only diagnostic overlay on an already-categorized device). `IndiAuxAdapter` (`galileo/adapters/indi.py`) lists every device on the server unfiltered by `DRIVER_INTERFACE` (Aux is the deliberate catch-all) and reshapes `IndiClient.device_properties()` 1:1 into the new dataclasses, one group per INDI property group (i.e. tab). `AlpacaAuxAdapter` (`galileo/adapters/alpaca.py`) is scoped to ASCOM's own interface for this purpose, ISwitchV2 (the "Switch" DeviceType) — each channel becomes a boolean On/Off pair when its declared range is `0..1` step `1`, or a numeric slider otherwise, in a single "Switches" group. The new Equipment > Aux page (`galileo/ui/app_window/_aux_page.py`) keeps the same Driver/Server/Port/Scan + Device/Connect/Save row every Equipment page has, then renders a `QTabWidget` built from the connected device's property groups: switch properties as a button per element (mutually exclusive for an INDI `OneOfMany`/`AtMostOne` rule, matching e.g. Connect/Disconnect or Park/Unpark), number properties as a slider + spinbox + Set button, text properties as a line edit + Set button, each with a small state-colored dot (grey/green/yellow/red for INDI's Idle/Ok/Busy/Alert). The panel is rebuilt only when the driver's reported property set actually changes, and otherwise refreshed in place on the shared 2-second poll so an in-progress edit isn't clobbered. New tests: `tests/test_aux_page.py` (the Qt page end to end against a fake backend), new cases in `tests/test_indi_adapter.py` (unfiltered discovery and property grouping/writes against the real protocol fake server) and `tests/test_eqp.py` (`AuxController` against a mock), plus a `mock_aux_device` fixture in `tests/conftest.py`.
- **Galileo now sends a startup registration ping, ported from AstroFiler's `services/registration.py` (`galileo/registration.py`).** On launch, Galileo opens a short-lived TCP connection to the author's tracking server (`www.gordtulloch.com:5050`) and sends a one-line handshake (`"GA02.0"`) identifying the app and version, then closes it — the server counts the connection as a "use", the same mechanism AstroFiler has used to track install/version counts. The ping runs on a background daemon thread via `start_startup_ping()`, scheduled from `galileo.app.main()` right after the main window is shown; any failure (no network, server unreachable) is logged at INFO and otherwise ignored, so it can never block or break startup. As in AstroFiler, this is undocumented in the UI but can be disabled by adding `Registration = False` to `library.ini`'s `[DEFAULT]` section (`_ini_allows_registration()`, checked fresh on every ping). New `tests/test_registration.py` covers the handshake payload over a real loopback socket, the ini opt-out, and that a failed ping never raises out of `start_startup_ping()`.
- **The Focus screen gains a "Filter Offsets" button opening a dialog that measures each filter wheel position's focus offset relative to a chosen Primary filter, and applies it automatically on future filter changes without a full autofocus run (`EQP-FW-020`, `FOC-060`).** The dialog (`galileo/ui/filter_offsets_dialog.py`, `FilterOffsetsDialog`) lists one row per filter the connected wheel reports — a Primary checkbox (exactly one at a time, persisted immediately), a Select checkbox for which filters Start measures this run, four Measurement columns and a Result column. Start moves the wheel to the first checked filter, runs four autofocus sweeps there, averages their best-focus positions, then repeats for every other checked filter; each non-Primary filter's Result is the Primary average minus its own. Previously `AutofocusService.apply_filter_offset`/`FilterWheelController.set_focus_offset` (`FOC-060`/`EQP-FW-020`) existed at the service layer with no way to populate or see the offsets from the UI. New `FilterOffset` dataclass and `get_filter_offsets()`/`get_primary_filter()`/`save_filter_offset()`/`get_filter_offset_steps()` (`galileo/autofocus.py`, `galileo/observatory.py`) persist each Pier's measured state in a new `filter_offsets` table (migration `023_add_filter_offsets.py`, `FilterOffsetRecord`), surviving an application restart. - **The Planning > Scheduler screen is gone (`galileo/ui/scheduler.py` deleted entirely), user's call now that Planning > Schedule's timeline (above) is the queue's only UI.** Its priority-order table, per-row Move Up/Down, and the `SchedulerPageWidget`/`_EditJobDialog` UI are removed; `"scheduler"` dropped from `PLANNING_ITEMS` and its sidebar icon. **Reopened gap:** the Edit… dialog (priority, `JobConstraints`, startup/completion conditions) and the Show Trajectory… altitude chart had no equivalent on the Schedule screen and were not ported — `SCHED-020`'s "modified" clause, `SCHED-030`/`040`/`050`'s constraint/condition editing, and `SCHED-080`'s chart display are consequently unreachable from the running app again, though the underlying domain model/tests (`galileo.scheduler`) are untouched and still satisfy `SCHED-010`–`100` at the level RTM already verifies them (`Test`, not a specific screen). `_AltitudeChart` (still needed by the Sky Atlas/Targets and What's Up Tonight pages) moved to `galileo/ui/app_window/_widgets.py` rather than being deleted with the rest of the screen. `docs/SDD.md` 4.9b/4.9c and `TODO.md` updated with the gap; `tests/test_sched.py`'s three UI-level Scheduler-screen tests removed (domain-level `TC-SCHED-010`–`100` coverage at the top of that file is unaffected); `tests/test_star_atlas.py`'s nav-menu snapshot test updated to match.
- **Removed the Imaging tab's Star Overlay checkbox, and retired `IMG-050` (the SRS requirement it was the only UI for).** The checkbox toggled `ImagingService.star_overlay_enabled`, but nothing ever read that flag to actually draw star markers on the preview — it had no renderer behind it, so it did nothing visible from the day it was added. Removed the checkbox and its wiring from `galileo/ui/app_window/_imaging_page.py`, `ImagingService.set_star_overlay`/`star_overlay_enabled` from `galileo/ui/imaging.py`, and `TC-IMG-050` from `tests/test_img.py`. Per-frame star count/HFR statistics (`IMG-040`) are unaffected — only the (non-functional) overlay toggle is gone. `docs/SRS.md`/`docs/SDD.md`/`docs/RTM.md` updated: `IMG-050` is marked retired rather than reused, and the `IMG` domain/requirement totals move from 268 to 267 (SRS) and 282 to 281 (RTM).
- **PySiril is gone from the Library's Options > Calibration tab and from the codebase entirely.** The `master_manager.py` module never actually called PySiril — it always fell back to its astropy-based sigma-clip/simple-average stacking — so the "Frame Processing Method" dropdown (PySiril vs Internal, defaulting to PySiril) and the PySiril Convert Timeout, PySiril Stack Timeout and Enhanced Siril Logging controls it exposed configured a code path that didn't exist. Removed `frame_processing_method`/`pysiril_convert_timeout`/`pysiril_stack_timeout`/`pysiril_debug_logging` from `galileo/ui/library/config_widget.py` (widgets, save/load/reset) and reworded the stale PySiril-integration docstrings in `galileo/library/core/master_manager.py`; nothing else in the codebase read these settings. The unrelated Siril-compatibility note on the FITS compression tooltip (about GZIP2 being readable by Siril/NINA) is unchanged — that's about file-format interop, not the PySiril library integration.
- **Colour XISF files can now be imported, and XISF import works through the Library at all.** The ingest handler called the converter with the wrong arguments and so failed for every `.xisf` file; separately, `XISFGeometry.channel_size()` returned the whole image's pixel count, which broke the per-channel reshape of any multi-channel image; the converted header double-counted the channel axis in `NAXIS`; and the creation time and creator application were never read from namespaced headers or from PixInsight's standard `XISF:` properties. Found while writing the XISF tests.
- **`galileo-load-repo --repo` and `galileo-sync-repo --repo` now do what they say.** The override was set on the processor facade but files are filed by a fresh repository manager built from `library.ini`, so everything still went to the configured repository. Found while writing the command tests.
- **Tests brought in line with the product, and unimplemented features marked as such.** Three Star Atlas tests had gone stale (`contextMenuRequested` now carries a third argument; Options has a Plugins page after the per-section pages; a plugin can append items to a core menu, which also made the Science-menu test depend on the machine's installed plugins) and now match. The four tests for requirements with no implementation yet — `LOG-060` (recent-log pane) and `NOTIF-020`/`030`/`040` (email/SMS channels, contact details from the owning Observatory) — are `xfail(strict=True)` with the reason, so a failing run means a regression and implementing one of them will flag the leftover marker. No product code changed. Found by the 2026-10-04 code review (F3/F10).
- **Importing a hostile XISF file can no longer exhaust memory, and a non-HTTP notification webhook is refused.** The XISF converter parsed the header of an imported file with the standard XML parser, which expands entity declarations ("billion laughs", external entities); it now uses `defusedxml` (a declared dependency now, previously only present by accident), and a header that declares entities is rejected with a clear error. `WebhookChannel` also refuses any configured URL that is not `http`/`https` — `urlopen` would otherwise happily read a `file://` URL — and logs why. Found by the 2026-10-04 code review (F7). New tests: `TC-LIB-010` (XISF header, normal and hostile) and `TC-EXT-070` (webhook scheme).
- **SFTP retrieval is the Library's alone, and its failures are no longer silent.** The VSTarget plugin only re-exported the Library's SFTP adapter (and declared an unused `paramiko` dependency), so it was removed from the plugin and `VST-AN-010` retired across the plugin's SRS/SDD/PSD/RTM (counts now 20 requirements); core `SRS`/`SDD` state that `EXT-120` is Library-owned. In the adapter itself (`galileo.library.adapters.sftp`), a connection or listing failure now logs at WARNING with its traceback instead of debug (an unreachable server used to look like an empty folder), the SSH client is closed even on error, one failed file no longer abandons the others, accepted unknown host keys are logged with their fingerprint, and `strict_host_keys=True` refuses them. Found by the 2026-10-04 code review (F4). The plugin's own changelog records its side.
- **The two type errors on Galileo's startup path are fixed.** The main-window mixins' shared `AppWindowState` protocol declared `_camera_backends` and `_imaging_service` as plain attributes while `AppWindow` defines them as read-only properties, so mypy rejected `AppWindow` as a valid `self` (surfacing at `window.show()` in `app.py`); they're now declared as read-only properties. `app.py` also casts `QApplication.instance()` to `QApplication` before calling `setWindowIcon`. Type-annotation changes only — no runtime behaviour differs. Found by the 2026-10-04 code review (F9).
- **A device property write could silently vanish.** `DeviceController.set_property` fired the backend's async setter with a bare `ensure_future`, so the task could be garbage-collected mid-write and any failure (a device refusing a gain/offset value, say) was lost; with no event loop it swallowed the error and left the coroutine un-awaited. The write is now kept referenced until it finishes and a failure is logged with its traceback; the no-loop case runs it to completion. Callers still don't see an exception, as before. Found by the 2026-10-04 code review (F6).
- **`TC-EXT-110` now tests the Simbad lookup that exists.** It asserted a `SimbadClient` class in `galileo.planning.sky_atlas` that the code never had — the lookup is `_search_simbad_sync` behind `SkyAtlas.search_online` — so it failed although `EXT-110` is implemented. The test now runs that function against a stubbed `astroquery` (no network) and checks the returned coordinates and V magnitude. No product code changed.
- **Blocking network and file I/O no longer runs on the asyncio event loop.** The weather-forecast fetch in `galileo.safety` (run from the safety poll loop, which stalled for up to 10 s when Open-Meteo was slow), the geocoding lookup, the Alpaca discovery/GET/PUT fallbacks used when `httpx` isn't installed, and the SMB download now run in worker threads via `asyncio.to_thread`; the SFTP adapter's directory creation moved into its existing worker thread; the ASTAP solver's file checks and the Imaging page's FITS save (a full-frame disk write) likewise no longer block the loop. Behaviour and error handling are unchanged. Found by the 2026-10-04 code review (F5).
- **Star Atlas tests no longer read the developer's real `planning.json`.** The `window` fixture built the app before any test patched the Planning options path, so a machine with "Do not slew where obstructed" saved as on made `test_slew_guard_is_scoped_per_pier` fail (the checkbox started checked, so the test's `setChecked(True)` changed nothing). The fixture now points the options at the test's temp folder. No product code changed — this was a test-isolation bug, not a slew-guard state leak.

# Changelog: 0.9.05alpha (2026-11-05)

Shipped as [v0.9.05alpha](https://github.com/gordtulloch/Galileo/releases/tag/v0.9.05alpha). Back to the [current changelog](../../CHANGELOG.md).

### Fixed

- **An INDI device that failed to connect with no driver message now says which serial port it tried.** Connecting a WandererBox Pro V3 switch ended in "failed to connect: no message from driver", which gave nothing to act on. When the driver sends no message and the device has a `DEVICE_PORT`, the error now names that port and points to the INDI Control Panel's Connection tab. The underlying failure is on the INDI server (most likely a wrong serial port, or the port in use); this only makes it diagnosable. No help, wiki or design-document change.
- **Galileo crashed (access violation) right after switching Observatory or Pier.** A switch shows the progress splash, which pumps the Qt event loop, so the Mount page's 5-second limit/flip guard and the Star Atlas pointing poll could fire in the middle of the switch, while pages were half-reloaded, and start worker threads re-entrantly. The switch now sets a `_pier_switching` flag for its duration and both timers skip their tick while it is set (the next tick runs normally). The crash was read from `faulthandler.log`; I could not reproduce it here, so confirm on your rig. No help, wiki or design-document change.
- **Reinstalling a plugin over the same version crashed with `PermissionError` on Windows.** A plugin's private dependencies (`.deps`) can hold a DLL that Galileo itself has loaded (WebConnect's `_cffi_backend.pyd`), and the installer deleted the whole folder first. It now removes what it can, keeps the locked files (the same dependencies) and extracts over them. No visible change otherwise, so no help, wiki or design-document update.

### Added

- **Frames a front end can look at (`galileo.control_surface.frames`, `PREV-070`).** The preview service could render a stretched, binned JPEG or a tile pyramid but nothing was registered to give it a frame, so no plugin could show a picture. The engine now follows the bus for finished frames (a remote capture and a running session both announce theirs) and keeps each Pier's current exposure, reads any Library frame from its file (fetching it first when it is held on a Master), and offers `render`, `tile`, `info` and a list of the newest Library frames through `ControlSurfaceService.previews`. While a session runs, previews shrink rather than compete with imaging. A malformed reference is refused before anything is read. No screen of the desktop changes; WebConnect's Camera, Focus and Solve pages are the first users. Tests: `TC-PREV-070` (five cases, including the real catalogue listing and a real FITS read).
- **Connect plugins checklist: WebConnect's first operating screen.** `docs/CONNECT_PLUGINS_CHECKLIST.md` now records that the WebConnect plugin has its first browser screen (Pier list, live state, lease bar, catalogue-built operations); the code is in the plugins repository. Documentation only; nothing in Galileo itself changed.
- **Sky and framing in the Control Surface catalogue (`CSURF-130`).** A remote client can now search the bundled catalogue by name or designation (`sky.search`, offline), read an object's details with its rise, transit and set tonight at the Pier's Observatory (`sky.object`), and work out how it frames on the Pier's own rig (`sky.framing`): the field of view and image scale from the first optical tube and saved camera, an optional rotation, and the panels of a mosaic of a chosen size and overlap. All three are read-only. A Pier with no focal length or no saved sensor and pixel size is refused instead of framed with invented numbers; without a rotator, a rotation reports the area a covering mosaic would span. Going to a target is the existing `mount.slew` and centring on it is `solve.centre`. The planetarium view, survey-image background and Telescopius and AAVSO lists stay on the desktop. Nothing changes on the desktop, so no inline-help or wiki change. Tests: `TC-CSURF-130` (two cases).
- **Plate solving in the Control Surface catalogue (`CSURF-140`).** A remote client can now solve a new frame (`solve.capture`), solve it and sync the mount to it (`solve.sync`), or centre on a J2000 target (`solve.centre`: slew, then correct with solved frames until within the accuracy asked for), stop a run (`solve.stop`) and read the state, latest solutions and log (`solve.status`). It runs the Solve screen's own workflow, built by the same assembly a session's Plate Solve block uses, so the solver, search parameters and image scale are the Pier's saved Options > Solve settings and optics; a solver that is not set up is refused in its own words. One solve per Pier at a time, and none while a session runs. Sync and centre are not offered when the mount is disconnected, which is reported before anything moves. `make_solve_workflow` gained an optional `log` argument (sessions are unaffected). Not offered yet: solving a frame already on disk, and the polar-alignment routine. Nothing changes on the desktop, so no inline-help or wiki change. Not run against a real camera, mount or solver; the workflow behind it is the existing, already-tested one. Tests: `TC-CSURF-140` (three cases).
- **Guiding on the engine and in the Control Surface catalogue (`CSURF-160`).** A remote client can now connect to the Pier's saved PHD2, start guiding (or recalibrate first), stop, dither, ask PHD2 to choose a star, and read the guiding state, RMS error, recent error trace and the guide-star cut-out. The engine holds one PHD2 connection per Pier, taken from the same saved guider the Guider screen writes, and connects only when asked, since PHD2 may start after Galileo. A session the engine runs now uses that connection, so its Start Guiding and Dither blocks work instead of reporting "No guider connected" at pre-flight (previously the engine had no guider at all). Commands return when PHD2 accepts them, not when guiding settles, which can take minutes; progress shows in `guiding.status` and as `guiding.state` / `guiding.rms` in the event feed. A command PHD2 rejects is refused in PHD2's own words. Nothing changes on the desktop, so no inline-help or wiki change. Not covered by a test: the session hand-off itself (one line in `build_context`); the commands, state, trace, cut-out and refusals are tested against a fake PHD2 behind the real `GuidingService`. Tests: `TC-CSURF-160` (two cases).
- **The Control Surface catalogue now offers session history and the scheduler queue, read-only (`CSURF-230`, `CSURF-200`).** `history.sessions`, `history.frames` and `history.report` give a remote client the recorded sessions with each frame's star count, HFR and guide error and the session averages; `scheduler.jobs` gives a Pier's queued jobs in priority order with progress, planned window and last run state, and names the next one. Both read what the desktop already stored and change nothing. Not offered yet: editing the queue (the engine does not own a live scheduler, and a second writer would corrupt the saved queue), and Library thumbnails and FITS download (they need a binary route). The engine registers both. Nothing user-visible changes on the desktop, so no inline-help or wiki change. Tests: `TC-CSURF-230`, `TC-CSURF-200`.
- **One ordered event feed for front ends (`galileo.control_surface.feed`, `CSURF-260`).** State changes, lease changes, device connections and operation progress are merged into a single feed with increasing ids. A plugin calls `read(after, timeout)` on `get_control_surface().feed` to get everything since its last id, waiting for news if there is none, and is told when it fell too far behind and must re-read state instead of showing a stale picture. A bounded buffer rather than a queue per reader means a slow or vanished browser can never hold up the engine. `LeaseBroker` gained `remove_listener` so the feed can detach cleanly. Nothing user-visible changes yet (WebConnect's live updates will use it), so no inline-help or wiki change. Tests: `TC-CSURF-260` (two cases).
- **The engine now hands its Control Surface to front-end plugins (`galileo.control_surface.service`, `CSURF-250`, `LINK-230`).** The engine already built the operation catalogue, the control lease, the request pipeline and the observable state, but only its own local channel could reach them; a plugin such as WebConnect or MobileConnect had no way to, and would have had to build its own, with a different lease and catalogue from the desktop's. The engine now publishes them when its channel starts and withdraws them when it stops, and a plugin reads them with `get_control_surface()` (`None` while no engine is running). Nothing user-visible changes, so there is no inline-help or wiki change. Test: `TC-CSURF-250` (second case).
- **Per-device Connect buttons now show the connection state.** On the Mount, Camera, Focuser, Filter Wheel, Rotator, Flat Panel, Dome, Aux and Switches pages, a device's **Connect** button reads **Disconnect** while that device is connected and disconnects it when pressed, however it was connected (the button, the top-bar Connect, a Pier switch or start-up) — previously it kept saying Connect and only reported "already connected". Each camera and focuser slot toggles independently. No control added, so the help only needs the button's behaviour noted.
- **Top bar Connect button shows connection progress.** Pressing **Connect** now brings up the same progress panel as switching Pier, naming each device page being connected, instead of the window freezing silently while devices connect. No new control, so no inline-help change.
- **Solve screen: Auto-Centre (`PLT-100`).** A new **Auto-Centre** tick box and **Auto-Centre Cadence** (minutes, default 2) under Solver Action. While ticked, Galileo captures, solves and slews back onto the Pier's current object at once and then on every cadence, always using Slew to Target, so drift is corrected unattended. A pass is skipped and logged (no dialog) if the previous one is still running or the camera, mount or current object is missing; Stop, a change of Pier or a missing solver turns it off. Not saved between runs, like Accuracy and Settle. Added to the Solve help and Plate Solving wiki article, SRS `PLT-100`, RTM, SDD 4.12, and two tests in `tests/test_solve_page.py`. Also fixed a stale assertion there that still expected the Solve page to expose no `capture_and_solve` hook.
- **`Galileo --engine`: the headless engine, first step (`galileo.engine`; `HEAD-010`, `020`, `030`).** Galileo can now start with no display and no Qt as a foreground service: it takes an exclusive lock so a second engine on the same computer is refused (exit code 3, naming the running one), opens the database, loads plugins, handles `SIGTERM`/`SIGINT` with an ordered shutdown, tells systemd when it is ready, and exits with a code that separates a clean stop from a failure. A crashed engine leaves nothing stale to clean up. It does not yet connect devices, run sessions or run the watchdog — those are still held by the desktop and arrive in the next steps (design: SDD §4.33) — so it is not yet useful on a controller by itself. `TC-HEAD-010`, `020`, `030` are written (9 tests, including two real engine processes in a manual check); the other 15 `HEAD` tests stay reserved. No control changed, so no inline-help change.
- **A plugin's Connect Link routes now survive a listener restart (`LINK-050`).** `ConnectLinkService.acquire` (and `LinkHost.acquire`) take an optional `install(server)` function. The listener builds a fresh server each time it starts, so routes registered once were lost when the link was disabled and re-enabled or its port changed; the install function is run on the running server at once and again after every start, a plugin that fails to install does not stop the listener, and leaving removes it. One new test (`TC-LINK-270`). Design note added to SDD §4.28. No visible control changed, so no inline-help change.

- **What's Up Tonight and Targets tiles: Goto and Centre.** Each result tile now has a **Goto and Centre** button beside **Slew To**: it slews the mount to the object, then plate-solves and re-centres on it, the same action as the Star Atlas right-click menu. Help and the Planning wiki article updated; SRS `WUT-060`, SDD 4.8b and both UAT scripts now name the button, and `tests/test_wut.py` covers it.
- **Headless engine and the desktop as a client specified (docs and reserved tests only; no engine code yet).** A Galileo computer with no screen, such as an Astroberry controller, could not run Galileo without the desktop application open, because device connections, session running and Pier helpers are held by the desktop window. Core SRS gains section 4.30 `HEAD` (18 requirements: 15 MVP, 3 P2), SDD gains section 4.33 `galileo.engine`, and the RTM and `tests/test_head.py` gain a row and a reserved test per requirement. The design: an **engine** with no display and no Qt owns the devices, sessions, safety and the control lease; the desktop becomes a client of it, holding the lease as `desktop` through a local channel that passes the same request pipeline as any remote client; with no engine running the desktop hosts one in its own process, so single-computer users see no change; two engines on one machine are refused because the lease lives in memory and two processes would not protect against conflicting commands. The WebConnect PSD, SDD and SRS (new open point `O14`) and the Connect plugins checklist now say that "inside Galileo" means inside the engine.
- **Control Surface, control lease, held motion and emergency operations (`galileo.control_surface`; `CSURF-010`–`080`, `250`, `300`, `400`–`420`, `LEASE-010`–`050`, `080`).** The contract the remote-client plugins are written against, usable with no plugin installed. Services declare operations (name, argument schema with ranges and units, permission class, lease requirement, availability) on a `Registry`; a request is validated first and always returns a typed outcome (`ok`, `refused`, `invalid` with the field, `unavailable`, `busy`, `unreachable`), never an exception, and a safety refusal passes through word for word. An entry of class *config* is refused at registration. Long-running operations publish started/progress/exactly-one-finished on the bus with a correlation id. `ObservableState` gives subscribers a snapshot then sequence-numbered changes per Pier. `LeaseBroker` keeps one holder per Pier in memory (granted when free, taken over only with confirmation, released on disconnect or after 10 idle minutes, published on the bus). `HoldManager` stops held motion when the keep-alive lapses, the holder disconnects, the lease changes hands, the pairing is revoked, the plugin is disabled or a safety stop occurs (defaults 250 ms / 600 ms, validated). `register_emergency` declares stop-everything, park and close-dome with no lease and no second step. No service registers its operations yet (the per-area inventory `CSURF-100`–`240` is still to do), so nothing in the app changes.
- **The Connect Link request pipeline (`LINK-230`).** `Gateway` is the one path from a route to a domain service: identify, authorise (read needs `view` or `control`, everything else `control`; guests only the allowlist), validate against the catalogue, lease, confirm (two-step single-use token for confirm-class operations), idempotency (a retried key returns the original result, even for a confirmed operation), dispatch under a load governor, and audit in a `finally` (a guest's identifier is never stored). The governor turns away transfers first, then previews, then interactive work, keeps slots for a running session, and always admits emergencies; clients are rate-limited individually; previews and transfers yield to a running session. It refuses to start if the catalogue holds a *config* entry.
- **The Master relay (`LINK-220`, `LEASE-070`).** `MasterRelay` presents the Master's Piers and those of paired spokes as one list, relays operations, state, events and previews, and forwards the originating client's identity so the spoke audits the client as actor and the Master's peer as carrier (the Master audits too). The grant is whatever the spoke gave (`control` or `view`); a spoke that gave nothing is reported but hidden from the list. The lease lives on the spoke, so its own desktop and the Master's clients contend through one lease. An unreachable spoke is reported with the time last heard, operations to it are refused with that reason, and it re-attaches with the same token. A spoke serves `/connect/v1/relay/*` when given `SpokeEndpoints`.
- **Replication support for NodeConnect (`galileo.replication`; `REPL-010`–`080`).** Migration 034 puts `app_settings` under change tracking with database triggers, so every write (including the settings store's bulk upserts) sets `dirty`, stamps `modified` and keeps the `base_rev` the edit started from; deletes leave tombstones until the sync owner releases them; applying replicated rows suspends tracking inside one transaction. Migration 035 adds core-owned sync tables (outbox, inbox, snapshots, run reports, transfer queue, per-peer state) behind `SyncStore`, so a sync plugin ships no migration. The Master issues revisions serially per table. A replicable-table registry (natural key, dependency order, node-local and secret fields, row filter) is in place with `app_settings` registered, and a test fails if a new table is neither registered, listed as not configuration, nor on the visible pending list. The session executor now sets a busy signal (`is_busy`, `on_idle`) and a `SettingsChanged` event exists for after a bulk apply. The twelve other configuration tables (Piers, devices, optical tubes and so on) are listed as pending registration and do not replicate yet.
- **A preview service for remote clients and guests (`galileo.preview`; `PREV-010`–`060`).** Renders a stretched, binned, size-limited JPEG of the current exposure, a Library frame or a stack, with an optional histogram and star statistics (count, HFR, FWHM from SEP in the process pool), and a 256-pixel tile pyramid whose stretch comes from the whole frame so tiles join without seams. Results are cached under a byte budget (least recently used out) and a new exposure behind the same reference is never served stale. While a session runs, previews shrink to 512 px / quality 70 rather than waiting. Guest mode encodes from pixels only, is held to 1024 px / quality 75, is never cached, offers no tiles or statistics, and `assert_clean` refuses any JPEG carrying EXIF, GPS, comments or trailing data. Nothing calls it yet.
- **Sky streaming for remote clients (`galileo.skystream`; `SKYSTR-010`–`080`).** Serves the bundled star and deep-sky catalogs by region, magnitude limit and level of detail, brightest first in pages with a resumable cursor, in a compact versioned binary form (delta-coded, quantised to 3.6″; about 6 bytes an object), plus ephemeris for an instant or a range, the site, horizon and live pointing, and a static sky image (stars, constellation lines, mount, field of view, horizon) for clients that cannot draw the sky. Every response carries the Master's as-of time. Capability limits (VR-class or not, concurrent clients, page size, rate) come from timing a page on this computer, not from a platform name; a slow machine says why VR is not offered. Streaming drops detail when a session runs and is capped and rate-limited per client. Nothing calls it yet.
- **Session history can move between nodes (`HIST-050`).** `SessionHistory.export_records` / `import_records` use `(origin_node_id, local_key)`, so a Master can hold every node's history with no collision (an imported session is filed under its origin and never touches a local one), a repeat import changes nothing and a corrected record updates in place. A node now has an identity (`galileo.node_identity`, a random id kept in the settings database and never replicated).
- **Manual focus is a function of the focus module (`ManualFocus`; `FOC-100`–`130`).** Relative and absolute moves, halt, position and temperature, with the focuser's own travel, the user's limits and backlash applied in one place, and held in/out moves that carry the Control Surface deadman (stopping on a lapsed keep-alive, lease change or safety stop). The desktop Focus screen now moves the focuser through it, so the screen and remote clients share one implementation; the screen looks and behaves as before.
- **A frame can be *On Master* (`galileo.library.core.location`; `LIB-200`–`220`, migration 036).** Frames carry a location (`local` / `on_master`) and the holding node. A frame is marked On Master only when the holder's whole-file hash equals the catalog's; only then may its local copy be deleted, and the row, hash, thumbnail and quality metrics stay. Retrieving fetches the file by hash over Connect Link (`data.pull`), verifies it, and restores it; a corrupt or interrupted transfer is discarded. Operations that need pixels call `ensure_local`. In the Library > Images screen such a frame shows a computer icon, **Retrieve** is in the right-click menu, and double-click retrieves then opens it. The integrity check no longer reports an On Master frame as missing. Moving frames to a Master is NodeConnect's job and is not built yet.
- **The Connect Link service (`ConnectLinkService`; `LINK-260`, `LINK-270`).** Composes the listener, pairing, audit, transfer and discovery. Its settings (enabled, port, pairing expiry, audit retention, advertising, bind address) are validated and stored in the shared database; keys stay in the secret store; the all-interfaces address is refused. The listener runs only while Connect Link is enabled *and* a plugin uses it, stops with the last plugin, and a departing plugin loses its routes and streams. Disabling closes the listener, ends every stream, withdraws the advertisement and leaves no timer or task running, while the pairings stay, so enabling again needs no re-pairing. Changing the port, bind address or advertising restarts the listener. Nothing starts it yet (the Options page, `LINK-250`, is not built).
- **The remaining configuration tables are replicable (`REPL-010`–`040`, migration 037).** Observatories, Piers, optical tubes, device configurations, autofocus and solver settings, filter offsets, horizon points, safety rules, safety devices and session templates now carry change tracking and tombstones like `app_settings`. Because their ids differ on every node, a row's parents are named on the wire (`observatory`, or `pier` = `[observatory, pier]`) and tombstones are keyed by those names; `from_wire` turns names back into this node's ids and raises if a parent has not arrived. The solver's web key is withheld from the default wire form, and a focuser's retained position and program paths stay on their machine. Only `scheduler_jobs` is still pending (the scheduler is being reworked). The sync engine itself (NodeConnect) is not built.
- **Device host fields refuse a loopback address (`PROF-130`, `GUIDE-100`).** In every Equipment page's server field and the Guiding screen's PHD2 host, finishing an edit with `localhost`, `127.x.x.x`, `::1` or `0.0.0.0` clears the field with a message asking for the computer's real name or LAN address, and a profile that was saved with one is marked in red and explained when it loads (the value is not changed). This is a behaviour change for anyone who relied on typing `localhost`: use the computer's name or LAN address. Inline help for *Server* and *PHD2 host* says so.
- **Options > Outreach (`LINK-190`) and the live image feed (`LINK-160`).** Open an outreach event for a set time, extend it, end it, eject all guests, make a new secret, and see the Wi-Fi and per-surface QR codes; save the Wi-Fi name, passphrase (kept in the system keychain), allowed networks, default duration, guest limit, image size and quality, the Piers to offer (shown by Observatory and name) and the surfaces to enable. While an event is open, each frame the imaging service finishes for an offered Pier is rendered in guest mode and pushed to the guests watching it; the feed subscribes only while an event is open. An event now ends when Connect Link is turned off. A failed save keeps what you typed. Inline help is `options.connect_link_outreach.md`. No surface (phone app, browser) exists yet, so visitors cannot actually join; the QR codes for them appear once a plugin provides one.
- **The Control Surface catalogue for devices, focus and safety (`CSURF-110`, `150`, `220`, `300`).** `register_device_operations` declares mount (status, slew, sync, track, abort, park as a confirm-class operation, unpark), camera (status, long-running expose, abort, cooling), filter wheel, rotator, dome, flat panel, weather, read-only safety status, focus (status, move, halt and held moves through `ManualFocus`) and the three emergency operations, each calling the same controller method the desktop calls. A device-layer refusal (parked mount, obstructed slew, mount limit, unsafe) comes back verbatim as `refused`, a lost connection as `unreachable`, and each operation says why it is unavailable on a Pier without that device. Nothing is registered by the application yet: a `DeviceAccess` that finds the connected devices of each Pier (they currently live in the main window's per-selection state) still has to be written. Imaging, sky, plate solving, guiding, flip, sessions, scheduler, calibration, Library and notification operations (`CSURF-120`–`240` otherwise) are not declared.
- **Options > Connect Link (`LINK-250`).** A new Options page shows whether Connect Link is listening and where, turns it on or off, sets the port, the pairing request lifetime, the audit-log retention and whether to advertise, and shows the certificate fingerprint. Pairing requests appear with their confirmation code and are approved (choosing the permissions to give; `config.*` is unticked by default) or rejected; paired devices are listed with their plugin, permissions and last contact and can be revoked (taking effect at once, closing any open connection) or deleted. The listener runs on its own thread and loop, created only when it is first needed, so a user who never turns Connect Link on has no thread, socket or certificate; it is shut down when Galileo exits. Pairing now takes a lock, because the page approves requests while the listener polls them. Built-in help is `options.connect_link.md`; the wiki's Options article has a Connect Link section. No plugin uses Connect Link yet, so turning it on today only shows "no installed plugin uses it".
- **The outreach event facility (`galileo.connect_link.outreach`; `LINK-100`–`210`).** An event is off by default and opens for a set time on the Master, only if Connect Link is running, a private-range subnet is set, Piers are offered and every enabled surface reports ready (a check that crashes counts as not ready). A random 160-bit secret lets visitors on the outreach subnet enrol anonymously; every refusal looks like a closed port, except that a holder of the secret is told when the event is full. The source address is checked against the subnet on enrolment and on every request, and a guest seen from outside is disconnected. A guest can do exactly three things (list Piers, receive the live image, switch Pier); everything else is refused and counted before reaching any plugin. Guest images come from the preview service's metadata-free guest mode. Guests are capped and rate-limited. One aggregate audit record per event (visitors, refusals by kind, guests per Pier) holds no tokens, addresses or secrets. The owner can extend, re-issue the secret, eject everyone and get the Wi-Fi and per-surface QR payloads (`segno` is a new dependency for the QR images). The secret and tokens exist only in memory, so a restart voids every guest. No screen or surface exists yet.
- **One loopback check (`galileo.net.is_loopback`, `PROF-130`, `GUIDE-100`).** Recognises `localhost`, `127.0.0.0/8`, `::1` and `0.0.0.0` in every form an address is typed. It is not yet applied to the device and PHD2 host fields, whose default is `localhost`; that changes the editors and is still to do.
- **Star Atlas right-click menu: "Goto and Centre".** It slews the mount like Goto and, once the slew has finished and tracking has resumed, starts a capture-and-solve on the Solve screen using that screen's settings, so a target can be put in the middle of the frame in one step. If the mount never settles, no solve is started. Inline help (`star_atlas.md`) documents it. Not yet covered by an automated test (the menu is built inside the Qt page).
- **First slice of the Galileo edition of Astroberry Manager built and run on a real Astroberry OS 3.2 box (`galileo-astroberry-manager`, not yet committed; no change to Galileo itself).** A Galileo dock item and status panel (hidden unless Galileo is installed or answering), and a streaming `/galileo/` reverse proxy to WebConnect on loopback that forwards only Galileo's own cookies in both directions and answers nothing when WebConnect is not running. The version reads `1.2+g1` and `--version` says "Galileo edition". Checked through the box's HTTPS front end against a stand-in Galileo: status, page proxying, and Server-Sent Events arriving one second apart rather than in a batch. Six unit tests live in the fork's `tests/`. Not yet built: fall-back to the stock manager, packaging, approval vouching and chart goto routing, and WebConnect itself. The core PSD vision also gains the Astroberry line, and the SDD now names the release marker the manager reads (`/etc/astroberry/version`).
- **Browser outreach added to the WebConnect vision statement (docs only)** in the core plugin PSD (re-added after the merge of origin's WebConnect documents replaced the earlier edit), so the vision matches the outreach requirements (`WCON-1200`–`1330`).
- **Connect Link listener, certificate and pairing (slice 2; `LINK-010`, `LINK-020`, `LINK-260`).** `LinkServer` is an `aiohttp` HTTPS listener (TLS 1.2+, bound to the LAN address by default, never `0.0.0.0` unless chosen) whose single gate answers only *request pairing* and *poll pairing* without a token; every other request, including to a path that does not exist, gets the same bare 401, so a caller learns nothing about the routes. `PairingService` holds a request with a six-digit confirmation code (shown to the peer and listed for the owner), expires it (default 5 minutes), rate-limits per source address, refuses when the list is full, and hands an approved peer its token exactly once. `CertificateStore` generates a self-signed EC P-256 certificate on first use (certificate in the database, private key only in the OS credential store; a user-supplied pair replaces it if the key matches) and exposes the fingerprint peers pin. Revoking a peer refuses its token on the next request. New dependencies `aiohttp` and `cryptography`. Not yet built: the route registry, event stream, transfer, handshake, discovery and the Options page. Tests `TC-LINK-010`, `-020` in `tests/test_link_net.py`.

- **Connect Link nodes can find each other on the LAN (`LINK-040`).** While the listener runs it advertises `_galileo-link._tcp` by mDNS with only its display name, node id, port, protocol version and role hint (no secret, and finding a node does not let anyone pair with it), and the advertisement is withdrawn when the listener stops. `Discovery.browse()` lists other nodes (never itself, skipping malformed ones) and `manual_address()` validates a host and port typed in by hand. If mDNS is unavailable the listener still starts and only logs a warning. The tests use a fake mDNS backend, so discovery across real networks (Windows, macOS, Pi) still needs checking by hand. No screen exists yet to show the results (`LINK-250`), so no inline-help or wiki change.
- **Connect Link can now move large files reliably (`LINK-070`).** A paired peer holding `data.push` uploads, and one holding `data.pull` downloads, in checksummed 1 MiB chunks at `/connect/v1/transfer/<sha256>`. An interrupted transfer resumes from the last verified chunk (a stale offset gets a 409 saying where to continue), each chunk and the whole object are verified before it is reported complete, and the receiver recognises an object it already holds by hash so a repeat upload sends nothing. Transfers are the lowest-priority traffic: they are refused with `Retry-After` while a session is running or when two are already in progress. `TransferClient` gives plugins (NodeConnect first) a ready-made resumable upload/download. No screen or control changed, so no inline-help or wiki change; the audit log currently records one row per chunk, which the gateway work (`LINK-230`) should coalesce.

### Changed

- **Catalog images now come from one ZIP download.** The old "Cache All Catalog Thumbnails" (tens of thousands of survey requests, hours of work) is replaced by **Download Catalog Images** on Options > Planning, which downloads a single ZIP from `www.galileo-imaging.com/downloads/galileo-thumbnails.zip` and unpacks it into the thumbnail cache; images you already have are kept, and only `skythumb_*.jpg` entries are ever written.

# Changelog: 0.9.10alpha (2026-11-25)

Shipped as [v0.9.10alpha](https://github.com/gordtulloch/Galileo/releases/tag/v0.9.10alpha). Back to the [current changelog](../../CHANGELOG.md).

### Changed

- **Subtract dark now reaches the solver (PLT-070).** On the Solve screen the dark master is taken off each frame before it is solved (Capture & Solve, Auto-Centre, Polar Alignment, Load & Slew), not only off the picture. On Imaging it applies to the preview, to Live Stack and mosaic stacks, and to the frame solved for Annotate; individually saved frames stay raw. Saved stacks built this way carry a `DARKMAST` header, and the Library registers any file with that header as already calibrated (so it also gets no flat from automatic calibration).

- **Imaging screen buttons.** **Capture** is now twice the size, **Stop** is red (dimmed while nothing is being captured), and **Crosshair** has moved beside **Fit** with the other view controls.

### Added

- **Library > Calibration (LIB-230).** The auto-calibration command can now be run from Galileo: choose the operation and switches, press **Run**, and watch the output in a frame on the same screen, with **Stop** to end it. Switches that the chosen operation would ignore are greyed out, so **Dry run** is not offered for the *All* workflow, which would have made changes regardless. **Clear all masters** asks for confirmation. `--report` and `--no-cleanup` are shown but disabled because the command does not act on them. Not yet tried in an installed (frozen) build.

- **Protective stop: unsafe weather now parks the telescopes and closes the roof (SAFE-130 to SAFE-180).** Previously nothing acted by itself: a scheduled session was only paused and an idle or Run session was left as it was. Now, whether or not anything is running, Galileo stops sessions and other activity (including the exposure in progress) and guiding, parks every mount in the Observatory and closes the dome once they confirm; if one does not, the roof stays open, the park is retried and you are alerted. A banner stays until conditions have been safe (15 minutes by default) and you acknowledge. **After upgrading both the automatic park and the roof close are on**; a weather rule can be set to Warn, and the Safety page has switches for both. A saved safety device that is not connected now counts as unsafe, and weather rules are as authoritative as a Safety Monitor. The headless engine now connects the Observatory's safety devices, which it did not before. New database migration 042. Applies to the desktop and the engine. Tested with simulated devices only, not on real equipment.


- **Video scripts (`docs/scripts/`).** Narration scripts for an eleven-episode video series covering Galileo's functions (episode 4 is 60 minutes, the others 30), plus a 10-minute quick start (episode 2 includes installing ASTAP and PHD2), with screen directions and demonstration pauses, plus `extract_narration.py`, which writes narration-only text for an AI narrator and reports running times. Written from the wiki, inline help and plugin notes; not yet checked against a running build. No application behaviour, help, wiki or design document changes.

- **The Imaging screen says whether a dark master is available too.** The same **Dark available** / **No dark available** label now sits beside **View > Subtract dark**, following the selected optics and camera and the **Exposure** setting. The box ticks itself when a master matches, so previews are now dark-subtracted by default when one exists; unticking it is remembered for that setup until Galileo is closed. Inline help and wiki updated.

- **The Solve screen says whether a dark master is available (PLT-070).** A label beside **Subtract dark** reads **Dark available** or **No dark available** for the selected optics, camera, exposure and binning, with the master's file name as a tooltip. The box now ticks itself when a master matches (and unticks when none does); your own choice overrides this and is kept for that setup until Galileo is closed. Inline help and wiki updated.

- **Load & Slew can take a frame from the Library (PLT-070).** The Solve screen's **Load & Slew…** button now offers **From the Library…** (a searchable list of light frames, fetching one held on the Master first) or **From disk…** (the previous file chooser), so a previous night's framing can be recalled without hunting for the file. The Library list sorts by any column header (numbers compare as numbers) and shows the selected frame in inverse colours.

- **Estimated total time for each session, used as its scheduled duration (SES-240).** Every session card on Planning > Sessions now shows how long all its operations are expected to take, updated as it is edited. Scheduling a session puts that figure (whole minutes, rounded up) on its Schedule entry instead of the flat 60-minute default, so the calendar block, the window in which it may start and Autoschedule's slot all reflect the real length. Sessions already queued without a duration get one on restart. The estimate (also behind the remote pre-run summary) now counts the filter change on each FOR Filter pass, the slew for each FOR Object pass, and every wheel filter for an "All" flat capture. The Set Time duration limit rose from 24 hours to 7 days so a long estimate is not cut short. Inline help, wiki and design documents updated.

### Fixed

- **Two out-of-date session tests, and lint errors that failed the code-quality check.** The tests compared blocks with `==`, which now means the same object; they compare the saved form. A leftover duplicate of one safety test was removed. No application behaviour changes.

- **Library command-line utilities no longer fail on a fresh install.** With no Library settings saved they stopped with "Configuration not found", although the Library screens work with the default folders. They now use the same defaults; a missing `--config` file is still an error.

- **Tests no longer load the developer's installed plugins.** Some tests loaded whatever was installed in the user's plugins folder, changing what screens showed and leaving those packages importable for later tests, which produced failures that depended on the computer. Every test now gets an empty plugins folder (`tests/conftest.py`). Test-only change; no application behaviour changes.
- **Automatic roof closes now park the telescopes first (SAFE-110).** A session's Dome Close block, the **open/close dome with sessions** close and the watchdog could close a roof on an unparked telescope. Each now parks every mount under the roof and confirms it is parked; if any cannot be confirmed (including a configured mount that is not connected) the roof is **left open**, you are alerted and the session ends in error. The session-end close is also held back while another Pier is imaging. Note the trade: a roof that cannot be confirmed safe to close stays open in whatever weather there is. The Dome page's own Close button is unchanged.
- **Unsafe weather now reaches running sessions (SAFE-120).** No session was ever given the safety verdict, so one started with **Run** carried on through unsafe conditions, even opening the roof. It now runs only its shutdown blocks once unsafe, and ends in error (so it is not removed as completed). A block already running still finishes, scheduled sessions are still only paused, and nothing yet parks or closes by itself: that is the next stage. New requirements SAFE-110/SAFE-120, SRS, SDD, RTM and help updated; `tests/test_safe.py`. Checked with simulated devices only, not on real equipment.

- **Two identical blocks in a session are no longer mistaken for each other (SES-120).** With two blocks of the same type and settings (for example two new **Slew To** blocks), dropping, moving or deleting one could act on the other: a block dropped between them landed above the first. This was found while investigating a crash when a second Slew To block was dragged into a session; that crash has not been reproduced, so it is not confirmed fixed.
- **INDI cameras whose offset lives in `CCD_CONTROLS` (ZWO and similar) never had the Offset applied, so they used their own default.** The INDI adapter only wrote `CCD_OFFSET`; it now falls back to `CCD_CONTROLS` / `Offset`, as it already did for gain, and logs a warning if the driver has neither. This is the likely cause of the user report of camera defaults being recorded instead of entered values (INDI), not yet confirmed on their camera. In addition, the FITS `GAIN` and `OFFSET` cards are now **read back from the camera** after each exposure (INDI and Alpaca) instead of copied from what was requested, so a refused or ignored value shows as what the camera really used; a reported 0 is written as a 0 card (previously omitted). If a camera reports neither, the requested value is recorded, and the card is omitted only when nothing is known. This supersedes the limitation noted in the Alpaca Offset entry below. Tests `TC-EQP-CAM-010` and `TC-IMG-150` added.

- **GitHub releases came out with an empty description.** The release workflow's `release` job never checked out the repository, so it could not find `docs/release-notes/<tag>.md`. It now checks out first, and it marks the release as a pre-release, as the notes and README already describe these alpha builds (earlier releases are unchanged). The v0.9.08alpha and v0.9.09alpha descriptions were filled in by hand. No help, wiki or design document change (build workflow only). **Not run:** the fix takes effect at the next tagged release.
- **A newly installed solver plugin, such as Skyshot, now appears without restarting Galileo (PLUG-190, PLUG-220).** The plugin was already loaded on install, but the Solve screen's Solver Mode buttons and the Solver list in Options > Solve were only filled when the window was built. Both are now updated when a plugin is installed, updated, removed, enabled or disabled. This is a change to Galileo itself, so the plugin does not need rebuilding. Inline help (Solve > Solver Mode) updated; test `TC-PLUG-220` extended. No wiki change.

- **Alpaca cameras ignored the Imaging Offset.** `AlpacaCameraAdapter.start_exposure` applied Gain but silently dropped the Offset it was given, so the exposure used the camera's own offset while the FITS header (written from what was requested) claimed the entered value. It now sets Offset before exposing (0 still means "leave as configured"), as INDI already did. Audit of the rest of the Gain/Offset path for a report that camera defaults were recorded instead of entered values: the page reads both fields at each Capture, passes them to the camera, and writes them to GAIN/OFFSET from the same values, and a new end-to-end test (change the fields between captures, read the saved FITS header) confirms it; no other substitution was found. Two limits remain by design: the header records the requested value, not a read-back from the camera, and a Gain or Offset of 0 means "leave as configured", so that card is omitted. Tests `TC-EQP-CAM-010` and `TC-IMG-150` added. If the report was from an INDI camera, a driver log of the property updates would be needed to see whether the driver accepted the value.

- **Star Atlas details panel: the Goto and Centre button was missing and Add to Session was clipped.** The panel's Goto, Sync and Add to Session buttons shared one row of a 230 px column, so the last was cut off, and Goto and Centre existed only in the right-click menu. The panel now has Goto, **Goto and Centre**, Sync and Add to Session as full-width buttons, one per row. A **Park / Unpark** button sits at the bottom of the same column: it reads Park while the mount is unparked and Unpark while parked (checked every 5 s and after each press), and is disabled when no mount is connected. The inline help already documented Goto and Centre; the Park entry is added and the wiki's Star Atlas article mentions the button.

- **Mount Control nudge pad: uneven button spacing and a clipped "Stop".** All nine buttons are now the same size and evenly spaced, "Stop" fits without being cut off, and the Stop button is red so it is easy to find.
- **Mount Control now has a single Park / Unpark button.** It replaces the two separate buttons, reads **Park** while the mount is unparked and **Unpark** while it is parked, and follows the mount's status while the window is open.

- **Guider screen no longer reports "star lost" while PHD2 is calibrating, and now shows calibration progress.** Calibration deliberately moves the mount, so the star leaves its tracking square and PHD2 sends `StarLost`; the screen switched to LostLock and hid what was happening. `StarLost` during calibration now leaves the state as Calibrating, the Guiding state line shows live progress (phase, step, distance moved), and the end of calibration is stated plainly: "Calibration complete" (cleared when guiding starts) or "Calibration failed: <reason>" (kept until the next run). The log gets one line per calibration phase rather than per step. Inline help (Guiding state) updated. Test `TC-GUIDE-080` extended. No wiki change (no new control).

- **Mount jog and Imaging nudge buttons now stay highlighted while held.** With the log tail gone from these screens there was no visible sign that a direction button was being pressed. `HoldToMove` (shared by Equipment / Mount and the Imaging nudge pad) now paints the held button in the palette's highlight colour from press until release, and also clears it if the button is hidden or disabled or the application loses focus, the same cases that stop the mount. No new controls, so no help or wiki change. Test `TC-EQP-MNT-010` (held-button highlight) added.

- **Star Atlas Milky Way background (Mellinger survey) was never populated.** CDS's hosts (`alasky.cds.unistra.fr`, `alasky.u-strasbg.fr`) now answer 404 to every Mellinger tile, and the tile fetcher took the first 404 to mean "this tile doesn't exist" without asking the remaining mirrors, so the independent IAS Orsay mirror (which still serves the survey) was never reached and the sky stayed blank. A 404 now moves on to the next mirror, the tile is reported missing only if every mirror says so, and the mirror that answers is tried first from then on. The dead CDS mirrors are also removed from the list, leaving IAS Orsay as the only (and so primary) source. Internal fetch behaviour only; no new controls, so no help or wiki change. Test `TC-SKYMAP-100` added.

- **Skyshot data download no longer fails with `SSL_CERTIFICATE_VERIFY_FAILED` ("unable to get issuer certificate").** Python on Windows checks HTTPS certificates against the OS trust store, which can lack an intermediate certificate GitHub's download hosts leave out of their chain, so retrying the same way never helped. After the first certificate failure the Skyshot plugin now retries with a verifying context built from the bundled certifi CA list (`galileo.net.certifi_ssl_context`, and an optional `context` argument on `urlopen_http`). Certificate checking stays on. Needs the Skyshot plugin reinstalled from its zip and Galileo restarted. Internal behaviour only; no new controls, so no help or wiki change.

### Changed

- **Imaging: the Rotator box now sits directly under Camera Cooling** in the settings column, instead of at the bottom, so the equipment controls are together near the capture settings. Layout only; no help or wiki change.

- **Imaging: the mount nudge pad moved into a Mount Control dialog.** The Mount Nudge group no longer takes space in the Imaging settings column (or the portrait dock); a new **Mount Control** button opens it in a small modeless tool window that floats in front of the main window, so it stays usable while watching the preview, and hides when you leave the Imaging screen. Nudge behaviour is unchanged. The dialog also has **Park**, **Unpark**, **Home**, **Track On**, **Track Off** and **Do Meridian Flip** buttons, which run the Mount screen's own commands (`MountOps`); the flip asks for confirmation, re-slews to the current position so the mount takes the other pier side, then resumes tracking once the slew ends (new `MountOps.meridian_flip`). "Mount Nudge" is gone from the movable-panels list (a saved layout that mentions it is cleaned up on load). Inline help (new Mount Control entry) and the Imaging wiki article updated; tests `TC-IMG-120` adjusted and `TC-IMG-130` (dialog) added.

- The Solve screen now remembers the Solver Mode you last picked, per Pier. Before, a choice made on the screen was lost on restart and only Options > Solve was saved. The choice is stored as the Pier's solver backend, so everything else that solves with the saved solver (the phone via MobileConnect, session Plate Solve blocks, Imaging, Star Atlas) uses it as well. No schema change.
- **Plugin settings pages moved off the Options menu onto the Plugins screen.** Each plugin that has settings used to add its own item to the Options side menu, which was filling up. Those items are gone; instead the plugin's tile under Options > Plugins > Installed has a gear (⚙) button that opens its settings page. The pages themselves, and their help, are unchanged. Inline help for Plugins gains a "Settings" entry (the gear); SRS `PLUG-170` and SDD §4.20 describe the gear, and the wiki articles for NodeConnect, WebConnect, AllSkyCam, Skyshot, Plate Solving and the Plugin Developers Guide now say "the ⚙ on its tile in Options > Plugins" instead of "Options > <plugin>".
- **Exposure notices now show progress, and a finished set is announced.** When a series of more than one frame is running (Imaging captures, darks, mosaics), each start notice reads "Exposure 4 of 99 starting: 30 s Light" instead of just the exposure length, and an "Exposures complete" notice is posted when every frame in the set has been taken (not when the set was stopped early or failed). Single-frame exposures are unchanged. The progress counter lives in `galileo.notices` (`set_series_progress` / `clear_series_progress`) and is set by `ImagingService.capture_series` and the mosaic series. No new controls, so no inline-help or wiki change.
- **Skyshot plugin: no more asking for the program or index location (`SKY-120`).** The plugin's design documents (`docs/plugins/skyshot_solver/`) now record that both are downloaded to a fixed `skyshot` folder inside Galileo's data folder, with a `program` folder there for a hand-built Skyshot, instead of the user typing or browsing to paths. Plugin change only (Galileo-Plugins, `skyshot_solver` 0.1.1); no Galileo code changed, and nothing in Galileo's own screens, help or wiki articles (other than the Skyshot article) changes.
- **Skyshot plugin design record brought up to date (`SKY-100`).** `docs/plugins/skyshot_solver/RTM.md` now records that the `Build Skyshot engine` workflow has been run (run 45310212150, upstream commit `76f0181`): the Windows x64, Linux x64, Linux ARM64 and macOS Apple-silicon builds passed upstream's tests and packaged smoke solve and are published as release `skyshot-engine-v0.1.0-76f0181`, pinned in plugin 0.1.1, and that only the Windows build has so far been downloaded and run by the plugin. Documentation only; no Galileo code changed.

### Added

- **Object field on the Imaging screen.** An **Object** text box above Capture Settings shows the Pier's current object, or "Unknown" when none is selected, and can be typed over; entering a name found in the offline catalog (or, failing that, Simbad) also makes it the Pier's current object, while an unfound name only labels the frames. Its text is the name used for the frames' OBJECT header card and file names (also for Save Frame and Save Stack to Library); selecting another object replaces an override, and clearing the box restores "Unknown". Inline help and the Imaging wiki article updated; test `TC-IMG-140` added.

- **Emergency stop on the Mount Control dialog.** A full-width red **EMERGENCY STOP** button below Do Meridian Flip aborts any slew and halts both axes (including a held nudge) immediately; tracking is left as it is. Inline help, the Imaging wiki article and test `TC-IMG-130` updated.

- **Camera cooling controls on the Imaging screen.** A new *Camera Cooling* box under Capture Settings shows the camera's sensor temperature (refreshed every 5 s, with cooler power when reported), a **Target** temperature and a **Cooler on** checkbox, so you can start or stop cooling without going to Equipment. Camera adapters (INDI and Alpaca) gain `set_cooler(on)` and `read_cooling()`; device calls run off the UI thread. Inline help (`imaging.md`) and the Imaging wiki article updated.

- **Plugin icons (`PLUG-210`).** A plugin's tile under Options > Plugins > Installed now shows an icon instead of a star. A plugin author adds `icon.svg` or `icon.png` at the root of the plugin ZIP; first-party plugins always show the Galileo icon. Marketplace tiles of first-party plugins without a server icon use it too. Plugins with no icon are unchanged. No new controls, so no inline-help change; the Plugin Developers Guide documents the file.
- Draft Project Scope Document for a planned **INDI Server plugin** (`docs/plugins/indi_server/PSD.md`): a first-party plugin that would let Linux and macOS users run and supervise a local `indiserver` with nothing preinstalled (bundled INDI, detect-and-adopt a running server on start-up and add or remove its drivers, choose drivers live through the server's FIFO, restart on failure, a lifetime option) from a panel on Equipment > Control Panel. Scope includes per-platform build scripts, run by hand on each platform, that build INDI and publish the bundles, stored on the project website's own server, to the website by rsync over SSH, with the Linux x86-64 build run on a local server and macOS limited to Apple silicon. The bundles track the latest stable INDI release. All scope questions in the PSD are now answered, pending sign-off. Documentation only: no code, SRS/SDD/RTM, help or wiki changes yet; those follow once the remaining scope questions in the PSD are agreed.

## Rebuilt 2026-11-26

The `v0.9.10alpha` tag was moved and the installers rebuilt, without changing the version number, to include the following.

### Added

- **Library > Masters** lists the master calibration frames. You can open one in the FITS viewer, **Recreate** it from the session it was built from (sessions using it keep using it), or **Delete** its file and Library entry. Imported masters, and masters with fewer than two source frames left on disk, cannot be recreated.
- [SeeStar Native Mode Analysis](docs/SeeStar%20Native%20Mode%20Analysis.md): what it would take to control a Seestar over its own protocol so it can record to its own storage, with a proposed plugin design, the core changes needed, risks and a phased plan. Analysis only; nothing is implemented, so no help, wiki or requirements changes.
- A **Delete** button beside Save on every Equipment > Safety tab removes that safety device and its saved settings and rules, including the Observatory's first weather station, which could not be removed before.

### Changed

- With no safety device registered (none saved with a device name, none connected) the safety system is now off for that Observatory: nothing is blocked or parked, no banner shows, and an unacknowledged safety stop is cleared. A tab saved with a blank device no longer counts as a device. The crash/hang watchdog is separate and unaffected.

### Fixed

- Two masters of the same type and telescope made within one second no longer fail to be recorded because of a duplicate ID.
- **Goto and Centre** from Planning (Search, Targets, What's Up Tonight) slewed to the new object and then slewed straight back to the previously selected one. Any goto sent to the mount, including **Slew To** and **Goto and Centre**, now makes its object the Pier's current object, so the plate solve, Auto-Centre and frame naming follow it.
- The **Acknowledge safety stop** button looked as if it did nothing when the stop could not yet be cleared. It is now greyed out until it can be used, and the banner says why and about how long is left.

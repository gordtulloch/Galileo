# Changelog: 0.9.08alpha (2026-11-18)

Shipped as [v0.9.08alpha](https://github.com/gordtulloch/Galileo/releases/tag/v0.9.08alpha). Back to the [current changelog](../../CHANGELOG.md).

### Changed

- **The release workflow puts `docs/release-notes/<tag>.md` in the GitHub release.** Releases were created with an empty description; the short notes written for each release (the same text posted to Cloudy Nights) now show on the release page. Add the file before tagging.
- **Tests brought in line with behaviour that had already changed (no product change).** `TC-SKYMAP-010` now expects IC as a fourth catalog (`IC 1` is in `{"IC"}`, counts include `IC: 0`), and `TC-PLT-070` no longer sets the removed Solve "Dark" checkbox and expects only the Light exposure. Both failed on the committed code and would have stopped the installer build, whose first job is the test suite.

### Added

- **Star Atlas: the object you Select is plotted (`SKYMAP-130`).** Choosing an object with Select on Search or What's Up Tonight made it the Pier's current object, but the Atlas drew only saved targets, Find matches and a small reticle, so an object from a catalog that was switched off (IC objects, since only Messier is on by default) showed as empty sky until it was saved as a target. Each Pier's current object is now always plotted, labelled and with its type's icon, as saved targets are (in yellow, like Find matches). **Checked:** a new test; **not looked at** on screen. The mobile apps are unchanged: they have no Search or What's Up Tonight screens, and their Find already plots what it finds.
- **Run saved sessions and manage the queue from a phone, tablet or browser (`CSURF-186`, `CSURF-205`).** New operations: `session.saved` (the Pier's saved sessions, never templates), `session.start_check`, `session.run_saved`, and `scheduler.remove`, `.reorder`, `.pause`, `.resume`, `.stop`. The live queue and the session runs belong to the desktop, so the desktop that hosts the engine now registers itself as the owner (`galileo.ui.remote_schedule.DesktopScheduleOwner`) and does each thing on its own thread, exactly as the Schedule and Sessions screens would; with no desktop attached they are unavailable and say why. `session.run_saved` starts the session immediately as Run does, is refused with "Jobs already running" while a job or session is running, and while a job is still to come is refused until repeated with `preempt` (the app asks "Pre-empt any upcoming jobs?"); a running job cannot be removed or reordered. `scheduler.jobs` now lists the live queue with `running`/`paused`, including a session started by Run that is not a queued job. Reordering renumbers the queue's priorities 1..n to the new order. **Checked:** unit tests with a fake window and the real scheduler and database; **not run:** a real phone against a real desktop.
- **Save asks for a name (`SES-065`).** The first Save of a session on the Sessions screen asks what to call it (starting with its current name) and asks before replacing a saved session of that name on the Pier; the name is what a phone lists. Inline help and the wiki updated.
- **`guiding.loop` for the apps.** Asks PHD2 to start looping exposures without guiding, as the desktop Guider screen's Loop button does; the guide star and frame only appear while PHD2 is looping or guiding. No change to the desktop screens. **Remote PHD2 (`GUIDE-110`):** the whole guide frame needs PHD2 to save it to a file this computer can read; with PHD2 on another computer (for example an Astroberry) it saves on that machine. Galileo now notices (the file is missing), logs it once, and shows a large guide-star image fetched over the PHD2 connection instead, starting at the camera's smaller side (at most 640 pixels) and halving the size each time PHD2 refuses it; the log says what size PHD2 gave. It is centred on the guide star, not the whole sky the camera sees, and a tap on it still selects the star. **Not run** against a real PHD2: how large PHD2 allows is unknown until tried.

### Fixed

- **Guiding > Connect from a phone, tablet or browser now connects PHD2's equipment as well as the PHD2 server.** `guiding.connect` only opened the connection to PHD2, so guiding then failed until someone pressed Connect equipment in PHD2. It now also connects PHD2's camera and mount (waiting up to 90 seconds) and says so if they don't come up, leaving the PHD2 connection in place; Connect stays available then, to retry just the equipment. The result has `equipment_connected`. No change to the desktop Guider screen, so no help or wiki change.
- **Autofocus from the apps showed no V-curve or HFR.** A sweep point with no stars measured an HFR of NaN, which isn't valid JSON and could break the `focus.autofocus` state update. Such points are now skipped (the message says "no stars found") and each point's message carries its HFR and position ("Point 3 of 9: HFR 2.41 at 5200"). No change to the desktop Focus screen.

### Changed

- **A failed operation's reason names the kind of failure and where to look** ("the operation failed (AttributeError); the Galileo log has the details") instead of just "the operation failed". The exception's own text still doesn't reach the client (`CSURF-040`). No change to the desktop screens, so no help or wiki change.
- **Survey thumbnails and Framing cutouts now come from IRSA's HiPS mirror, not CDS hips2fits.** The CDS services (`alasky.cds.unistra.fr`) are down, so target thumbnails (Targets, What's Up Tonight) and the Framing Assistant's survey image failed. New `galileo.planning.hips_cutout` builds the same north-up DSS2 colour cutout locally from the static tiles at `https://irsa.ipac.caltech.edu/data/hips/CDS/DSS2/color/` (tiles are disk-cached under the cache dir's `hips/`). Both `_fetch_hips_thumbnail_sync` and `_fetch_hips_cutout_sync` use it; their signatures and the thumbnail cache are unchanged. The Mellinger sky-map background is unaffected (IRSA doesn't mirror it). **Checked:** M81 and M42 cutouts render correctly oriented against the live mirror; no visible controls changed, so no help or wiki change.

### Added

- **`imaging.phase` state: `integrating`, `downloading` or `processing`** while a capture runs, for the apps' "Exposure 1 of 999 integrating..." line. Downloading is the time after the exposure has run its length and before the frame arrives.
- **Progress for the apps' bars.** While a capture runs the engine publishes `imaging.exposure_progress`, `imaging.exposure_s`, `imaging.progress`, `imaging.frame` and `imaging.count` (twice a second), and `solve.exposure_progress` while a solve's frame is being taken; they were read by the apps but never published, so the bars never moved. Autofocus and polar alignment now report a fraction with each step (points done of points; the three measuring solves) in their `op.progress` events.
- **`imaging.capture` takes `binning` (1 to 4).** For the apps' capture line; passed to the camera only when above 1, as Solve does.
- **Operations asked for through the Control Surface are logged.** Each action (anything but a read) is logged at INFO with who asked, what, on which Pier, its arguments and its outcome, including the long-running ones' finish, so what a phone or browser did is in the desktop log. Reads are logged at DEBUG, since apps poll them.

### Fixed

- **What's Up Tonight: the Smoke row is always shown.** When NOAA smoke data is unavailable (not today's date, outside North America, or a failed fetch) the row now shows one grey "no data" cell across the night instead of vanishing. No new controls, so no help or wiki change. **Not run:** visually in the app.
- **What's Up Tonight: forecast row labels (Cloud, Seeing, Smoke, Aurora, …) were drawn over the data cells.** The labels now sit in their own column to the left, and the day/night band uses the same left gutter so hours still line up with the cells beneath. Visual layout only; no controls changed, so no help or wiki change. **Not run:** visually in the app.
- **Polar alignment from a phone, tablet or browser failed every time with "the operation failed".** `polar.start` read the rig's FITS-header context from `SessionContext.frame_context`, which doesn't exist (the context is built once and handed to the session's services), so it died with an `AttributeError` before anything moved and the desktop log showed only a trace under a generic message. It now gathers the context the way a session does. **Checked:** a new test builds the workflow; **not run:** a real polar alignment (no mount here).
- **A solve that found nothing finished as "Done".** `solve.capture`, `.sync`, `.centre` and `.load` returned a summary with `solved: false` as success, so a Solve and Centre that slewed and then failed to capture or solve looked like it had worked. A run that ends without a solution (and wasn't stopped) now finishes `refused` with the solver's reason, or the workflow's own failure line ("Capture failed: ...") when it never reached the solver. The summary and log are still published as `solve.last`.
- **`filter.names` raised on an INDI filter wheel** (every 30 seconds from a connected app: `'IndiFWAdapter' object has no attribute 'get_filter_names'`); it now reads the adapter's `filter_names`.

- **`weather.readings` failed with `'IndiWeatherAdapter' object has no attribute 'get_readings'` (`CSURF`).** The Control Surface operation called `get_readings()` on what the device pool holds, which is the raw adapter, not a `WeatherController`. It now wraps the adapter in a `WeatherController`, polls it and returns the fresh readings. **Checked:** code read against `weather_ops.read_device`; **not run:** against a real weather station. No visible controls changed, so no help or wiki change.
- **A device the desktop connected was held under a second category spelling (`HEAD-090`).** The device service stored desktop-connected filter wheels, flat panels and weather stations as `filterwheel`/`flatpanel`/`weatherstation`, while the Control Surface looks for `filter_wheel`/`flat_panel`/`weather`, so the phone could see them listed as connected yet get "no filter wheel". `DeviceService.adopt` now files every device under the Control Surface name. **Checked:** the name mapping; **not run:** against the phone.

- **The phone no longer reports "Pier has no mount/camera" for devices the desktop shows connected (`HEAD-090`).** With *Hold devices in the device service* on, a mount or camera connected before that (or kept by a screen across a Pier switch) was owned by its screen only, so the Control Surface could not see it and the phone refused with "this Pier has no mount/camera" even after Connect All. The top bar's Connect, and the periodic connect-state refresh, now hand every live adapter the screens hold for the current Pier to the device service (`desktop_devices.adopt_held`), so no separate connect from the phone is needed. **Checked:** imports and existing tests; **not run:** against a real phone and hardware. No visible controls changed, so no help or wiki change.

- **ASTAP solves that worked in standalone ASTAP but failed from Galileo (`PLT-060`).** Galileo called ASTAP with settings the standalone program does not use. (1) `SolverParams.downsample` defaulted to 2, so ASTAP was forced to `-z 2` and could lose too many stars on a small or binned frame; the default is now 0 (ASTAP chooses, as it does standalone) and the Options > Solve box reads **Auto** instead of **Off**. `-z 1` is now sent when you choose 1, so full resolution is possible. (2) The field-of-view hint was computed from the optical train's scale and the image height, ignoring binning, and overrode the header; it is now skipped when the frame header carries `FOCALLEN` and `XPIXSZ` (ASTAP derives the scale itself) and otherwise multiplied by the binning. (3) A solve that fails with a position hint (typically the mount's possibly-wrong reported position, limited to the search radius) is retried once without the hint so ASTAP reads the position from the header. (4) Failures are now logged at warning level with the full command. **Checked:** new `TC-PLT-060` tests pass; **not run:** against a real ASTAP install. A Pier that saved Downsample 2 earlier keeps it; set it to Auto if solves still fail.

### Added

### Fixed

- **Connecting all of a Pier's INDI devices at once reported that none of them were available (`EQP-040`).** Connect All Devices (and the engine's start-up connect) brings up a Pier's devices at the same time. They share one connection to the INDI server, and only the device that opened it waited for the server to finish announcing its devices; the others read the device list too early, saw nothing, and failed with "INDI server has no device named X (available: none)". The desktop connects its devices one after another, which is why the same Pier worked there. Every caller now waits for the server's property burst (immediate once it is over). New test `test_tc_eqp_040_a_second_connect_waits_for_the_servers_first_property_burst`, which fails without the change. Restart Galileo.

- **Library > Sessions now shows masters created by Auto-Calibration straight away.** The Sessions tree was reloaded after the Auto-Calibration dialog only if it returned "accepted", but the dialog never accepts (Close and the window X both count as rejected), so new masters didn't appear until you regenerated sessions. It now reloads whenever the dialog closes. No control changes, so inline help and wiki are unchanged; recorded in `docs/Astrofiler Back Propogation.md`.

- **Autofocus V-curve was scrambled: HFR was huge at moderate defocus and tiny when far out of focus.** The star measurement (`_measure_stars`) let SEP deblend defocused donuts into fragments that each read as a small star, counted faint noise detections and neighbouring stars, and sized apertures too small for faint donuts, so the median HFR jumped around instead of rising with defocus. It now turns deblending off, detects at 3σ with a minimum area, uses only isolated stars (brightest 150), sizes each star's aperture from its own detected area, and takes a true half-flux radius with unclipped background. On synthetic crowded fields (279 stars) HFR now rises steadily from sharp to far out of focus (HFR ~2 to ~14 px); `TC-FOC-010` has a regression test for it. The star count is now used to judge each reading: a reading with no stars, or with under half the sweep's best star count *and* an HFR below the sweep's median (a hot pixel or noise speck, not a real sharp focus), is left out of the V-curve fit and named in the log; a high HFR from few stars (genuinely defocused) is kept. If fewer than 4 readings remain the run fails with a message suggesting a longer exposure or smaller step instead of fitting noise (`unreliable_points`, `AutofocusResult.rejected_positions`, test in `TC-FOC-010`). The sweep also refuses a downward-opening parabola and reports a failure instead of moving to the worst position. Not yet checked on real frames, and HFR values differ from earlier versions, so saved HFR thresholds may need adjusting. No UI control changes.

- **Scheduled sessions now start even if you never opened Planning > Sessions.** The timer that fires due calendar entries was only started when the Sessions page was built, and pages are built lazily, so a job placed on the Schedule calendar sat at "pending" with an empty log forever. The Schedule page now starts the timer too. The log dialog's empty text no longer claims execution "isn't wired up for this build" (it is); it says the entry has not run. No help, wiki or design-doc change needed.
- **No more "Python quit unexpectedly" popups from short-lived runs.** The Plugins page's marketplace workers (`_LatestThread`, `_FetchThread`, `_DownloadInstallThread`) were `QThread`s; building the window and exiting (the test suite, `python -m galileo.ui.help --audit`, or quitting) while the version lookup was mid-HTTPS-handshake made Qt abort with "QThread: Destroyed while thread is still running" and macOS showed a crash report. They are now daemon Python threads reporting through queued Qt signals, so a request still in flight at exit is just dropped. Behaviour of the Plugins page is unchanged (no help, wiki or design-doc change needed).

- **Generating tetra3 databases (Options > Solve) now fails politely when the star catalogue can't be downloaded.** A network timeout or connection error used to log a long traceback and leave only a terse `URLError` line in the status text. It now logs a one-line warning, removes the partial download, reports "Could not download the star catalogue — check your internet connection and try again", and shows a warning dialog listing any databases that failed. No new controls, so inline help, wiki and design docs are unchanged. Not exercised against a real network failure.

- **Connecting to an INDI server with the protocol left on Alpaca no longer just logs a traceback.** On the Equipment device pages, if the scan fails with the chosen protocol, Galileo now retries with the other one (switching the protocol dropdown, and the port if it was still the old protocol's default) and reports the switch in the status bar. If neither protocol finds a server, a "Server not found" dialog says so and only a one-line warning is logged. No new controls, so inline help, wiki and design docs are unchanged. Not run against live servers or covered by a new test.

- **The sky survey background now falls back to more backup sites when CDS is unreachable.** The Mellinger photo-mosaic behind the star atlas only tried CDS's two hosts (`alasky` and `alaskybis.cds.unistra.fr`), which share one DNS domain and one institution, so a CDS or DNS outage left the atlas with no sky image. It now also tries CDS's older `alasky.u-strasbg.fr` name and the independent IAS Orsay mirror (`healpix.ias.u-psud.fr/CDS_P_Mellinger_color`), remembering whichever answers first. The added hosts could not be reached from the development machine (its DNS was failing), so they are untested live. No visible controls changed, so inline help, wiki and design docs are unchanged.

- **The mount jog pad and the Imaging nudge pad now use arrows (↑ ↓ ← → and ↖ ↗ ↙ ↘) instead of N/S/E/W letters, and the Mount page's Rate box is wide enough to read.** The Rate drop-down sat beside its label squeezed to about one character; it now sits below the jog pad at a usable width. Hovering a button still names the direction. No change to what the buttons do. The wiki's Imaging table was updated.

No user-visible change, so no help, wiki or design-doc update.

# Changelog: 0.9.09alpha (2026-11-23)

Shipped as [v0.9.09alpha](https://github.com/gordtulloch/Galileo/releases/tag/v0.9.09alpha). Back to the [current changelog](../../CHANGELOG.md).

### Added

- **Event notices replace the log panes (`NOTE-010`–`NOTE-060`).** Every significant event now appears as a small floating panel over the top-right corner of the Galileo window, whichever screen is showing, and closes itself after 10 seconds or when you click its **×** (up to five stack at once). Announced: each exposure start and abort; each slew start and end; park, unpark, home, sync and tracking changes; focuser, filter-wheel, rotator, dome and flat-panel moves; plate-solve started, resolved, failed or cancelled; autofocus started and its result; equipment connected, disconnected or in error; unsafe conditions; session started and finished; and PHD2 guiding progress (guiding started, star lost, a command rejected). Device commands are caught in the one place each protocol already logs them (`_log_interaction` for INDI, `_put` for Alpaca), so they are announced whoever issued them — a screen, a running session, the solver, autofocus or a phone — and "Slew complete" is posted when the mount adapter sees the mount stop slewing. Nothing is announced during start-up, from launch until the splash and its status display finish (`NOTE-060`): notices are dropped, not queued, so the initial equipment connections are not replayed. The panels use the theme palette only, so the red night-vision theme stays red. New modules `galileo.notices` (the `NoticeEvent`, `post_notice`, the command descriptions and the bridge from existing bus events) and `galileo.ui.notice_toast`. **Checked:** `tests/test_note.py` (9 tests) and an offscreen run of the panels; **not run:** a live INDI/Alpaca device.
- **Event notices reach the mobile apps (`NOTE-040`).** The engine's event feed now carries `NoticeEvent`; the MobileConnect plugin sends each to a connected app as a `notice` stream frame (see the MobileConnect changelog). The plugin must be reinstalled from its zip (Options > Plugins) and Galileo restarted. **Checked:** feed membership test; **not run:** a phone against a live Master.
- **Plugins can now add plate solvers (`PLUG-220`).** A plugin calls `ctx.register_solver_backend(backend)` with a `galileo.platesolve.SolverBackend` (a `key`, a `label`, `is_available()`, `missing_message()` and an async `solve(fits_path, hint, params)`). The solver then appears in the **Options > Solve > Solver** list and as an extra button under the Solve screen's **Solver Mode**, and `PlateSolver` runs it like the built-in ones, including the "plugin disabled" and "setup missing" messages. A plugin cannot take the name of ASTAP, astrometry.net, nova or tetra3 or of another plugin's solver; a disabled plugin's solver is hidden, an unloaded plugin's is dropped, and an exception inside a plugin's solver becomes a failed solve instead of an error. Nothing about the built-in solvers changed, and no database migration is needed (the saved choice was already free text). First user: the new **Skyshot Solver** plugin (`../Galileo-Plugins/skyshot_solver`, requirements `SKY-010`…`SKY-070` in `docs/plugins/skyshot_solver/`), which adds the Skyshot blind solver and downloads its star index from its own page under Options. The plugin can also download a prebuilt Skyshot program for Windows, Linux (Intel/AMD and ARM, including Raspberry Pi 5) and macOS on Apple silicon, built by a GitHub Actions workflow in the plugins repo from one pinned upstream commit and trusted only through checksums pinned in the plugin (`SKY-080`…`SKY-100`); until that workflow has been run and published, Skyshot has to be built from source. So far it has been checked against a real Skyshot build on Windows with Skyshot's own synthetic demo, not yet on real sky or on the other platforms. Installing it is via Options > Plugins from its zip.
- **Skyshot credited in `THIRD_PARTY_NOTICES.md`.** New section for Skyshot Solver (Copyright 2026 Adam Jesionkiewicz, Apache-2.0): it is not bundled, the plugin downloads unmodified builds that keep Skyshot's LICENSE, NOTICE and third-party notices, and it runs as a separate program, so there is no combining with Galileo's GPL-3.0 code. It also records that the plugin's index installer follows upstream's installer rules without copying its code, and that **Skyshot's star indexes are not under Apache-2.0**: upstream describes them as intended for non-commercial use, derived from the ASTAP D80 catalogue (ESA Gaia DR3), so the plugin never redistributes them, warns before downloading, keeps their `LICENSE-DATA.txt`, and refuses an index without one. Anyone using Galileo commercially should check those data terms with Skyshot's author before relying on the index.

### Changed

- **The log panes are gone from every screen (`LOG-060` retired).** The Log pane (and its "Log" heading) is removed from all Equipment pages (Camera, Mount, Focuser, Filter Wheel, Rotator, Optics, Dome, Flat Panel, Switch, Weather, Aux and the generic device page), the Imaging screen (including its portrait log bar and the "Log" entry in the panel layout list — an old saved layout simply drops it), the Focus screen, the Solve screen, and the Guider screen (PHD2's own event list; its lines now come out as notices). `RecentLogPane`, `_build_log_pane`, `_LogPane` and the once-a-second refresh timers are removed. **View Log** (sidebar icon menu) is unchanged and is where the full log, with errors and tracebacks, now lives. Inline help: the common "Log" entry is replaced by "Event notices". Wiki articles 02, 03, 09 and 19 updated. Design docs: new SRS domain `NOTE`, SDD §4.22a, RTM rows; `LOG-060` retired. Note: a Master running as a separate headless process announces on its own bus, so a desktop attached to it shows only its own events.

### Fixed

- **A phone could not connect when the Master picked the wrong network adapter (`LINK-010`).** With a VPN or virtual adapters installed, "Automatic" chose an address that was not on the LAN (for example 172.18.x.x instead of the Wi-Fi 192.168.x.x), so the Connect Link listened and advertised somewhere the phone could not reach. The `bind_host` setting existed but had no control. **Options > Connect Link** now has a **Listen on** list of this computer's addresses (plus Automatic, or type one); `0.0.0.0` is still refused, and a typed address is checked to be IPv4. The list works without `psutil` (it falls back to the host name's addresses), and a typed address is used as typed rather than being added to the list as a blank entry (which silently meant Automatic). Turning **Enable Connect Link** on or off now saves the form first; before, only **Apply** saved the address, so switching the link off and on listened on the previously saved (Automatic) address instead of the one chosen. The Automatic choice itself is unchanged. **Checked:** the address list on this machine and lint; **not run:** the page or a phone connection. Inline help updated; no migration.
- **Moving blocks on the Sessions screen could crash the app or freeze the window on macOS (`SES`).** On macOS Qt delivers the drop *inside* the native drag session, before `QDrag.exec()` has returned, so the deferred "refresh" (a zero-delay timer) could still run mid-drag and rebuild every session card, destroying the widget the drag came from. Everything a drop triggers (re-render, the "Can't add block" warning, drag-out-to-delete) now waits until the drag has actually ended, for drags from both the palette and a block list. Not a PySide6 defect as such: it was a lifetime race that other platforms' drag loops happened not to expose. **Checked:** imports and the existing Sessions tests; **not run:** the drag itself on a Mac. No visible controls changed, so no help or wiki change.
